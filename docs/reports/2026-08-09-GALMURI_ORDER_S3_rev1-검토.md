## 1. 착수 전 해소 — 개정 2를 **지금 배포하면 쓰던 사람의 두 칸이 자리를 바꾼다**

> **정정(2026-08-09)**: 이 절의 초판은 「근거 날짜가 미래다」였다. 클코1 의 날짜 인식 오류였고
> 지휘부가 바로잡았다 — 오늘은 **한국시간 8월 9일**이 맞다. 지시서의 근거 날짜는 정상이며
> 3회차 실강 녹취(143분)는 실재한다. 개정 1·2의 근거는 흔들리지 않는다.
> 다만 날짜가 바로잡히면서 **지시서도 이 보고서도 놓쳤던 문제**가 드러나 아래로 대체한다.

**3회차 갈무리는 오늘 00:00(KST)에 이미 열렸다.** `cohort_sessions` 실측(퓨처나우2026예봄1기):

| 회차 | 개시(KST) | 마감(KST) |
|---|---|---|
| 3 | **08-09 00:00** | 08-15 23:59 |

실강이 오늘 오전이었으므로 **참여자는 지금 이 시각에 카드를 쓰고 있을 수 있다.** 그리고 갈무리는 한 번에 끝내는 서식이 아니라 **며칠에 걸쳐 고쳐 쓰는 문서**다(ADR-91 A).

여기서 개정 2가 걸린다. 순서 반전은 **키를 바꾸지 않으므로 저장값은 안전하다** — 지시서 판단이 옳다. 그러나 **화면에서 두 칸이 자리를 바꾼다.**

| | 지금 화면 | 개정 후 화면 |
|---|---|---|
| 위 칸 | `habit_stop` 줄이거나 없애기로 한 것 | **`habit_start`** 이번 주에 새로 시작하거나 늘릴 것 |
| 아래 칸 | `habit_start` 그 자리에 들이기로 한 것 | **`habit_stop`** 줄이거나 없앨 것 |

이미 위 칸에 적어 둔 사람이 내일 다시 열면, **자기가 위에 쓴 문장이 아래로 내려가 있고 라벨도 달라져 있다.** 값이 사라진 것은 아니지만 사라진 것처럼 읽힌다. ADR-91 C 가 `1·2회차 옵션을 바꾸면 이미 그 낱말을 고른 사람의 답이 화면에서 사라진다`며 3회차부터만 적용한 것과 **같은 계열의 위험**이고, 그때보다 가볍지만(값 보존) 눈에는 더 잘 띈다(자리 이동).

**판단에 필요한 수치**: 지금 3회차에 내용이 있는 행이 몇 건인가.

- **0건이면** 즉시 배포해도 안전하다. 개정 1~5를 한 커밋으로 처리한다.
- **1건이라도 있으면** 지휘부 결정이 필요하다 — ⓐ 감수하고 배포(값은 살아 있고, 새 순서가 자책을 막는다는 것이 개정 취지이므로 빠를수록 좋다) · ⓑ 개정 2만 4회차로 미루고 나머지(1·3·4·5)를 지금 배포 · ⓒ 전체를 4회차로 미룬다.

**클코1 권고는 ⓐ다.** 개정 2의 목적이 `자책 목록이 완성되기 전에 짝을 맞추게 한다`인데, 미루면 이번 주 참여자가 정확히 그 상태로 한 주를 보낸다. 자리 이동은 한 번 놀라고 끝나지만 자책은 남는다. 다만 **오늘 안에 배포해야** 값을 적은 사람이 최소가 된다.

> 클코1 은 현재 Supabase MCP 권한이 막혀 이 수치를 직접 조회하지 못한다(`-32600 You do not have permission`).
> 권한이 복구되거나 지휘부가 수치를 주시면 즉시 판정한다.

## 2. 보완수용 — 지시서가 빠뜨린 걸림돌 넷

### ① `copyBaseline.json` 재생성이 **필수**다 (개정 2·3·4·5)

**바로 오늘 ADR-94가 `session3` 을 리터럴 잠금에 넣었습니다.** 그전까지 3회차 문안은 회귀 보호 밖이라 자유롭게 고칠 수 있었지만, 이제는 문안을 한 글자만 바꿔도 **테스트가 붉어집니다.**

이번 개정은 문안을 최소 **일곱 곳** 바꿉니다 — `pairText.label`·`from.label`·`connector`·`to.label`·`to.help`(삭제)·`identity_gap.help`·`speech_habit.help`·`step.help`.

**이것은 사고가 아니라 잠금이 작동하는 것입니다.** 절차: 문안을 고친 **뒤** baseline 을 재생성합니다(먼저 뽑으면 옛 문안을 잠그고 즉시 깨집니다). ADR-91 D 때와 같은 순서이며, 그때처럼 **교체가 되돌아가지 않도록 명시 단언**(옛 문구 부재 + 새 문구 존재)을 함께 답니다.

### ② `REQUIRED_3` 의 습관 라벨도 **두 곳**이다 — 순서만이 아니다

지시서 §개정 2는 "`REQUIRED_3` 그룹 내 필드 **순서**도 화면과 맞춘다"고만 했습니다. 그런데 라벨 **문자열**도 함께 바뀝니다.

```
현재 REQUIRED_3 (session3.ts:24-27)
  { key: 'habit_stop',  label: '줄이거나 없애기로 한 것' }
  { key: 'habit_start', label: '그 자리에 들이기로 한 것' }
```

개정안은 `habit_start` 를 `이번 주에 새로 시작하거나 늘릴 것`, `habit_stop` 을 `줄이거나 없앨 것` 으로 바꿉니다. **`gap_area` 와 똑같은 이중 기재**이며, 한쪽만 고치면 결측 안내가 화면과 다른 문안을 읽어 줍니다. `required.test.ts` 의 ADR-91 일반화 테스트(3회차 포함)가 잡습니다만, 지시서에 명시돼 있어야 빠뜨리지 않습니다.

**즉 개정 2의 실제 수정 지점은 다섯이 아니라 일곱입니다** — 렌더 5(label·from.label·connector·to.label·to.help 삭제) + `REQUIRED_3` 2(라벨 문자열, 순서 포함).

### ③ `areaPick.line` 은 **단수 타입**이다 — 개정 1은 타입 확장을 부른다

```ts
areaPick?: BlockBase & { key; label; help; options: readonly string[]; line: CheckinField }
```

`line` 이 하나뿐이라 `gap_want` 아래 `rough_project` 를 넣으려면 타입을 손대야 합니다. **`line2` 같은 임시 필드는 쓰지 않기를 권합니다** — ADR-90이 경계한 슬롯 증식(“회차마다 늘리면 7회차에 여덟 개가 되어 무너진다”)과 정확히 같은 형태입니다.

**권고**: `line: CheckinField` 를 `lines: readonly CheckinField[]` 로 승격합니다. 1·2회차도 한 줄짜리 배열이 되지만 **문안은 한 글자도 바뀌지 않으므로** 리터럴 잠금에 걸리지 않고, 이후 회차가 줄을 몇 개 붙이든 타입이 따라옵니다. 렌더·`readModel` 두 곳이 순회로 바뀝니다.

`CheckinSession` 은 `/src/instruments` 안이라 **계약 변경이 아닙니다**(§1 승인 게이트 밖). 다만 세 회차 전부에 닿으므로 지휘부가 알고 계셔야 합니다.

### ④ 개정 5는 개정 1에 **의존**한다

개정 5의 새 `step.help` 가 `위에 우당탕탕 프로젝트를 적으셨다면` 이라고 위를 가리킵니다. **개정 1이 빠지면 없는 칸을 가리킵니다.** 두 개정은 묶음으로 채택하거나 함께 보류해야 합니다.

## 3. 판단 요청에 대한 회신 — `summaryFields` 넷

지시서 §개정 1이 판단을 제게 맡겼습니다. 현재 셋입니다.

```
지금 가장 바라는 것 · 습관 바꾸기(짝) · 입에 붙은 말
```

**넷으로 늘리는 데 찬성하되, 자리를 두 번째가 아니라 마지막으로 권합니다.**

- 찬성 이유: 나눔 열은 4회차 오프닝에서 소리 내어 읽는 재료입니다. 셋 중 둘(`습관 바꾸기`·`입에 붙은 말`)이 뒤를 보는 항목이라, 앞을 보는 항목이 하나 더 붙으면 오프닝의 무게가 바뀝니다. 지시서 §0의 진단(“앞을 보는 칸이 하나뿐”)과 일치합니다.
- 자리를 뒤로 권하는 이유: `rough_project` 는 **선택**이고 과제 시점이 “다음 주까지”라 **빈 칸이 가장 많이 날 항목**입니다. 두 번째에 두면 빈 칸이 목록 한가운데 생겨 읽는 흐름이 끊깁니다. 마지막이면 있는 사람만 덧붙는 모양이 됩니다.

| 지시서 주장 | 대조 결과 |

| 키 불변(`habit_start`/`habit_stop`) → 저장 데이터·결측 판정·나눔 열 보존 | **맞다.** 순서만 바꾸면 기존 답이 살아 있다 |

| `pairText` 개정 라벨에 `(책 117~118쪽)` 유지 | **맞다.** 참조 다섯 단언이 깨지지 않는다 |
| 코치 의견 5 미수용 — 4회차 결산 사슬 | **맞다.** 4회차가 `step_what`·`step_when` 을 되비추므로 대체하면 사슬이 끊긴다 |

**`우당탕탕` 이라는 낱말이 `CLAUDE.md` §7(강의 어휘 노출 금지)에 걸리는지 검토했고, 걸리지 않습니다.** §7이 막는 것은 구인명·STEP·진단 명명(`시들음`·`원씽`)입니다. 우당탕탕은 측정 어휘가 아니라 인도자가 참여자와 공유한 활동 이름이고, 인도자가 **카드에 적으라고 지정**한 항목입니다.
