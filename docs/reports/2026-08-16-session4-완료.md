## 1. B — ADR-103 되비추기 깊이 (커밋 `2e86eb0`)

### 상한을 없앤 것이 이 커밋의 핵심입니다

메모 §5가 지적한 대로, 지시서 §4-0이 *"회차별 특례로 처리하면 그때 하드코딩하게 된다"*고 써 놓고 §4-2에서 `back?: 1 | 2`로 상한을 박았습니다. 종단 축에서 **7회차가 2회차를 되비추면 `back: 5`**이고 그것은 축의 끝점이라 반드시 옵니다.

```ts
back?: number                              // 상한 없음
type Priors = Record<number, Answers|null> // 깊이별 봉투
priors[mirror.back ?? 1] ?? null           // resolveMirror 한 줄
neededBacks(copy): number[]                // 문안이 정한다
priorSessionNos(sessionNo, mode, backs)    // 페이지 분기를 순수 함수로
```

### §4-7 세 잠금 — 테스트 이름과 통과 출력

**(1) 되비추기 스냅샷 / 봉투 분리**

```
✓ back 미지정은 직전 회차(1)를 읽는다 — 기존 선언 전부 그대로
✓ 다른 깊이를 채워도 1~3회차 출력이 변하지 않는다        ← 봉투 분리 증명
✓ back: 2 는 두 회차 전만 읽고 직전은 읽지 않는다
✓ back2 가 없어도 empty 규칙은 그대로 적용된다
```

`{ 1: ANSWER, 2: {…}, 5: {…} }`처럼 다른 깊이를 채워도 `back` 미지정 선언의 출력이 `{ 1: ANSWER }`와 **완전히 같습니다.** 봉투가 새면 `step_what`·`mood`·`self_note` 같은 공용 키가 다른 회차 값을 읽어 참여자에게 틀린 문장이 보입니다 — 병합하지 않은 이유가 이것입니다.

**(2) 왕복 수**

```
✓ 1회차는 깊이 0, 2·3회차는 깊이 1 — 왕복이 늘지 않는다
✓ priorSessionNos — 열람에는 싣지 않고, 없는 회차는 거른다
✓ 상한 없음 — 가상의 back:5 도 그대로 동작한다
```

| 회차 | `neededBacks` | 조회 | 이전 대비 |
|---|---|---|---|
| 1 | `[]` | 0회 | 동일 |
| 2 | `[1]` | 1회 | 동일 |
| 3 | `[1]` | **1회** | **동일** |
| 4 | `[1, 2]` | 2회 | 신규 |
| 가상 7(`[1,5]`) | — | `[6, 2]` | 상한 없음 증명 |

**메모의 검증 항목 하나를 고쳤습니다.** `neededBacks(SESSION_1) === [1]`이라 적혀 있었으나 실측은 `[]`입니다 — **1회차는 되비추기 선언이 0개**입니다(첫 회차라 되비출 지난 회차가 없습니다). 코드가 옳고 테스트를 사실에 맞췄습니다. 왕복은 이전과 같습니다(`sessionNo > 1` 가드와 결과 동일).

**(3) 문안 불변**

`git diff --name-only` 결과 B 커밋에 `session1·2·3.ts` **없음.** 렌더 경로만 건드렸습니다.
