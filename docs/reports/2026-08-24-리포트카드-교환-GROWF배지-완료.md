## 0. 지시서 검토 — 반박 1 · 보완수용 1 · 나머지 수용

### 반박 — §3.1 의 전제가 부정확하다 (처방은 옳다)

> 지시서: *"리포트 1면은 2×2 카드다."*

실제 그리드는 **`repeat(auto-fit, minmax(260px, 1fr))`** 다. 열 수가 폭에 따라 바뀐다.

| 폭 | 열 | 현재 읽기 순서 |
|---|---|---|
| 넓음 | 4 | 활력 · 나침반 · 간격 · 준비도 (한 줄) |
| 중간 | 2 | 2×2 — 지시서가 본 모습 |
| 좁음 | 1 | 세로 스택 |

**그러나 처방은 옳고 오히려 더 넓게 맞습니다.** DOM 순서를 바꾸면 **1·2·4열 셋 다** 해석 순서와 일치합니다. 전제만 고쳐 그대로 실행했습니다.

### §3.1 이 요구한 확인 — 원래 오른쪽이던 레이아웃상 이유는 없었다

`git log -S` 로 추적: `8fe80d5`(B③ 시각화 v2 최초 조립) 이래 그대로이고 **후속 조정이 0**입니다. 의도적 배치가 아니라 최초 나열 순서였습니다. 두 카드는 같은 `1fr` 셀이고 행 높이는 둘 중 큰 쪽이라 **교환해도 높이가 변하지 않습니다.**

### 보완수용 — 시안의 흰 글자는 대비 미달이다

지시서 §3.2 가 이미 *"첨부의 하드코딩 색은 시안 편의용… 디자인 토큰을 쓴다"* 라고 지시했고, 실측하니 그 지시가 정확히 맞았습니다.

| 조합 | 대비 | 판정 |
|---|---|---|
| 흰 글자 / 시안 초록 `#2f8f6b` | **3.99:1** | 미달 |
| 흰 글자 / 토큰 `--color-success` `#2e7d6b` | **4.93:1** | 통과 |
| 흰 글자 / 시안 금색 `#b8893a` | **3.14:1** | 미달 |
| 흰 글자 / 토큰 `--color-accent` `#c8911f` | **2.79:1** | 미달 |
| **네이비 글자 / 토큰 금색** | **5.18:1** | 통과 |

`2.79:1` 은 [globals.css:79](src/app/globals.css#L79) 가 **이미 기록해 둔 수치**이고, 그래서 이 저장소에는 `--color-text-on-gold`(네이비)가 이미 있습니다(ADR-106 모집 랜딩에서 같은 문제를 한 번 풀었습니다).

**그러므로 F 배지의 글자만 네이비입니다.** 시안을 따르되 시안이 몰랐던 대비 규칙을 얹었고, 이 저장소가 전에 내린 판단을 두 번 내리지 않았습니다.

## 2. 배지 매핑과 강조 규칙

| 순서 | 축 | 이니셜 | 기본 |
|---|---|---|---|
| 1 | 조감도 | G | 네이비 |
| 2 | 현실인식 | R | 네이비 |
| 3 | 원씽 | O | 네이비 |
| 4 | 피드백 | W | 네이비 |
| 5 | 정체성 | F | **금색(바닥)** |

```ts
export function growEmphasis(grow) {
  const top = Math.max(...keys.map((k) => grow[k]));
  // 지렛대를 먼저 본다 — 그래야 F 가 최고점일 때 초록이 금색을 이긴다.
  for (const k of keys) out[k] = grow[k] === top ? 'lever' : k === 'F' ? 'floor' : 'plain';
}
```

- **최고점은 런타임 계산** — 하드코딩 0
- **동점이면 해당 축 모두** 지렛대
- **F 가 최고점이면 초록 우선** — 판정 순서가 그것을 자연히 만든다
- **판정은 사후(post) 값으로만** — 사전 막대는 회색 그대로. '그때'까지 물들이면 무엇을 본 판정인지 흐려진다

색표 `GROW_TONE` 은 **화면(CSS 변수)과 PDF(리터럴)가 한 표를 봅니다** — ADR-112 `CARE_TONE` 과 같은 구조입니다.

## 3. 지시 범위를 넘은 지점 하나 — PDF 도 함께 바꿨다

지시서는 `리포트 1면`(화면)을 말했습니다. PDF 도 `twoCol` 두 벌로 **같은 2×2**를 그리는데, 인쇄물만 옛 순서로 두면 **인도자가 화면과 종이를 오갈 때 동선이 어긋납니다.** ADR-112 에서 배너 색을 양쪽에 함께 준 것과 같은 이유입니다.

PDF 배지는 14×14 축소판(A4 밀도에 맞춤)이고 판정·색표는 화면과 **동일**합니다.

---

## 4. 선택 항목 — 범례는 넣지 않았다

§3.3 이 **`기본은 생략, 범례 없이 색만`** 이라 명시했습니다. 색의 뜻은 인도자 가이드가 집니다(ADR-111 이 원응답을 가이드에 맞춘 것과 같은 전제 — 가이드가 동반 문서입니다).

> ADR-111 에서는 `권장` 이던 축 소제목을 넣었는데 여기서 범례를 뺀 이유는 **지시서의 기본값이 반대**이기 때문입니다.

---

## 5. 판단 필요 — 전 축 동점이면 강조가 사라진다

다섯 축이 **전부 같으면** 규칙대로 **다섯 다 지렛대(초록)** 가 됩니다.

전 축 3.0 은 평평하게 응답한 사람에게서 **실제로 나오는 값**입니다. 그때 인도자는 `모든 축이 지렛대`라는 무의미한 화면을 봅니다(아래 렌더 ③).

지시서 §3.2 의 동점 규칙이 명시적이라 **규칙대로 구현하고 보고만 했습니다.** 테스트가 그 결과를 못 박아 두었으니, 바꾸실 경우(예: 전 축 동점이면 지렛대 없음) 한 줄입니다.
