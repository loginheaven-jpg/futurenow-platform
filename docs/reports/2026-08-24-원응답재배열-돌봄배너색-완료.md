## 2. 원응답 재배열 (ADR-111)

### 새 그룹 순서

```
1 들어가며 · 인생 조감도   (INTRO — 자유서술, 코드 없음)
2 활력                    A1 · A3 · A2 · A5 · A4
3 나침반                  NAV1 · NAV2 · NAV3 · NAV4
4 준비도 (GROW+F)         C2·C1 / C3·C4 / C6·C5 / C8·C7 / C9
5 다섯 영역의 간격        B1 · B2 · B3 · B4 · B5
6 참여자의 언어           E1 · E2 · E3
7 숨은 층 · 인도자 참고   D1 · D2 · D3 · F1 · F2
```

`지금의 나`(A·C·D 혼합)를 해체했다 — `NOW_CODES` 폐기. 믿음(F)이 중간에서 끝으로 옮겨 함정(D)과 한 그룹이 됐다.

### 준비도가 코드 번호순이 아닌 이유

`scoring.ts` ③과 **1:1**이다.

```
G = avg(C2, C1)      → 조감도
R = avg(C3, C4)      → 현실인식
O = avg(C6, 6−C5)    → 원씽
W = avg(C8, C7)      → 피드백
F = C9               → 정체성
```

축 이름은 **`GROW_AXES` 를 그대로 돌려** 만든다. 새로 적은 강의 어휘가 없다.

### 선택 항목 셋의 처리

| 항목 | 지시서 | 채택 | 사유 |
|---|---|---|---|
| §3.2 문항 번호 병기(`A2 · 문7`) | 선택 · 기본은 코드만 | **코드만** | 지시서가 기본을 명시 |
| §3.3 축 소제목 | 선택 · 권장 · 최박사 확인 | **넣음** | 아래 |
| §3.1 그룹6 제목 | `나에게 묻는 시간` 또는 `참여자의 언어`(택1) | **참여자의 언어** | 지시서 표의 정본 · 코치 화면 · 가이드 표기 |

**축 소제목을 넣은 판단**: 소제목이 없으면 준비도 9문항이 `C2·C1·C3·C4…` 라는 **설명 없는 비번호순**으로 보인다. 재배열이 오히려 혼란을 준다. 소제목이 짝 순서를 눈으로 읽히게 하는 장치다.

> **되돌리기**: `RawAnswers.tsx` 의 `GROW_AXES.map` 안 소제목 `<div>` **한 줄**을 지우면 된다. 지시 주시면 즉시.

## 3. 기존 테스트 충돌 — 삭제하지 않고 좁혔다

`RawAnswers.test` 가 이렇게 단언하고 있었다.

```js
expect(html).not.toContain('준비도');  // GROW 패널
expect(html).not.toContain('GROW');
```

새 그룹 제목이 `준비도 (GROW+F)` 라 **레드가 났다.** 그러나 그 단언의 진짜 의도는 **낱말 금지가 아니라 파생 점수 비혼합**이었다. 제목은 점수가 아니다.

지켜야 할 불변 쪽에 못을 다시 박았다.

```js
expect(html).not.toContain('활력의 이동'); // 패널 제목
expect(html).not.toContain('시들음');      // 구간 판정
expect(html).not.toContain('번성');
expect(html).not.toContain('역채점');
expect(html).not.toContain('주 함정');     // 판정은 인도자 패널 몫
```

ADR-105 의 PLEDGE 처리와 같은 방식이다 — **레드가 났다고 지우지 않고, 무엇을 지키려던 단언인지 되묻는다.**

## 4. 돌봄 배너 색 (ADR-112)

| 트리거 | 조건 | 색 | fill / line / text / body |
|---|---|---|---|
| `byVitality` | 마모 A2·A5·A4 **모두 4~5**(Red Flag) | 앰버 | `#fbf4e9` / `#e6cfa6` / `#8a6a2f` / `#7a6134` |
| `byCareCheck` | 참여자가 1:1 요청(Red Flag) | 블루 | `#eef3fb` / `#c6d6ee` / `#345088` / `#42588a` |
| `languish` | 활력 **총점 10 이하**(Red Flag 아님) | 그레이 | `#f2f4f7` / `#d9dee7` / `#5a6472` / `#5a6472` |

**왜 색이 필요한가**: 우선순위로 **하나만** 뜨므로 인도자는 배너를 보고도 왜 떴는지 모른다. 특히 `byVitality` 와 시들음은 **제목이 글자 그대로 같다.** 문안으로 갈 수 없는 구분이라 색으로 간다 — 시안 하단 주기가 바로 이 함정(`byVitality ≠ 시들음`)을 짚는다.

**구현**: `careBanner` 반환에 `kind` 추가. 색표는 `CARE_TONE`(리터럴) + `CARE_VAR`(CSS 접두어) **한 곳** — 화면(CSS 변수)과 PDF(react-pdf, var 미지원)가 같은 표를 본다.

**삼중 잠금**: 시안 HTML ↔ `globals.css` ↔ `CARE_TONE` 12개 값을 **원본을 직접 읽어** 대조한다. 스냅숏 사본을 만들지 않았다(ADR-106 랜딩과 같은 계열). 시안이 고쳐지면 여기가 먼저 레드가 된다.

### 지시 범위를 넘은 지점 하나 — 판단 필요

**테두리를 왼쪽 3px → 전체 1px 로 바꿨다.** 지시는 `색상`이었다.

시안 색이 옅어서(`#e6cfa6` 등) 왼쪽 막대만으로는 형태가 잡히지 않는다 — 옛 색(`#d85a30` 코랄)이 진했기에 3px 막대가 성립했다. 시안 자신이 전체 1px + radius 로 그 옅은 색을 받는다.

> **되돌리기**: `CareSignal`·`pdf.tsx` **각 한 줄**. 지시 주시면 즉시.

**시안의 도트(9px 원)는 넣지 않았다** — 색이 아니라 형태라 지시 범위 밖으로 봤다. 필요하시면 추가하겠다.

**기존 `--care-*` 는 손대지 않았다** — 콘솔(`먼저 챙길 분`·삭제 확정 버튼·로스터 행)과 `ui.css`, 활력 구간 `tone==='care'` 가 계속 쓴다. 이번에 가른 것은 **배너 하나**다.

## 8. 함께 보고 — 모집 자료 열람 범위 문구 불일치 (미조치)

앞선 확인에서 찾은 것으로, 이번 커밋 범위 밖이다.

앱은 참여자에게 일관되게 **`인도자와 운영자만 봅니다`** 라고 말한다(`StartGuide`·`ResponseRunner`·갈무리 1~5회차·`LetterPhotos`·개인정보 동의). ADR-77 이 §4.3 을 `운영자 포함`으로 확정하며 **정직하게 갱신한 문장**이다.

그런데 모집 카드뉴스·원고·랜딩 셋은 **`세미나 인도자만 봅니다`** 라고 한다(카드 8).

- 사실과 다르다 — 운영자도 원응답을 본다
- **가입 전 약속이 가입 시 동의서보다 좁다**
- ADR-77 이 일부러 고친 문장이 옛 형태로 남았다(원고 작성 8/18 이 ADR-77 이후인데 옛 진단지 문구를 가져온 것으로 보인다)

지휘부 문안이라 임의로 고치지 않았다. 지시 주시면 시안·원고·랜딩 셋을 함께 고치고 카드 8 을 재렌더한다(테스트가 셋을 묶고 있어 한쪽만 고치면 레드가 난다).
