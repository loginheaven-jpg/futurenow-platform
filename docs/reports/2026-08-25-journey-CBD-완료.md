## 4. 화면 D — PDF

`ReportPrintButton`·`ReportPrintHeader` 를 **그대로 재사용**했습니다. 사본을 만들지 않으려고 헤더에 선택 `title` 만 더했습니다(기본값은 기존 문구라 리포트 출력 무변경).

**`<details>` 를 쓰지 않았습니다.** 브라우저가 비열림 자식을 UA 규칙으로 감춰 `@media print` 강제 펼침이 기기마다 다르게 동작합니다. **ADR-77 의 `report-raw-content` 가 이미 검증한 display 토글**을 그대로 씁니다.

```css
@media print {
  .journey-print-root { max-width: none !important; ... }
  .journey-full-content { display: block !important; }   /* 접힘이 펼친 채로 인쇄 */
}
```

토글 버튼은 `no-print`, 대신 `print-only` 회차 제목이 그 자리를 대신합니다.

**인도자 PDF에 신호가 포함됩니다**(사실 요약이지 해석이 아닙니다). **AI 자리는 비워 두지도 않았습니다** — 빈 자리가 남으면 다음 사람이 채워야 할 결손으로 읽힙니다. **격자 PDF는 만들지 않았습니다.**

## 5. 배달 검증이 경계를 짚었습니다

첫 실행에서 `인도자에게 남긴 말이 없다` 가 **레드**였습니다. 원인을 보니 **⑦ 회차별 전문**이었습니다.

`buildCheckinRead(..., 'self')` 는 참여자에게 **자기가 쓴** 인도자 상자 내용과 자신감 값을 되읽어 줍니다. 그것은 `/my/cohorts/[id]/checkin/[n]` 열람 화면이 **이미 하는 일**이고, 발주서 §5-3 표가 ⑦을 `self` 로 **명시**했습니다.

**그러므로 제외 셋은 편집 블록에 관한 것입니다.** ADR-86 이 막은 것은 *자기 숫자 다섯이 세로로 서서 추이 그래프가 되는 것*이지, 접힌 회차 안에 자기가 적은 한 값이 있는 것이 아닙니다. 단언을 그 경계로 좁혔고, **경계 자체가 실재함**(전문 블록이 뒤에 있음)도 함께 단언합니다.

가드가 헛돌지 않음도 증명합니다 — **같은 자료로 화면 A 는 셋을 전부 그립니다.**

```ts
expect(a).toContain('자신감');
expect(a).toContain('자료 미리 주세요');
expect(a).toContain('신호');
expect(a).toContain('급락');
```

그리고 ⑦이 `facilitator` 가 아니라 `self` 임을 `readModel:202`(익명 체크 상태는 본인에게만)로 확인합니다.
