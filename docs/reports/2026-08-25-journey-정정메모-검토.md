# 반박 2

## ① §1-2 — `자신감 하강`의 "재료 16건"은 그 신호의 재료가 아닙니다 ★★

메모가 `자신감 하강`을 **보조 → 주**로 올렸습니다. 근거는 표의 `1기 재료 · 16건`입니다.

### 그런데 신호 조건은 응답 수가 아닙니다

```
자신감 하강 = 두 회차 연속 하강 (양쪽 응답 있을 때만)
```

같은 사람이 **인접한 두 회차 모두** 자신감을 냈어야 한 번 판정할 수 있고, 그 판정이 **두 번 연속 하강**이어야 신호입니다. 16은 **응답 건수**일 뿐 이 조건과 무관합니다.

### 재측정 (2026-08-25 · 1기 · `role='user'` · 제출 행)

```sql
WITH c AS (SELECT user_id, session_no, (answers->>'confidence')::numeric AS conf
           FROM checkins ... WHERE submitted_at IS NOT NULL
             AND jsonb_typeof(answers->'confidence')='number'),
pairs AS (SELECT a.user_id, a.session_no s1, a.conf c1, b.conf c2
          FROM c a JOIN c b ON b.user_id=a.user_id AND b.session_no=a.session_no+1)
SELECT count(*) FROM pairs p1 JOIN pairs p2
  ON p2.user_id=p1.user_id AND p2.s1=p1.s1+1
 WHERE p1.c2<p1.c1 AND p2.c2<p2.c1;
```

| 항목 | 값 |
|---|---|
| 자신감 응답 | 16건 |
| **응답자** | **9명 중 5명** |
| 연속 쌍(판정 가능) | 10쌍 |
| 하강 쌍(1회) | 4쌍 — `2→3 7→6` · `3→4 8→6` · `1→2 8→3` · `2→3 8→7` |
| **두 회차 연속 하강** | **0건** |

**신호가 1기에서 한 번도 켜지지 않습니다.**

### 같은 메모가 정반대 논리를 씁니다

§1-2는 `연락 요청`을 **0건이라서 보조로 강등**했습니다.

> *"재료가 없는 것을 주에 두면 그 자리가 낭비된다."*

**`자신감 하강`도 실제 발생 0건입니다.** 같은 기준을 적용하면 보조여야 합니다. 메모는 **둘 다 0건인 신호의 급을 정반대로** 바꿨습니다 — 하나는 내리고 하나는 올렸습니다.

### 그리고 §10의 규율이 같은 메모 안에서 다시 어긋났습니다

> §10: *"앞으로 DB 실측을 근거로 설계를 바꿀 때는 **그 쿼리 자체를 보고에 싣겠다.** 값만 적으면 도구의 오류가 보이지 않는다."*

§1-2 표는 `16건`이라는 **값만** 적었고 쿼리를 싣지 않았습니다. 그래서 **그 16이 신호 조건과 무관한 수라는 것이 보이지 않았습니다.** 원인은 도구가 아니라 **지표 선택**이지만, 규율이 막으려던 실패 유형은 같습니다.

### 판단 요청 — 셋 중 하나

| 안 | 내용 |
|---|---|
| ⓐ | **보조로 되돌린다** — 발생 0건. `연락 요청`과 같은 대우 |
| ⓑ | **조건을 바꾼다** — `연속 2회` 대신 **하강 폭**으로. 1기에 `8→3`(5점 급락)이 실재하는데 지금 조건으로는 안 잡힙니다 |
| ⓒ | 주로 두되 **1기에서는 안 켜진다는 것을 알고** 간다 |

**ⓑ를 권합니다.** 급락 한 번이 완만한 두 번보다 인도자에게 중요한 신호이고, 재료가 실제로 있습니다(4쌍 중 1건이 5점 낙폭). 어느 쪽이든 **"재료 16건"이라는 근거는 표에서 빼야** 합니다.

### 부기 — `연락 요청` 강등은 재고를 권합니다

`contact_request`는 **참여자가 명시적으로 손을 든 유일한 신호**입니다. 나머지는 전부 코드의 추론입니다. 0건인 것은 *"재료가 없다"* 가 아니라 *"아직 아무도 요청하지 않았다"* 이고, **켜지는 순간 가장 확실한 신호**입니다.

**빈도로 급을 정하면 희귀하지만 중대한 신호가 가장 낮은 급이 됩니다.** 이것은 확실성으로 매겨야 하는 자리입니다. (다만 `care` 톤 전용이라 급을 내려도 시각적으로는 여전히 구별됩니다 — 실질 영향은 작습니다.)

# 보완수용 3

## ① `AXIS_INDEX[3] = 0` 이 종단 축의 "영역3"이 아닙니다 — **제 제안이 부정확했습니다**

메모 §2가 제 `AXIS_INDEX`를 승인했는데, **3회차를 다시 보니 제 제안이 정확하지 않았습니다.**

### 3회차 `areaPick` 실물

```ts
areaPick: {
  key: 'gap_area',                    // 칩 — 일·재정·관계·건강·기여
  label: '… 지금 가장 간절한 영역 하나를 골라 주세요.',
  lines: [
    { key: 'gap_want', label: '그 영역에서 지금 가장 바라는 것 한 가지는' },
    { key: 'rough_project', … },
  ],
  mirror: { label: '지난 시간에 가장 가슴이 뛴다고 고르신 영역', keys: ['future_area', …] },
}
```

- `gap_area` = **간절한 영역**(칩)
- `gap_want` = 그 영역에서 바라는 것(칩 아래 줄)
- `summaryFields[0]` = `{ label:'지금 가장 바라는 것', key:'gap_want' }`

**`gap_area`는 `summaryFields` 어디에도 없습니다.**

### 종단 축 주석의 "영역3"은 `gap_area`를 가리킵니다

`index.ts:31`: `갈망1 → 한 문장2 → 영역3 → 원씽4 → 환경5`

2회차 `areaPick.key = future_area`이고 **3회차 `mirror`가 그 `future_area`를 되비춥니다.** 즉 `future_area`(2회차 영역) → `gap_area`(3회차 영역)로 이어지는 축이 실재하고, 주석의 "영역3"은 그것입니다.

**따라서 `AXIS_INDEX[3]=0`(=`gap_want`)은 주석의 축과 다른 것을 가리킵니다.** 인덱스 표로는 `gap_area`를 잡을 수 없습니다 — `summaryFields`에 없기 때문입니다.

### 그래도 `gap_want`가 맞다고 봅니다 — 다만 주석을 함께 고쳐야 합니다

`summaryFields`는 **나눔 후보 열**이고 종단 축과 목적이 다릅니다. 3회차가 `gap_area`(낱말 하나)를 나눔 열에 안 넣은 것은 합리적입니다 — 한 낱말은 문장이 아닙니다.

그리고 종단 축의 나머지 넷(갈망 쌍 · 한 문장 · 원씽 · 환경)이 **전부 문장**입니다. `gap_want`("그 영역에서 지금 가장 바라는 것")가 결이 맞고, 4회차 `인생의 원씽`으로 이어지는 흐름도 자연스럽습니다.

**그러므로 `AXIS_INDEX[3]=0`을 유지하되, `index.ts:31` 주석의 `영역3`을 실제 축(`바라는 것3`)에 맞게 고쳐야 합니다.** 그러지 않으면 주석과 코드가 어긋난 채 남고, 다음 사람이 `gap_area`를 축으로 되살립니다.

### 충돌 주의 — 그 주석을 session6 지시서도 건드립니다

`CC_ORDER_checkin_session6.md` §7이 **같은 `Mirror.back` 주석 한 줄**을 고치라고 지시합니다(옛 배속 `남은 시간6 → 정체성 선언7` 정정). 제 session6 검토서에서 §7이 **파일을 `slots.ts`로 잘못 적었다**(실제는 `index.ts:31`)고 보고했습니다.

**두 지시서가 같은 주석 한 줄을 각각 다른 이유로 고칩니다.** 먼저 착수하는 쪽이 양쪽 정정을 함께 반영하고 나머지 지시서에 그 사실을 남겨야 합니다. 지금 지정해 주시면 좋습니다.

## ② 자신감 응답자는 5명뿐입니다 — 화면 A의 열은 절반이 `—`

메모 §1-1은 *"제출 24건 중 16건(67%)"* 로 고쳤습니다. **건수 기준으로는 맞습니다.**

사람 기준으로는 **9명 중 5명(56%)** 이고, 그 5명이 여러 회차를 낸 것입니다. **화면 A를 4명에 대해 열면 자신감 열이 전부 `—`** 입니다.

원래 지시서 §5-1 ③의 *"실측상 이 열의 대부분이 `—` 다"* 는 **건수로는 틀렸고 사람으로는 절반쯤 맞았습니다.** 메모가 그 문장을 지운 판단은 옳으나, **`—` 처리 규칙을 남긴 것이 더 중요해집니다** — 열 자체를 지우면 안 되고, 4명에게는 빈 열이 정상입니다.

## ③ §2 "6·7회차는 발주 시 한 줄씩" — 7회차는 참여자 카드가 없습니다
