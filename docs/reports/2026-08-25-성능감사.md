## 1. 실측 — 리전이 전부였다

### 프로덕션 TTFB (동일 커밋 `bc2e820`, 리전만 다름)

| 경로 | `icn1::iad1` (전) | `icn1::icn1` (후) | 차이 |
|---|---|---|---|
| **`/login`** (DB 호출 **0**) | **349~452ms** | **150~236ms** | **−200ms** |
| `/recruit` (엣지 캐시) | 150ms | 150~173ms | 변화 없음(정상) |
| `/recruit` (STALE 재생성) | 435ms | — | 함수 왕복 비용 ~285ms |
| `/home` (307, 엣지) | 127~153ms | — | 함수 미경유 |

**`/login` 이 결정적입니다.** 데이터 조회가 한 줄도 없는 페이지가 350~450ms였습니다. 같은 페이지가 로컬에서는 **8~96ms**입니다. 차이는 전부 **위치**입니다.

### 왕복 단가

| 구간 | 값 |
|---|---|
| 한국 → Supabase 서울 (제 PC 실측) | 72~100ms |
| `iad1` → Supabase 서울 → `iad1` | ~200ms+ **[추정]** |
| 한국 → `icn1` → `iad1` → 한국 | ~150~200ms **[확정, 위 표]** |

여기에 **요청마다 인증 왕복이 하나 더** 붙습니다. `src/proxy.ts` 가 정적 자산을 뺀 모든 요청에서 `await supabase.auth.getUser()` 를 부르는데, 이것이 로컬 JWT 해독이 아니라 네트워크 호출임을 패키지에서 확인했습니다.

```js
// node_modules/@supabase/auth-js/.../GoTrueClient.js
async _getUser(jwt) { return await _request(this.fetch, 'GET', `${this.url}/user`, ...) }
```

리전이 어긋난 동안에는 **모든 클릭에 ~200ms 가 무조건** 붙었고, 페이지가 4~6번 직렬 await 하면 그것이 곱해졌습니다.

## 3. 증상 2 — 왜 아무 반응이 없었는가

두 겹이었습니다.

**ⓐ 클라이언트 라우팅 부재.** 내부 앵커 **57곳 / 26파일**이 순수 `<a>` 였고 `next/link` 는 4곳뿐이었으며 **넷 다 `href="/"`** 였습니다(ADR-52 의 결과). 순수 앵커는 Next 라우터를 거치지 않으므로 **클릭 즉시 뜰 수 있는 폴백이 원천적으로 없고**, 브라우저는 새 문서의 첫 페인트 전까지 이전 화면을 그대로 칠해 둡니다.

**ⓑ 눌림 피드백 0.** Tailwind Preflight 가 `-webkit-tap-highlight-color: transparent`(`preflight.css:45`)로 모바일 기본 탭 하이라이트를 껐고, `src/` 에 되돌리는 선언이 **0건**이며, 저장소 전체 `:active` 규칙 **3개**가 전부 `.ui-btn--*`·`.ui-listrow--tappable` 전용인데 **헤더와 홈 카드 행은 인라인 스타일이라 그 클래스가 안 붙어 있었습니다.**

→ 탭 → **화면 변화 0** → "안 눌렸다" → 재탭. **재탭은 진행 중이던 요청을 취소하고 처음부터 다시 시작시킵니다.**

> **커버리지 정정**: 루트 `src/app/loading.tsx` 하나가 **30개 라우트 전부**를 덮습니다(`loading.md:78·88` — `loading.js` 는 `page.js` 와 그 아래 모든 자식을 Suspense 로 감싼다). 죽은 구간은 "전 구간"이 아니라 **클릭 ~ TTFB 사이**였습니다. *"loading.tsx 가 30개 중 2개뿐"* 은 개수로는 맞지만 커버리지로는 오해를 줍니다.

## 4. 처방

### A. 완료 (ADR-119·120)

| 작업 | 기대 | 상태 |
|---|---|---|
| 함수 리전 서울 | **모든 요청 −200~400ms** | 최박사 완료 |
| `vercel.json` 고정 | 회귀 방지 | 완 |
| `<a>` → `<Link>` 57곳 | **증상 2 해소.** 클릭 즉시 로딩 표시 | 완 · 실증 |
| 격자·로스터 `prefetch={false}` | 링크 72개 화면의 프리페치 폭주 차단 | 완 |
| 눌림 피드백 | 탭 즉시 반응 | 완 · 실증 |
| 잠김 결함 4건 | 영구 잠김 제거 | 완 |
| `run()` pending | 이중 발화 차단 | 완 |
| 홈 → 차수 홈 직결 | 단일 차수 사용자 **서버 렌더 1회 제거** | 완 |

### B. 중기 (사전 보고 필요)

| 작업 | 기대 | 제약 |
|---|---|---|
| 독립 await 3개 이상 `Promise.all`(`/account`·`/home`) | ADR-61 실측상 유의미(4직렬 854ms → 병렬 289ms) | 게이트-데이터 순서(§9)·`.catch` 누락 시 에러 페이지 회귀 |
| 폰트 self-host(`next/font/local`) | 첫 방문 2.2~3.7MB → 수백 KB | weight 축소는 §8 지휘부 소관 |
| `CHECKIN_ANSWERS_SCHEMA` 를 서버 전용 모듈로 | first-load **−70KB gzip** | 클라이언트 4곳이 `createCoreContext` 를 값으로 import 하는 것이 원인 — §3 범위 보고 |
| `LogoutButton`·`ConsentGate` 서버 액션화 | supabase-js 64KB 를 ~15개 라우트에서 제거 | §3 범위 보고 |
| 세그먼트별 `loading.tsx` | 전면 텍스트 → 화면 유지형 스켈레톤 | **§8 도안 확정 필요** |

### C. 관측 — 먼저 재야 할 것

| # | 무엇 | 왜 |
|---|---|---|
| C1 | `curl -D - .../login` 의 `x-vercel-id` | `icn1::icn1::` 유지 확인. **유일한 합격 판정** |
| C2 | **로그인 상태 실제 TTFB**(`/home`·`/my/cohorts/[id]`) | 이번 조사는 자격증명이 없어 **인증 페이지를 한 번도 못 쟀다.** 직렬 await 의 실제 비용은 여기서만 확정된다 |
| C3 | 카카오톡 인앱 브라우저 · 모바일 LTE 콜드 로드 | 참여자 실사용 환경. 폰트·번들 비용은 여기서만 드러난다 |
| C4 | 클릭 → 첫 시각 변화 초시계(전후) | 증상 2 의 유일한 정직한 지표. 서버 TTFB 로는 안 잡힌다 |

## 5. 이건 원인이 **아니다** (오해 방지)

| 오해 | 사실 |
|---|---|
| `force-dynamic` 26/30 이라 느리다 | **25곳 중 22곳이 no-op.** `cookies()`/`searchParams` 가 이미 동적으로 만든다. **지우는 데 인력을 쓰지 말 것 — 1ms 도 안 바뀐다** |
| `loading.tsx` 가 2개뿐이라 안 뜬다 | 루트 1개가 **전 라우트를 덮는다.** 문제는 개수가 아니라 클라이언트 전환 부재 |
| 쿼리·인덱스가 느리다 | **DDL 0건.** 최대 테이블 `checkins` **53행/392kB**, `my_cohorts` 8.06ms. 미사용 인덱스 15개는 **지우지 말 것**(행이 적어 플래너가 안 쓸 뿐) |
| 코치 콘솔이 전부 재로딩 | 아니다. 콘솔→차수→리포트 축은 `router.push` 라 **이미 클라이언트 전환** |
| `@react-pdf/renderer` 가 번들을 키운다 | **번들에 0바이트.** 다만 설치 의존성 ~11MB 가 죽어 있어, 클라이언트에서 import 하면 즉시 새는 지뢰 |
| favicon 404 | 브라우저가 부정 결과도 캐시한다. 기여 **0** |
| 프록시가 매 요청 인증 왕복 | 세션 쿠키 없으면 왕복 0, 있어도 요청당 1회 |
| RLS 48건이 성능 문제 | 호출당 ~10µs, 최대 45행. 기여 0 |

### 조사 중 잡은 위양성 하나

`<Link>` 전환 실증 첫 시도에서 **클라이언트 전환이 안 되는 것처럼 보였습니다**(document 재요청 발생, 하이드레이션 실패). 원인은 포트 3000 에 남아 있던 **이전 빌드의 좀비 프로세스**였습니다 — 청크 매니페스트가 안 맞아 JS 가 500 을 냈습니다. 서버를 정리하고 다시 재니 전부 통과했습니다. **`fetch 200 ≠ browser normal` 규율이 여기서 값을 냈습니다.**

## 7. 이번 조사가 확인하지 **못한** 것 (정직한 공백)

1. **인증 페이지의 실제 TTFB** — 자격증명이 없어 `/home`·`/my/cohorts/[id]`·`/coach` 를 한 번도 재지 못했습니다. 직렬 await 의 실제 비용은 여기서만 확정됩니다.
2. **모바일 실기기** — 탭 하이라이트 복원(`-webkit-tap-highlight-color: initial`)은 데스크톱 Chromium 으로만 확인했습니다. iOS Safari 확인이 필요합니다.
3. **`<Link>` 전환의 재적재 절감량** — 기전은 확정이나 크기는 재지 않았습니다 **[추정]**.
4. **Hobby 플랜에서 `vercel.json` 단일 리전이 적용되는지** — 문서로 확인하지 못했습니다. 적용되지 않으면 대시보드 설정이 유일한 통로입니다.
