## 2. 사본이 셋이 되는 자리를 잠갔다 (지시 1)

```
tests/fixtures/membershipAccess.ts   ← 재는 자(픽스처)
src/app/_lib/assessmentAccess.ts     ← 표시 매핑(앱). 픽스처를 모른다
supabase  member_can_assess()        ← 서버 강제
```

`assessmentAccess` 가 의존하는 것은 **계약 타입 하나뿐**이다. 테스트가 양쪽을 대조한다 —
5상태 × 2계열 전수 + 여정을 여는 상태는 `cohort` 하나 + 상시는 `cohort`·`individual` 둘.

**import 금지를 테스트로 못 박았다.** 첫 판은 소스 텍스트에 `fixtures/membershipAccess` 가
없는지 보게 했는데 **주석의 설명까지 잡혀 레드가 났다.** 규칙을 **설명하는 것**과 **읽어 쓰는 것**은
다르므로, import/export 문만 걸러 검사하도록 좁혔다. 자기 테스트가 자기 설계를 먼저 때린 자리다.

## 3. 전화번호는 서버 경계에서 잘린다 (지시 2)

`page.tsx`(서버 컴포넌트)가 `listMembershipQueue` 원값을 받아 `maskPhone` 을 지나
`forumPhoneMasked` 만 클라이언트 컴포넌트에 넘긴다. **원값은 브라우저 번들에 실리지 않는다.**

`maskPhone` 순수 함수 + 테스트 6종:
국내(`010-****-1234`) · 구분자 있는 입력 · 국제번호(`+` 보존) · null/빈 값 → null ·
**8자리 미만은 통째로 가림**(부분 노출이 곧 전체 노출) · 가운데 숫자 부재 확인 · 8자리 경계.

전체 노출이 필요하면 기존 게이트(`getContactDetail` · `assertContactAccess`)를 지난다.
**이 화면에 '전체 보기' 우회로를 만들지 않았다.**

## 4. 응시 게이트 — 화면이 아니라 RPC (지시 3)

| 함수 | 게이트 | 근거 |
|---|---|---|
| `value_save_progress` | **추가** | 첫 쓰기가 곧 응시 시작이고, 이후 모든 진행 저장도 지난다 |
| `value_finalize` | **추가** | 응시의 마지막 걸음 |
| `value_patch` | **두지 않음** | 확정 후 **자기 기록**에 라벨을 다는 일이라 '새 응시'가 아니다. 열람이 상태와 무관하다는 확정(메모 §2-가)에 더 가깝다 |
| 열람 경로 전부 | **손대지 않음** | 자기가 응시한 결과는 상태와 무관하게 언제나 본인에게 열린다 |

**사전 체크(journey)에는 별도 게이트를 두지 않았다** — 차수 등록이 곧 게이트이고 등록된 사람은
`cohort` 라 여정이 열린다. **게이트를 두 겹 두면 한 겹만 고쳐질 때 뚫린다.**

### 4.1 적용 전 롤백 검증 6/6 PASS

| # | 단언 | 실측 |
|---|---|---|
| 1 | `cohort` 응시 허용 | **PASS** |
| 2 | `held` 차단(차수에는 그대로 남아 있음) | **PASS** — 42501 |
| 3 | `expired` 차단 | **PASS** — 42501 |
| 4 | `pending` 차단 | **PASS** — 42501 |
| 5 | `individual` — **상태 게이트 통과 후 차수 게이트에 걸린다** | **PASS** — `not a member of this cohort` |
| 6 | 열람은 상태 무관 — `held` 로 되돌려도 자기 행 보존 | **PASS** |

**⑤가 중요하다** — 두 게이트가 **독립**임을 실증한다. S-2 의 `/my/values`(차수 미소속 개인 응시)가
성립하려면 상태 게이트를 통과한 뒤 차수 게이트만 비껴가면 되고, 그 구조가 이미 서 있다.

## 5. 시안 이행과 부품 부재

### 5.1 따른 것

| 화면 | 시안 | 이행 |
|---|---|---|
| `/pending` | G | 3단계 진행(✓/●/○) · "지금도 하실 수 있는 것" · 하단 문의 안내 · 딥링크 착지 |
| `/admin/approvals` | P4 | 통계 카드 · **6열 대조 표**(신청자·이메일·**포럼 이름·연락처(마스킹)**·가입 경위·신청일·처리) · "포럼 가입 정보는 신청자가 직접 적은 것입니다" 캡션 · "명단 대조 안 됨" 표기 · 승인 시 유효기간·근거 메모 · 만료 임박 목록 · 하단 문구 |

`/pending` 은 **보호 접두사에 넣지 않았다**(IA v2.1 §2.2) — 대기자는 이미 인증된 사용자라
미들웨어가 할 일이 없고, 접두사를 늘리면 불변식 17 근처를 건드린다. 세션 확인은 페이지가 한다.
**게이트를 데이터보다 먼저** 통과시켰고(CLAUDE §9), 자격이 생긴 사람은 `returnTo` 로 되돌린다.

### 5.2 부품 부재 — 골격에 머문 곳 (§7.2 보고)

지휘부가 넷을 승인했으나 `design_system.md` 에 **사양이 아직 없다.** 임의로 만들지 않고
기존 토큰·`ui-*` 클래스로 **조립 가능한 범위까지만** 했다.

| 부품 | 현재 처리 | 필요한 것 |
|---|---|---|
| **승인 큐 표** | 기본 `<table>` + 역할 토큰. `overflow-x:auto` + `min-width:900` | 열 정렬·행 hover·헤더 고정 사양 |
| **날짜 입력** | `<input type="date">` 에 `.ui-textarea` 를 빌려 입힘 · 높이 44px | 전용 토큰(브라우저 기본 피커 유지 전제) |
| **단일행 입력** | `<input type="text">` 에 `.ui-textarea` 를 빌려 입힘 · `maxLength=200` | `TextArea` 와 구분되는 전용 부품 |
| **PC 브레이크포인트** | `max-width:1200` 만 적용 | 지휘부 확정 4단(`--bp-sm|md|lg|xl`)이 `globals.css` 에 아직 없다 |
| **상태 배지** | **쓰지 않았다** | 대기 큐가 단일 갈래라 배지가 필요 없었다. S-3 진단 허브에서 필요해진다 |

**시안 P4 의 좌측 ADMIN CONSOLE 사이드바(6메뉴)는 만들지 않았다.** S-1 범위는 승인 화면이고,
사이드바는 콘솔 전체의 내비게이션 구조 변경이라 §7.1(PC 우선 콘솔)의 별건이다. 임의로 세우면
되돌리기 비싸다. **지휘부 판단을 청한다.**

## 6. 시안을 따르지 않은 곳 둘 — 근거

### 6.1 메일 발송 문구를 쓰지 않았다 (중요)

시안 셋이 메일을 전제한다.

| 위치 | 시안 문구 |
|---|---|
| G · 3단계 | "확인이 끝나면 **메일로 알려 드립니다**" |
| P4 · 승인 시 함께 정하는 것 | "안내 메일 — **승인과 동시에 1통 발송**" |
| P4 · 만료 임박 | "**갱신 안내 보내기**" 버튼 |

**그런데 통지는 (c)안으로 확정됐다** — 메일 없음 · 인앱 + 운영자 수동(메모 §6). 실측으로
발송 수단이 0임을 확인했고(설계 §5.3), 지휘부가 SMTP 확보를 **별도 트랙**으로 두었다.

시안대로 쓰면 **지키지 못할 약속**이 된다. 참여자는 메일을 기다리다 오지 않고, 오지 않는 이유를
모른다. ADR-119 가 잡은 것과 같은 계열이다 — **문안이 실제보다 넓다.**

→ G 3단계 셋째 줄을 **"확인이 끝나면 이 화면이 열립니다"** 로 바꿨다(인앱 통지 = 확정된 수단).
→ P4 의 "안내 메일" 항목과 "갱신 안내 보내기" 버튼은 **만들지 않았다.**
→ SMTP 가 서면 `notifyMembershipDecided` 훅 안만 바꾸고 이 문구를 시안대로 되돌린다.

### 6.2 S-4 미구현 링크를 걸지 않았다

시안 G 는 "소식 보기 / 공개 자료실 / 세미나 참여 신청" 셋과 하단 탭 4개(홈·소식·자료실·계정)를 둔다.
**`/news`·`/library`·`/contact` 는 S-4 라 아직 없다.** 없는 곳으로 보내면 대기 화면이
404 로 끝나고, 그것은 이 화면이 막으려던 바로 그 막다른 골목이다.

→ **있는 것만 두었다** — `/recruit`(세미나 참여 신청) · `/account`(내 정보).
→ 하단 문의는 링크 대신 **"인도자나 운영자에게 알려 주십시오"** 문장으로. `/contact` 가 서면 링크로 바꾼다.
→ S-4 완료 시 이 화면에 세 링크를 되살린다. **보고서에 적어 두어 잊히지 않게 한다.**
