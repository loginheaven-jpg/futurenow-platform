# S-1 단계 6 완주 보고 — `/signup` 대조 키와 동의 경로별 분기

마이그레이션 `20260826200000_signup_intake.sql` → **적용 `20260826142335`**

> **S-1 의 마지막 구멍을 메웠다.** 승인 화면이 섰는데 대조 키가 비어 있어 운영자가 승인할
> 근거가 화면에 없었다(발주서 §4.3 "이 발주의 급소").

## 1. 판정 — 항목 단위 분기는 **가능했다**

멈추고 보고해야 할 조건(`consent.ts` 구조상 불가능)에 **해당하지 않았다.** 근거 둘:

1. **`ConsentText` 는 타입별 독립 상수다.** `ConsentBlock` 이 `{title, lines, agree}` 를 받는
   재사용 부품이라, 새 상수를 하나 더하는 것으로 항목이 는다. 기존 셋을 건드릴 필요가 없다.
2. **홈 게이트는 `privacy_use` 하나만 본다.**
   `home/page.tsx` — `consents.some((c) => c.type === 'privacy_use' && c.version === CONSENT_VERSION)`.
   다른 유형이 늘어도 이 판정은 변하지 않는다.

→ **`PRIVACY_CONSENT` 의 문안도 `CONSENT_VERSION` 도 한 글자 건드리지 않았다.**
새 유형 **`forum_match`** 하나를 더해 `/signup` 경로에서만 받는다. **기존 22명은 그 행이 없을 뿐
아무 화면도 달라지지 않는다.** ADR-107 의 규율("동의의 **내용**이 바뀔 때만 버전을 올린다")이
그대로 지켜진다 — 기존 동의의 내용은 그대로이고 새 경로에 새 항목이 붙었다.

**인라인 고지로 내려가지 않았다.** 수집 항목이 실제로 느는데 "고지했다"로 갈음되지 않는다는
지휘부 판단 그대로다.

## 2. 저장 배치 — 불변식 13

| 값 | 자리 | 근거 |
|---|---|---|
| 포럼 가입 **이름** | `user_contacts.forum_name` | 계정 이름과 다를 수 있어 `users.name` 을 덮지 않는다 |
| 포럼 가입 **연락처** | `user_contacts.forum_phone` | **불변식 13** — 전화번호는 `user_contacts` 격리. 계정 `phone` 과 별도 컬럼 |
| 가입 **경위** | `memberships.signup_note` | 민감 채널이 아니다 |
| **동의** | `user_consents(type='forum_match')` | 기존 유형 무변경 |

기존 `contacts_self` / `contacts_admin_read` 정책이 그대로 적용된다 — 본인 + 운영자만,
**인도자 전면 차단**. ADR-76 이 `address`·`bank_account` 를 얹은 선례와 같다.

`record_signup_intake` 는 self-scoped DEFINER(ADR-39 `create_coach_application` 패턴)이고
**`status` 를 건드리지 않는다** — 이미 승인된 사람이 정보를 고친다고 자격이 `pending` 으로
되돌아가면 안 된다. 운영자 결정은 `decide_membership` 만 바꾼다.

## 3. 회귀를 한 번 피했다 — `handle_new_user`

세션 없는 분기(이메일 확인 대기)에서도 대조 키가 남게 하려고 트리거를 고쳐야 했다(설계 §4.3).

**초판(`20260626064658`)의 본문을 기준으로 다시 썼다면 ADR-41 이 넣은 `user_profiles` 삽입을
통째로 되돌리는 회귀였다.** `CREATE OR REPLACE` 는 이전 정의를 통째로 대체하므로 조용히 사라진다.

→ **`pg_get_functiondef` 로 라이브 정의를 먼저 가져와** 그 위에 대조 키 블록만 얹었다.
`user_profiles` 삽입·성별/생년/신앙연수 파싱이 전부 그대로다.

**metadata 신뢰 폐기(S3 §3.4)와 충돌하지 않는다** — 그것이 막은 것은 `coachApply` 처럼
**권한을 주는 값**이었고, 대조 키는 운영자가 눈으로 맞춰 볼 재료라 위조하면 승인이 반려될 뿐
아무 권한도 생기지 않는다. **SAIL 가입에는 이 키가 없으므로 NULL 가드에 걸려 무영향**이다.
