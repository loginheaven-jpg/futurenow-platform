## 2. 멈출 수 있던 지점 — 예상과 달랐고, 적용 전에 잡았다

지휘부가 *"부분 유니크 인덱스 교체에서 기존 제약을 걷어내는 방식이 예상과 다르면 적용 전에 보고하라"* 고 했다.
**걷어내는 방식 자체는 예상대로였다** — `UNIQUE (user_id, cohort_id)` 가 테이블 제약(`contype='u'`)이라
`DROP CONSTRAINT` 로 인덱스까지 함께 걷혔다(실측 확인).

**그 다음이 달랐다.**

> **`ON CONFLICT (user_id, cohort_id)` 를 더 쓸 수 없다.** 그 추론은 **비부분** 유니크 인덱스에만 맞는다.
> 부분 인덱스로 바뀌는 순간 세 RPC 의 upsert 가 전부 `there is no unique or exclusion constraint
> matching the ON CONFLICT specification` 으로 죽는다.

갈래마다 `ON CONFLICT (…) WHERE …` 를 쓰면 15줄짜리 INSERT 가 **두 벌**이 된다(이 저장소가 반복해서
데인 "사본이 둘"). → **UPDATE 먼저·없으면 INSERT** 로 바꿨다. `IS NOT DISTINCT FROM` 이 NULL 을 정상 비교한다.

**대가를 숨기지 않는다**: 원자성이 `ON CONFLICT` 보다 약하다. 같은 사람이 동시에 두 번 시작하면
둘째가 23505 를 받는다. **그래도 데이터는 안전하다** — 부분 유니크 인덱스가 진짜 보증이고, 실패가
**예외로 드러난다**(조용한 중복이 아니다). 한 행의 주인이 한 사람이고 화면이 순차라 실측 위험은 낮다.

이것은 적용을 막을 사안이 아니라 **설계 선택이 바뀐 것**이라 판단해 진행하고 여기 적는다.

## 5. 딥링크 검증표 — 실브라우저(Vercel 프리뷰) · **부분**

프리뷰: `futurenow-platform-git-refactor-site-v2-…vercel.app` (브랜치 별칭).
판정은 불변식 19대로 **본문 민감 콘텐츠 0 + 리다이렉트 목적지**로 했다.

| 진입 | 상태 | 기대 | 실측 |
|---|---|---|---|
| `/my/values` | 미인증 | 로그인으로 | **PASS** — `x-matched-path: /login`, 본문이 로그인 폼. **가치 카드 콘텐츠 0** |
| `/pending?returnTo=/my/values` | 미인증 | 로그인으로 | **PASS** — **200 + `NEXT_REDIRECT;replace;/login;307;`** + `meta refresh → /login`. 본문은 `불러오는 중…` 뿐 |
| `/my/values` | 승인 대기·만료·보류 | 응시 차단 | **RPC 층에서 증명**(게이트 6/6 · 진실표 62/62) — 세션 없이 재현 불가 |
| `/my/values` | 개인 회원 | 정상 진입 | 〃 (통합테스트 "미등록 individual 도 연다") |
| `/c/{code}/values` · `/my/cohorts/{id}/values` | 각 상태 | 기존 동작 유지 | 〃 (통합 27건) |

### 5.1 실브라우저가 아니면 못 봤을 것 둘

**⑴ `/pending` 은 200 으로 온다.** `NEXT_REDIRECT` 페이로드로 서빙되고 HTTP 307 이 아니다.
CLAUDE §9 가 *"게이트 화면은 200 을 정상 통과로 판정하지 않는다"* 라고 못 박은 그 형태를 **실제로 관측했다.**
`fetch` 200 만 보고 판정했다면 "대기 화면이 잘 뜬다"고 오독했을 것이다.

**⑵ `/my` 진입 시 proxy 가 `returnTo` 를 비운다.** 로그인 페이로드가 `{"returnTo":null}` 이었다.
발주서 §10 표는 `/login?returnTo=/my/values` → 인증 후 복귀를 기대하는데 **현재는 발화하지 않는다.**
`safeReturn.ts` 주석이 이미 그 사실을 적어 두었다("`/my/…` 는 proxy 가 미인증을 걸 때 search 를 비운다 …
목적지가 같은 화면이라 짝을 맞춰 둔다"). **화이트리스트는 옳고, 붙이는 쪽이 없다.**
→ **판단 청함**: proxy 가 `/my/*` 에도 `returnTo` 를 붙이게 할지. S-3 진단 허브에서 같은 문제가 반복된다.

### 5.2 인증 상태 행을 실브라우저로 못 돈 이유

세션을 만들려면 실계정 자격이 필요하고 **나는 그것을 갖고 있지 않다.** 테스트 계정을 만들면
실데이터에 잔여가 남는다(지금까지 지켜 온 "픽스처 잔여 0"이 깨진다). 그래서 그 행들은 RPC·RLS 층에서
증명하고 **차이를 숨기지 않는다.** 지휘부가 테스트 계정을 지정해 주시면 그 행만 따로 돈다.
