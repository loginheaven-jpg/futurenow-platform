### 3.1 §8-C 차수 권한 — 프로덕션 DB 실측 10/10

지휘부가 병합 후 한 번 더 볼 것을 권한 항목이다. **실제 인도자 계정으로 동작을 재봤다**(롤백).

| 검사 | 결과 |
|---|---|
| `kind` UPDATE 권한(`authenticated`) | **false** ✓ |
| `name`·`description`·`max_members`·`status`·`expires_at` UPDATE 권한 | **전부 true** ✓ |
| `anon` 테이블 UPDATE 권한 | **false** ✓ |
| **인도자 이름 변경 실동작** | **1행** ✓ |
| **인도자 마감(`status`) 실동작** | **1행** ✓ |
| **인도자 `kind` 변경 차단** | **42501** ✓ |

`SET LOCAL ROLE authenticated` + JWT 시뮬레이션으로 **RLS 와 컬럼 권한이 동시에 걸리는 실경로**를
탔다. `updateCohort` 가 쓰는 다섯 컬럼은 열려 있고 `kind` 만 막힌다 — 설계 그대로다.
**전 과정 롤백**했고 실데이터는 변하지 않았다.

### 3.2 `/home` 역할 카드 — **화면으로 보지 못했다**

`/home` 은 보호 라우트라 미인증에서는 로그인 폼이 뜬다(정상). **역할 카드는 세션이 있어야 보인다.**

- **확인한 것**: 라우트 생존 · **`returnTo=/home` 보존**(S-3 returnTo 복원이 프로덕션에서 작동)
- **확인하지 못한 것**: 역할 카드가 실제로 그려지는지, 역할별 목적지가 맞는지

**QA 계정이 오면 이 항목과 딥링크 표 ⑵를 함께 돌린다.** 지금까지처럼 차이를 숨기지 않는다.
`RoleCard` 는 순수 분기 로직이고 `tsc`·빌드가 통과했으나, **그것은 렌더된다는 증명이 아니다.**

## 4. 발견 하나 — 남은 자리가 5 → **3**

ADR-110 이 기록한 실측(2026-08-24)은 **5**였는데 지금 **3**이다.
**자동 집계가 실제로 움직이고 있다는 증거다** — 그 사이 두 분이 사전 체크를 마쳤다.

손으로 박았더라면 그 둘이 반영되지 않은 채 배포돼 있었을 것이다. ADR-110 이
*"신청자가 있을 때마다 하드코딩으로 숫자를 고쳐야 하나"* 를 근거로 자동으로 되돌린 판단이
**운영에서 값을 냈다.**
