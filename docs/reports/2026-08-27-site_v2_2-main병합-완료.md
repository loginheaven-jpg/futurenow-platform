> 하나 잡으면 반영 여부를 확실히 가를 수 있다. `/feed` 404→307 이 그 역할을 했다.
> §9.6에서 별칭 폴링으로 위양성을 낸 뒤라 이번엔 **불변 URL + 내용 대조**를 함께 걸었다.

### 3.1 `/feed` 가 프로덕션에 살았다

병합 전 404 였던 경로가 307 + `returnTo=%2Ffeed` 로 응답한다. 이 한 줄이
**라우트 등재 · `PROTECTED_PREFIXES` 반영 · 미들웨어 게이트 · `loginRedirectSearch` 의 경로-only 정책**
넷을 동시에 증명한다. 본문 15 bytes 는 민감 콘텐츠 0 을 뜻한다(불변식 19).

### 3.2 `/news/[id]` — **발행된 소식이 0건이라 열 글이 없다**

| 확인 | 결과 |
|---|---|
| `news_posts` 라이브 | **0행**(발행분 0 · 초안 0) |
| `/news` | **200** · 빈 상태 문안 *"아직 올라온 소식이 없습니다."* |
| `/news/<없는 uuid>` | **200** + `NEXT_NOT_FOUND` 페이로드 · **본문·댓글 구획 노출 0** · 8.9KB |
| `/news/not-a-uuid` | 동일 |

> **200 을 통과로 판정하지 않았다**(CLAUDE §9 · 불변식 19). `notFound()` 는 307 이 아니라
> **200 + 페이로드**로 서빙된다 — 실제로 그렇게 왔다. 그래서 **본문으로 판정**했고,
> 존재하는 공개 화면(`/about` 13.2KB)과 크기·내용이 뚜렷이 갈린다. 게이트는 정상이다.

**시험 소식을 만들어 넣지 않았다.** `/news` 는 공개 화면이라 시험 글이 방문자에게 그대로 보이고,
현관(`/`)의 소식 구획에도 실린다. 검증 편의를 위해 공개 화면에 가짜 글을 띄우지 않는다 —
`cohort_seats_taken` 을 오염시키지 않은 것과 같은 판단이다.

**대신 다른 층으로 덮여 있다**: 롤백 검증 H군 **8/8**(비로그인 읽기 ○ / 쓰기 ✕ · 초안 거부 ·
`held` 차단 · 삭제 권한 3) · 통합테스트 2건 · `news/[id]/page.test.tsx` **3건**(key·postId·댓글이
같은 글을 가리킨다). **운영자가 첫 소식을 올리는 순간 화면으로 확인된다** — 그때 한 줄 보고한다.
