## 9.1 원인 — 지휘부 진단을 코드에서 확인했다

기수 칩은 **같은 라우트에서 쿼리만** 바꾼다(`/feed?cohort=…`). 그래서 `FeedClient` 가
**재마운트되지 않는다.** 서버는 새 기수의 글을 정확히 내려보내고 `initialPosts` prop 도 바뀌지만,
`useState(initialPosts)` 는 **첫 값만** 쓰므로 `posts` 가 옛 기수 글을 붙든다.

**더 나쁜 것은 `selectedCohortId` 는 prop 이라 갱신된다는 점이다.**
보고 있는 기수와 쓰는 기수가 어긋난다 — 데이터 손상은 아니나 사용자에게는 가장 나쁜 어긋남이다.

`force-dynamic` 도 `<Link href>` 도 정상이었다. 깨진 것은 **화면의 상태 수명** 하나다.

## 9.2 수정 — `key`

```tsx
<FeedClient key={selected.cohortId} … />
```

`useEffect` 동기화를 쓰지 않았다. **기수를 바꾸는 것은 다른 방으로 가는 일**이라 쓰던 본문과
고른 사진이 따라가지 않는 편이 정확하고, `photoUrls`·`mine`·`done` 초기화까지 key 하나가 처리한다.
동기화 코드는 **초기화할 상태가 늘 때마다 빠뜨릴 자리가 는다.**

## 9.3 회귀 테스트 — **결함을 실제로 잡는지 확인했다**

이 결함은 단위·통합·DB 검증 **어느 것도 잡지 못했다.** 전부 옳게 동작했기 때문이다 —
서버는 정확한 글을 내려보냈다. 그래서 **페이지가 만든 엘리먼트 트리의 `key` 를 직접 읽는다**
(렌더 없이 · jsdom·testing-library 없이).

| 파일 | 건수 | key 제거 시 |
|---|---|---|

되돌려 실제로 깨지는 것까지 확인했다.

## 9.4 같은 부류를 함께 막았다 — `/news/[id]`

**인스턴스가 아니라 부류를 봤다.** `/news/1` → `/news/2` 도 같은 자리에 같은 컴포넌트를 그리므로
재마운트되지 않는다. `NewsComments` 가 `useState(initial)` 로 댓글을 잡고 `postId` prop 은
갱신되므로 — **피드와 한 글자도 다르지 않은 어긋남**이다. `key={post.id}` 를 걸었다.

소식 댓글은 2차 산출물이라 이번 발주 범위 안이다.

## 9.5 관찰 — 같은 조건이 성립하는 자리 둘 (**고치지 않았다**)

`useState(prop)` 은 저장소에 10곳 있으나, 위험한 것은 **같은 자리에서 데이터만 바뀌는** 경우뿐이다.
그 조건이 성립하는 곳이 둘 더 있다. **1차 이전 산출물이고 갈무리는 §7-5 가 수정을 금하므로
건드리지 않았다.** 발현 여부는 **확인하지 않았다** — 확인하지 않은 것을 결함이라 적지 않는다.

| 자리 | 조건 | 근거 |
|---|---|---|
| `/my/cohorts/[id]/checkin/[session]` | 회차→회차 이동 · **`?edit=1` 자기참조 링크** | `CheckinCardClient.tsx:144` `useState(initialMode)` · `:327` 같은 라우트에 쿼리만 더한 `<Link>` · 페이지가 `key` 를 주지 않는다 |
| `/coach/cohort/[id]/report/[responseId]` | 리포트→리포트 이동 | `InterpretationPanel.tsx:67-68` · `MemberJourney.tsx:95` 가 형제 리포트로 잇는다 |

`?edit=1` 링크의 주석은 *"상태 토글이 아니라 **실제 이동**이다"* 라고 적어 두었다 —
그 의도가 성립하려면 재마운트가 일어나야 한다. **판단을 청한다**(§10).

나머지 여섯(`AccountClient`·`CoachInfoGate`·`JoinClient`·`RosterDetail`·`ValuesClient` 둘)은
형제 이동 경로가 없어 위험이 낮다.

## 9.6 자기 신고 — **내가 위양성을 냈다**

수정 푸시 뒤 프리뷰를 기다리며 **별칭**(`…-git-feat-site-v2-2-…`)이 응답하는지로 대기 루프를 걸었다.
루프는 **즉시 통과**했다 — 별칭이 아직 **옛 배포**를 서빙 중이었고 그것도 `/feed` 에 307 을 주기 때문이다.
새 배포는 그때 `BUILDING` 이었다.

**§0에서 내가 경고한 바로 그 위양성을 내가 냈다.** 대기를 **불변 배포 URL** 기준으로 다시 걸어
`READY` 를 확인했다. 위양성은 아는 것만으로 막히지 않는다.

# 11. 실기기 2차 — 기수 칩 (2026-08-27 · 추가)

지적: *"상단 기수 탭이 **클릭 자체가 안 된다.** 버튼이 아닌 텍스트 박스인 것처럼 클릭 동작이 안 먹힌다."*

## 11.1 먼저 배제한 것 — **클릭은 먹고 있었다**

추측하지 않고 하나씩 쟀다.

## 11.2 진짜 원인 — **화면이 아무 답도 하지 않았다**

두 값이 겹쳐 만든 결함이다. 둘 다 실측이다.

| # | 사실 | 결과 |
|---|---|---|
| ① | 내가 선택 배경으로 쓴 **`--color-surface-2` = `--gray-0` = `--color-bg`** | **선택 표시가 페이지 배경과 같은 색**이라 애초에 보이지 않았다 |
| ② | 라이브 **살아 있는 글 0건**(전체 1 · 삭제 1 · 사진 0 — 최박사 시험 글이 회수까지 끝났다) | 어느 기수를 보든 **목록이 똑같다** |

**전환이 실제로 일어나도 화면은 한 픽셀도 바뀌지 않는다.** 죽은 클릭과 구분할 방법이 없다.

## 11.3 수정 — 부품을 쓴다

| 수정 | 내용 |
|---|---|
| 칩 → **`ui-btn`** | 내가 만든 인라인 칩을 버리고 design_system 기존 부품을 쓴다. `cursor: pointer`·탭 최소 높이·focus 링이 **이미 들어 있고**, `primary`(네이비 면) / `ghost`(테두리)가 선택을 색이 아니라 **면의 차이**로 가른다 |
| 빈 상태가 기수를 말한다 | *"2기에는 아직 아무도 남기지 않았어요"* — 글이 0건일 때 **전환의 유일한 증거**다. 기수가 하나뿐이면 붙이지 않는다(없는 선택을 암시하지 않는다) |
| `aria-current` · `aria-pressed` | 상태를 **색만으로 말하지 않는다** |

> **내가 만든 칩이 애초에 임의 디자인이었다.** 불변식 20 은 "부품이 없으면 만들지 말라"인데,
> 나는 §12(부재 부품 목록)에 '기수 전환 셀렉터'를 올려 두고도 인라인으로 하나 그렸다.
> 있는 부품(`ui-btn`)으로 되돌리는 편이 규율에도 맞고 결과도 낫다.

## 11.4 회귀 테스트 7건

**링크가 존재하는지가 아니라 선택된 기수와 안 된 기수가 다르게 보이는지**를 단언한다 —
깨진 것이 존재가 아니라 **구분**이었기 때문이다.

- 칩이 `ui-btn` 부품이다(인라인 텍스트가 아니다)
- 선택 = `ui-btn--primary` / 미선택 = `ui-btn--ghost`, 전환하면 **역할이 뒤바뀐다**
- `aria-current="page"` 가 **정확히 하나**
- **글이 0건이어도 빈 화면이 기수 이름을 말한다**
- 기수가 하나면 칩도 이름도 붙지 않는다
- "내 걸음만" 토글이 `aria-pressed` 를 낸다
