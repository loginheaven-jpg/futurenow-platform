## 1. 판정 — 발현

발주 §3.1이 정한 순서대로 **발현 확인을 먼저** 했다. 코드 읽기로 끝났다.

### 1.1 `useEffect` 가 `responseId` 변화에 반응하는가 — **반응하지 못한다**

```ts
const [vm, setVm]         = useState<InterpretationVM|null>(initial);      // :67
const [status, setStatus] = useState(initial ? 'idle' : 'loading');        // :68
const [editing, setEditing] = useState(false);                             // :69
const [draft, setDraft]   = useState<Draft|null>(null);                    // :70
const triggered           = useRef(false);                                 // :71

useEffect(() => {
  if (initial || triggered.current) return;      // ← 이 가드
  triggered.current = true;
  … ensureInterpretationAction(responseId) …
}, [initial, responseId]);                                                 // :86-103
```

의존성 배열에 `responseId` 가 **있다.** 그래서 발주 §3.1의 첫 물음(*"다시 부르는지"*)만 보면
*"깜빡임은 있어도 어긋남은 없다"* 로 보인다. **그러나 가드가 그것을 막는다.**

| 경로 | 결과 |
|---|---|
| A에 해석이 **있었다**(`initial` 있음) → B로 이동 | `initial` 이 truthy 라 **즉시 early return**. `vm` 은 여전히 **A의 해석** |
| A에 해석이 **없었다** → `triggered.current = true` 로 굳는다 → B로 이동 | `triggered` 는 ref 라 재마운트 없이 **살아남는다** → B는 **영영 다시 부르지 않는다** |

`triggered` 가 ref 인 것이 결정적이다. **재마운트만이 그것을 되돌린다.**

### 1.2 `status`·`editing` 도 함께 본다 (발주 §3.1 지시) — **여기가 급소다**

`editing`·`draft` 가 살아남으면 표시가 아니라 **쓰기**가 어긋난다.

```ts
async function saveEdit() {                        // :110
  const content = toContent(draft);                // ← A의 초안
  …
  await saveCoachInterpretationAction(responseId, content);   // :119 ← B의 responseId
```

`responseId` 는 **갱신되는 prop**이고 `draft` 는 **살아남은 state**다.
A의 해석을 편집하던 중 형제 링크로 B로 이동해 저장을 누르면

> **A의 해석 텍스트가 B의 기록에 써진다.**

인도자가 A 화면에서 B의 해석을 **읽는** 것도 위험하지만(지휘부 §3),
이쪽은 **읽는 것이 아니라 쓰는 것**이다. 되돌리려면 누가 언제 무엇을 덮었는지 알아야 한다.

`status` 도 같은 결이다 — B에 해석이 없어 `'loading'` 이어야 할 자리에 A의 `'idle'` 이 남는다.

### 1.3 이동 경로는 실재한다

```
MemberJourney.tsx:95   <Link href={`/coach/cohort/${cohortId}/report/${reportId}`}>
```

리포트 상세 → **형제 리포트**로 직접 간다. 같은 라우트, 같은 자리, 같은 컴포넌트 →
재마운트 없음. 목록을 거쳐 가면(`CohortDetailClient.tsx:164`) 라우트 구조가 바뀌어 언마운트되지만,
**세로 보기에서 사람을 옮겨 가며 읽는 것이 인도자의 실제 동선**이다.

## 2. 수정

```tsx
<InterpretationPanel key={responseId} responseId={responseId} initial={initialVm} />
```

`page.tsx:97`. 2차 §9.2의 판단 그대로 — **`useEffect` 동기화가 아니라 `key`** 다.
동기화로 가면 `vm`·`status`·`editing`·`draft`·`triggered` **다섯을 빠짐없이** 되돌려야 하고,
하나라도 빠지면 오늘 고친 것이 내일 다시 샌다. **다른 리포트는 다른 화면이다.**

## 3. 회귀 테스트 3건 — **결함을 실제로 잡는다**

`src/app/coach/cohort/[cohortId]/report/[responseId]/page.test.tsx`

**"무엇이 깨졌는지"에 맞췄다**(2차 §11.4 규율). 깨진 것은 패널의 **존재**가 아니라
**key·responseId·initial 이 같은 리포트를 가리키는가** 하는 **신원 결속**이다.

| 단언 | key 제거 시 |
|---|---|
| 패널이 `responseId` 로 keyed | **FAIL** |
| 리포트가 다르면 key 도 다르다 | **FAIL** |
| key·`responseId`·`initial` 이 같은 리포트를 가리킨다 | **FAIL** |

**3/3 FAIL → 복원 시 3/3 PASS.** 레드를 내지 못하는 회귀 테스트는 회귀 테스트가 아니다.

## 4. §3.2 전수 확인 — "위험 낮음"의 근거를 다시 쟀다

2차 §9.5가 여섯을 *"이동 경로 없음"* 으로 분류했다. **그 근거가 지금도 참인지** 확인했다.

| # | 자리 | 형제 이동 경로 | 판정 |
|---|---|---|---|
| 1 | `AccountClient` (`/account`) | 없음(단일 라우트) | 위험 없음 |
| 2 | `CoachInfoGate` (`/coach`) | 없음(단일) | 위험 없음 |
| 3 | `JoinClient` (`/join?…`) | **화면 안에는 없다** — `/join?cohort=` 링크는 전부 **다른 라우트**(차수 홈·MemberHome·MyCohorts)에서 온다 | 위험 없음 |
| 4 | `ValuesClient` | `/my/cohorts/[A]/values` → `[B]/values` **링크 없음**. `/my/values` 는 다른 라우트 | 위험 없음 |
| 5 | `CheckinPreviewClient` | 미리보기 단일 | 위험 없음 |
| 6 | **`RosterDetail`** (`/coach/…/checkin?session=N&open=U`) | **있다 — 회차 탭이 쿼리만 바꾼다**(`RosterDetail.tsx:32`) | **조건 성립 · 영향 표시뿐** |
| 7 | **`CheckinCardClient`** (`/my/…/checkin/[n]?edit=1`) | **있다 — 자기참조 링크**(`:327`) | **조건 성립 · 영향 큼(§4.2)** |
| 8 | `InterpretationPanel` | 있다 | **수정 완료** |
| 9 | `FeedClient` · 10 `NewsComments` | 2차에서 수정 | 완료 |

**2차의 "여섯 위험 낮음" 판정은 넷에 대해 지금도 참이고, 둘은 아니었다.**
근거를 다시 재지 않았다면 그대로 넘어갔을 것이다.

### 4.1 `RosterDetail` — 조건 성립하나 **내용은 정확하다**

회차 탭이 `?session=N&open=U` 로 쿼리만 바꾸므로 `Row` 의 `useState(initialOpen)` 이 살아남는다.
다만 **명단 내용은 prop(`entries`)이라 정확**하고, 어긋나는 것은 **어느 행이 펼쳐져 있는가** 하나다.

탭이 각 행 안에 있어 항상 자기 `userId` 를 싣기 때문에 실사용 동선에서는 대체로 맞는다.
**고치지 않았다** — 갈무리 계열 화면이고(§8-5) 영향이 표시에 그친다.

### 4.2 `CheckinCardClient` — **조건이 성립하고, 발현하면 운영 중 결함이다**

| 실측 | 내용 |
|---|---|
| `mode` 초기화 | `useState<'edit'\|'read'>(initialMode)` (`:144`) |
| `setMode` 호출부 | **둘뿐이고 둘 다 `'read'` 로 간다**(`:230`·`:240`) — **`'edit'` 로 가는 클릭 경로가 없다** |
| 편집 진입 | `?edit=1` → 서버가 `initialMode='edit'` 계산 → **prop 으로만** 전달 (`page.tsx:73·114`) |
| 링크 | `:327` `href={.../checkin/${sessionNo}?edit=1}` — **같은 라우트, 쿼리만** |
| 페이지 `key` | **없음** |

**즉, 편집 모드로 가는 유일한 길이 prop 인데 그 prop 이 상태를 갈아끼우지 못한다.**
재마운트가 없으면 "수정하기"를 눌러도 `mode` 가 `'read'` 에 머문다.

> **그 링크의 주석이 스스로 근거를 적어 두었다** — *"상태 토글이 아니라 **실제 이동**이다"*.
> 의도가 옳고, 그 의도가 성립하려면 재마운트가 있어야 한다.

**발현을 확인하지 않았다.** 확인하려면 세션을 갖고 갈무리를 제출한 뒤 눌러 봐야 하고,
그것은 실기기·QA 계정 영역이다. 그리고 **§8-5가 갈무리 수정을 금한다.**

다만 메커니즘은 이번 발주에서만 **세 번** 확인됐다(피드 칩 · 소식 댓글 · 리포트 패널).
**같은 조건이고, 다른 결과가 나올 이유를 찾지 못했다.**

> **판단을 청합니다.** 갈무리는 **운영 중이고 9/20에 2기가 씁니다.**
> ⓐ §8-5를 이 한 줄에 한해 풀어 주시면 `key={\`${cohortId}-${sessionNo}-${initialMode}\`}` 한 줄과
>    회귀 테스트로 닫습니다(리포트 패널과 같은 형태). ⓑ 아니면 실기기로 먼저 확인하시고
>    결과에 따라 지시해 주십시오. **확인 없이 고치지도, 고치지 않은 채 덮지도 않겠습니다.**
