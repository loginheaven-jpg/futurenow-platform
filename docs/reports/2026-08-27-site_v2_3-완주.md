## 1. T-2 — 이 회차에서 가장 무거웠다

발주는 T-1을 본체로 지목했으나 **값은 T-2에서 나왔다.** 결함 **둘**을 닫았고 둘 다
표시가 아니라 **기능·데이터**였다.

### 1.1 리포트 패널 — 데이터 오염

`useEffect` 의존성에 `responseId` 가 있어 *"다시 부른다"* 로 보였으나 가드가 막았다.
`triggered` 가 `useRef` 라 **재마운트만이 되돌린다.** 급소는 그 다음이었다 —

```ts
await saveCoachInterpretationAction(responseId, content);
//                                  ↑갱신된 B    ↑살아남은 A의 초안
```

**A의 해석이 B의 기록에 써진다.** 읽는 것이 아니라 쓰는 것이다.

### 1.2 갈무리 `?edit=1` — 고쳐 쓰기가 닫혀 있었다

지휘부가 낸 **세 번째 길**로 닫았다 — 실기기도 임의 수정도 아니고 **테스트로 먼저 증명**한다.

| 단언 | 수정 전 |
|---|---|
| `mode.ts` 가 제출분 `read` / `?edit=1` `edit` 로 가른다 | **PASS** |
| 서버가 `initialMode` 를 정확히 내려보낸다 | **PASS** |
| 읽기 카드와 편집 카드가 다른 인스턴스 | **FAIL — `key` 가 `null`** |
| key 가 모드를 포함한다 | **FAIL** |

**앞의 둘이 그린인 것이 진단을 좁혔다.** 판정도 prop도 옳았으므로 남은 곳이 하나뿐이었다.
그것이 없었으면 *"어딘가 안 된다"* 에서 멈춘다.

되돌림 검증에서 **key 는 두되 모드를 뺀 경우도 2 FAIL** 이 났다 — 그것이 없었으면
`cohortId-sessionNo` 조합이 통과하고 같은 회차 안에서는 여전히 안 열렸을 것이다.

### 1.3 §3.2 전수 확인 — 근거를 다시 재니 둘이 뒤집혔다

2차 §9.5의 *"여섯 위험 낮음"* 은 **넷에 대해 지금도 참**이고 **둘은 아니었다.**
`RosterDetail` 은 조건이 성립하나 내용은 prop 이라 정확하고 펼침 상태만 어긋난다 — **그대로 둔다.**

## 3. T-3 · T-4

### 3.1 `/api/version`

turbopack 전환으로 빌드 id 마커가 사라진 자리를 메운다. `force-static` 이라 값이 빌드 시점에 굳는다.

인증이 없으므로 env 하나가 새면 그대로 공개된다. 칸 수 상한(6)까지 걸어 조용히 느는 것을 막았다.

### 3.2 콘솔 사이드바 — 설계를 한 번 바꿨다

처음에 `exact` 플래그로 현재 항목을 갈랐더니 **리포트 상세·조원 세로 보기에서 아무것도 켜지지
않았다.** 사이드바의 일은 위치를 알려 주는 것인데 *"어디에도 없음"* 을 표시하면 그 일을 배반한다.
**가장 긴 일치가 이기게** 바꾸니 상위 문맥(기수 대시보드)이 남는다.

경로에서 항목을 계산하는 순수 함수라 **서버 왕복이 늘지 않는다.** 참여자에게는 항목이 0이다.

## 4. T-6 문서 정합 — 어긋난 것 넷

발주 §7 *"어긋난 것을 고치되, 고친 사실을 보고서에 적는다. 조용히 맞추지 않는다."*

### 4.1 `architecture.md` §4 — **여덟이 더 빠져 있었다**

2차에서 한 번 정정했는데 **그때도 빠졌다.**

| 누락분 | 주인 |
|---|---|
| `checkins` · `cohort_sessions` · `report_interpretations` · `user_consents` | 본 저장소 |
| `results` · `groups` · `group_members` | **SAIL — 불가침**(CLAUDE §4). public 스키마를 공유한다 |
| `deltanote_preregistrations` | **저장소 밖에서 적용됨** — `supabase/migrations` 에 CREATE 가 없다 |

> **왜 두 번 세도 빠졌나.** 2차에서 센 것은 *"1·2차가 만든 표"* 였다. 그보다 **먼저 있던 것**과
> **다른 주인의 것**은 세지 않았다. **"무엇을 세는가"를 정하지 않고 세면 두 번 세도 빠진다** —
> `feed_posts` 3행을 잔여로 읽은 것, `taken`/`remaining` 을 뒤집어 읽은 것과 같은 종류다.
> 이번에는 라이브 `information_schema` 전수와 대조했다: **문서 18 → 26 · 라이브 26 · 차이 0.**

**SAIL 셋을 표에 넣되 "불가침"을 함께 적었다.** 목록에 없으면 다음 사람이 "없는 표"로 보고
만들려 하거나 지우려 한다.

### 4.2 **불변식 목록이 없다** — 이번 회차 최대 발견

발주 §7은 *"불변식 목록 1~24 중 2차에서 바뀐 것"* 을 확인하라 했다. **그 목록이 없다.**

- 문서·발주서·코드 주석에서 **14개 번호가 참조**된다 — 4·6·7·8·9·10·11·13·15·17·18·19·20·24
- **그 번호를 정의하는 목록이 저장소 어디에도 없다**(`architecture.md` 9회 언급은 전부 참조,
  `CLAUDE.md` 0회, `design_system.md` 1회 참조)
- 가장 큰 번호가 24 이므로 1~24 가 어딘가에 있었거나 있어야 한다

**참조는 살아 있는데 정의가 없다.** 뜻은 문맥에서 읽히지만 그것은 복원이지 정의가 아니다.

**추정으로 목록을 만들지 않았다**(ADR-121 정신 — 추정치를 문서에 박지 않는다).
대신 `architecture.md` §12 용어집에 **"불변식" 항목을 신설해 이 사실과 참조 14개를 기록**했다.
지휘부가 원본을 갖고 있으면 그것을 싣고, 없으면 참조에서 초안을 만들어 승인받는다.

### 4.3 `value_assessments` 마이그레이션에 적용 버전 주석이 없었다

파일명 `20260826120000` · 적용 `20260826005825` — **첫 번째 불일치**인데 머리에 주석이 없었다.

주석만 더했다 — **SQL 은 한 줄도 건드리지 않았다.**

### 4.4 `docs/reports/README.md` 접미사 규약이 실제와 어긋났다

셋만 적어 두었으나 실측하니 **여덟 종이 더 있다**(`-완주`·`-초안`·`-실브라우저`·`-성능감사`
·`-목차보고`·`-메모검토`·`-리포트패널`·`-설계보고`). 설계 보고서는 **`-설계`와 `-설계보고` 두 형태**다.

**파일을 바꾸지 않고 규약을 실제에 맞췄다.** 이름을 되돌리면 커밋 메시지와 다른 보고서가

## 5. **§11 부채 — 토큰 체계 하나의 문제** (지휘부 지시대로 한자리에)

**흩어 두면 별개로 읽히고, 별개로 읽히면 영원히 안 고쳐진다.**
아래 셋은 다른 증상이지만 **한 뿌리**다 — 역할 토큰이 원천 팔레트에 1:1로 매여 있어
**역할이 요구하는 값과 팔레트가 가진 값이 어긋날 때 조정할 자리가 없다.**

| # | 부채 | 실측 | 증상 |
|---|---|---|---|
| ① | **면 위의 면이 없다** | `--color-surface-2` = `--color-bg` = `#ffffff` · 대비 **1.00** | 카드가 면이 아니라 테두리(1.39)로 선다. 면으로 상태를 가를 수단이 `--color-primary` 하나뿐 |
| ② | **`--color-border-strong` = `--color-text-muted`** | 같은 `#a8a29a` | 역할이 다른데 값이 같다. 둘을 나란히 두고 구분에 쓰면 안 된다 |
| ③ | **`--color-text-muted` 가 §10 기준 미달** | `--color-bg` 대비 **2.53** (기준 4.5 · 큰 글씨 3.0) | **91곳**에 쓰인다. 문서가 자기 규칙을 어긴다 |

**왜 한 사안인가.** ②와 ③은 **같은 토큰**(`--color-text-muted`)의 두 얼굴이고, ①과 ②·③은
**같은 원인**(3단 구조에서 역할 토큰이 팔레트 값을 그대로 물려받는다)에서 나온다.
`--gray-400` 을 조정하면 ②·③이 함께 움직이고, `--color-surface-2` 를 `--gray-50` 으로 옮기면
①이 풀리면서 `ui-card` 전 화면의 인상이 바뀐다. **하나를 건드리면 나머지가 따라온다.**

**이번 회차에 고치지 않은 이유**는 발주 §8-6이다 — 부품 사양을 쓰면서 화면을 갈아엎지 않는다.
지금은 §1.6 **금지 규칙**으로 함정만 막아 두었다.

> **금지는 다음 사람이 빠지는 것을 막지만, 이것이 의도된 설계인지 미결 부채인지는 말하지 않는다.**
> **지금 고치지 않는 것과 영원히 이대로 가는 것은 다르다.** 그래서 §11에 남겼다.

**제안**: 4차(사후진단) 전에 **토큰 체계 한 번**을 별도 발주로 연다. 사후진단은 새 화면이 여럿이고,
면 대비를 전제한 부품이 필요해지는 순간 ①이 곧바로 걸린다. 지금은 화면 수가 적어 가장 싸다.

## 8.3 사이드바 — **CSS 는 배포됐다. 화면은 보지 못했다**

콘솔은 인증 뒤라 **세션 없이는 사이드바를 볼 수 없다**(1·2차와 같은 제약, QA 계정 대기).
대신 **배포된 스타일시트에서 규칙 본문을 직접 읽었다** — `grep` 존재 확인이 아니라 실물이다.

```css
@media (min-width:1024px){
  .console-shell{grid-template-columns:250px 1fr;align-items:start;min-height:100vh;display:grid}
  .console-nav{flex-direction:column;align-items:stretch;min-height:100vh;position:sticky;top:0}
  …}
@media print{.console-nav{display:none}.console-shell{display:block}}
```

기본(모바일):
```css
.console-nav{gap:var(--space-1);padding:…;background:var(--navy-900);display:flex;overflow-x:auto}
```

| 층 | 결과 |
|---|---|
| 배포된 CSS 에 규칙이 실렸는가 | **PASS** — `lg` 이상 **250px 그리드** · 미만 **가로 스크롤 탭** · 인쇄 숨김 |
| 사양(§3.1)과 값이 같은가 | **PASS** — `1024px` · `250px` |
| **브라우저에서 실제로 그렇게 보이는가** | **미완 — 세션 필요** |
| 항목 계산·현재 표시 | 단위테스트 **9/9**(참여자 0 · 현재 정확히 하나 · 긴 일치 · 세그먼트 경계) |

**"CSS 가 있으니 됐다"로 갈음하지 않는다.** 2차에서 배운 것이 그것이다 —
마크업이 정상인데 화면이 답을 안 한 일이 있었다(§11). 규칙이 실렸다는 것과
**폭 1024px에서 실제로 250px 사이드바가 서고 그 아래에서 탭이 된다**는 것은 다른 층이다.
