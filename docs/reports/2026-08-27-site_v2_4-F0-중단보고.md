## 1. §1.2 대비 실측 — 지휘부 사전 계산이 정확했다

| 쌍 | 지휘부 | 실측 | 기준 | 판정 |
|---|---:|---:|---|---|
| `text-muted`(gray-600) / `bg` | 5.77 | **5.77** | ≥4.5 | **통과** |
| `text-on-accent` / `surface-inverse`(navy-700 끝) | 11.64 | **11.64** | ≥4.5 | **통과** |
| `accent-strong`(gold-300) / `surface-inverse`(navy-900 끝) | 7.86 | **7.86** | ≥3.0 | **통과** |

**그라디언트는 최악단으로 판정했다.** `surface-inverse` 가 navy-900 → navy-700 이므로
글자 대비가 가장 낮은 곳은 **navy-700 끝**이다.

| 최악단 실측 | 값 | 판정 |
|---|---:|---|
| `text-on-accent` / navy-700 | **11.64** | 통과 |
| **`accent-strong` / navy-700** | **5.75** | **통과** — 기준 3.0 을 넘고 **4.5도 넘는다** |

> `accent-strong` 는 *"굵은 대형 전용"* 으로 명시하라 했으나 **최악단에서도 5.75** 라
> 본문 기준(4.5)까지 만족한다. 제한을 그대로 두어도 무해하나, **근거는 3.0이 아니라 5.75** 다.

신규 `surface-2`(gray-100) 위 글자도 함께 쟀다 — `text` **14.07** · `text-muted` **4.89**. 통과.

## 2. 게이트 ② 미달 — **충돌이 3에서 4로 는다**

3차 §2.1 방식으로 **역할 토큰끼리** 값이 같은 쌍을 전수했다.

### 2.1 현재 — 3묶음

```
#ffffff  ← --color-bg , --color-surface-2 , --color-text-on-accent
#a8a29a  ← --color-border-strong , --color-text-muted        ← §11 부채 ②
#1a3a5c  ← --color-primary , --color-text-on-gold
```

### 2.2 발주 §1.2 적용 후 — **4묶음**

```
#ffffff  ← --color-bg , --color-text-on-accent               (축이 달라 무해)
#eeece8  ← --color-surface-2 , --color-surface-sunken        ← **신규 · 같은 축**
#6b655c  ← --color-text-secondary , --color-text-muted       ← **신규 · 같은 축**
#1a3a5c  ← --color-primary , --color-text-on-gold            (축이 달라 무해)
```

**해소 1(부채 ②), 신규 2.** 그리고 신규 둘은 **같은 축**이라 무해하지 않다.

> `bg`=`text-on-accent`, `primary`=`text-on-gold` 는 **면과 글자**라 축이 다르다 —
> 흰 배경과 "네이비 면 위 흰 글자"가 같은 값인 것은 당연하다. 3차 §1.6이 급소로 꼽지 않은 이유다.

## 3. 신규 충돌 둘 — 성격이 다르다

### 3.1 `surface-2` = `sunken` — **기능 결함이다**

`--color-surface-sunken` 의 실제 쓰임을 전수했다. **전부 "면 위에 놓이는 것"** 이다.

| 자리 | 무엇 |
|---|---|
| `ui.css:56` | **`.ui-progress`** — 진행바 트랙 |
| `ui.css:218` | **`.ui-textarea`** — 입력창 바탕 |
| `ui.css:434` | `.ui-disc__head:hover` |
| `visuals.tsx:185` | 리포트 **막대 트랙** |
| `MemberRow.tsx:149·168` | 카드 안 접힌 상세 |

`surface-2` 가 `gray-100` 이 되면 **카드와 입력창·트랙이 같은 색**이 된다.
`.ui-textarea` 는 `ui-card` 안에 자주 들어가므로 **입력창 경계가 테두리 하나만 남는다.**

### 3.2 `text-muted` = `text-secondary` — **회피할 수 없다**

흰 바탕에서 4.5를 넘는 회색을 찾았다.

| 후보 | 흰 바탕 | 판정 |
|---|---:|---|
| `#a8a29a`(현재 gray-400) | 2.53 | ✕ |
| `#8f8880` | 3.50 | ✕ |
| `#857f76` | 3.97 | ✕ |
| **`#7d7770`** | **4.43** | **✕ — 0.07 차이로 미달** |
| **`#6b655c`(gray-600)** | **5.77** | ○ |

**4.5를 넘으면서 `gray-600` 보다 눈에 띄게 옅은 회색이 없다.**
따라서 `text-muted` 는 **`text-secondary` 의 별칭이 될 수밖에 없다.**

> **그것이 나쁜 결과는 아니다.** WCAG 가 두 단계를 하나로 밀어붙인다면, 디자인 시스템은
> **두 단계가 있는 척하지 말고 하나임을 적어야 한다.** 3차 §11 부채 ③이 가리킨 것이 이것이다.

## 4. 대안 둘 — 값과 함께 (§7)

### 대안 ① — **별칭을 인정한다** (코드 0 · 팔레트 0)

| 토큰 | 값 | 비고 |
|---|---|---|
| `--color-surface-2` | **`--gray-50`**(#F7F6F4) | `--color-surface-1` 과 **같은 값 — 별칭으로 명시** |
| `--color-surface-sunken` | `--gray-100` **유지** | 카드 안 입력창·트랙이 카드와 갈린다 |
| `--color-text-muted` | `--gray-600` | `text-secondary` 와 **별칭으로 명시** |

| 실측 | 값 |
|---|---:|
| 카드(`surface-2`) / `bg` | **1.08** |
| `sunken` / 카드 | **1.09** |

게이트 ②를 **"구분에 쓰이는 같은 축 쌍 0"** 으로 읽으면 통과한다(별칭은 구분에 쓰지 않는다고 명시).
**대가**: 카드 면 대비가 발주안 1.18보다 약한 **1.08**.

### 대안 ② — **팔레트에 한 칸 넣는다** (코드 0 · 팔레트 +1) — **권장**

| 토큰 | 값 | 비고 |
|---|---|---|
| `--gray-150` | **`#E4E1DA`** | **신설** — gray-100 과 gray-200 사이 |
| `--color-surface-2` | `--gray-100`(#EEECE8) | **발주안 그대로** |
| `--color-surface-sunken` | **`--gray-150`** | 카드 안이 카드와 갈린다 |
| `--color-text-muted` | `--gray-600` | 별칭 불가피(§3.2) |

| 실측 | 값 |
|---|---:|
| 카드(`surface-2`) / `bg` | **1.18** — 발주 의도 그대로 |
| `sunken` / 카드 | **1.11** |
| `sunken` / `border`(gray-200) | 갈린다(같은 값 아님) |

**면 축 충돌 0.** 글자 축만 별칭으로 남고, 그것은 어느 안에서도 같다.
**대가**: §1.1이 확정한 X1 원천 팔레트에 값 하나가 는다 — **지휘부 승인 사항**.

## 5. §7 목록 보고 — 발주에 없던 것

### 5.1 `--color-surface-2` 가 **역할 둘을 겸하고 있다**

전수하니 카드 면만이 아니라 **입력창 배경**으로도 쓰인다.

| 입력창으로 쓰는 곳 | |
|---|---|
| `LoginForm` · `ContactForm` · `FeedClient` · `AuthGate` · `ProfileForm` · `AccountForm` · `ResetRequestForm` · `ResetConfirmForm` · `NewsComments` | 전부 `border: hair solid var(--color-border)` + `background: var(--color-surface-2)` |

**값을 바꾸면 두 역할이 함께 움직인다.** 지금은 둘 다 흰색이라 드러나지 않았다.
`.ui-textarea`(sunken)와 인라인 입력창(surface-2)이 **이미 다른 토큰**을 쓰고 있다는 뜻이기도 하다.

**고치지 않았다**(§5-2 기존 화면 수정 금지). `--color-surface-input` 분리는 **F-2·F-3 발주 사항**으로 올린다.

### 5.2 `text-muted` 사용처 — **91과 87이 둘 다 맞다**

| 셈법 | 결과 |
|---|---:|
| `color-text-muted` **문자열 전부**(정의 1 + 주석 포함) | **91** |
| `var(--color-text-muted)` **실제 사용** | **87** |

지휘부 91 = 문자열, 클코1 87 = 사용. **세는 단위가 달랐다** —
`taken`/`remaining` · `feed_posts` 3행 · §4 스키마 · 참조 12/14 에 이은 **다섯 번째**다.
재매핑 대상은 **87**이고, 방향은 **어두워지는 쪽만**이다(단일 토큰 재매핑이라 연해지는 곳 0).
