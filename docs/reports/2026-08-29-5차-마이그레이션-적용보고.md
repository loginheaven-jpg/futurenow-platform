## 0. 순서에 대한 해석 — 먼저 밝힌다

지시가 두 가지로 적혔다.

- 열거: *"적용 → 롤백 검증 → 통합테스트 → 보고"*
- 조건: *"**되돌리는 문을 먼저 확인하라**는 것도 그대로다. 2차 때 103 대 103 을 했던 방식"*

2차의 그 방식은 **적용 전** 롤백 검증이었다(*"발주 §10 마이그레이션 적용 전 롤백 검증은 유지한다"*).
그래서 **롤백 검증을 적용보다 앞에** 두었다 — 그래야 두 지시가 모두 지켜진다.
열거는 **단계 이름**으로 읽었고, 조건은 **시점**으로 읽었다. 다르게 읽으셨다면 알려 주십시오.

실제 순서: **① 롤백 검증(BEGIN…ROLLBACK) → ② 적용(COMMIT) → ③ 통합테스트 14 → ④ 보고**

## 1. **적용 직전에 잡은 것 — 이것이 이 회차의 요점이다**

적용 직전 실물 조회에서 이것이 나왔다.

```
feed_post_list 반환  : undefined      ← 그런 함수가 없다
```

**마이그레이션이 없는 함수를 고치고 있었다.** 저장소의 목록 RPC 는 `feed_list` 다
(`20260828100000_feed.sql:402` 정의 · `context.ts:1418` 이 부른다).

### 적용했다면 무슨 일이 났나

1. `DROP FUNCTION IF EXISTS public.feed_post_list(...)` → **조용히 지나간다**(없으니까)
2. `CREATE FUNCTION public.feed_post_list(...)` → **아무도 안 부르는 함수가 하나 생긴다**
3. 진짜 `feed_list` 는 **옛 모양(`my_reaction text`) 그대로 남는다**
4. 코드는 배열을 기대 → **순서 가드가 발화 → 피드가 닫힌다**

**즉 적용하고도 안 고쳐지고, 그 위에 배포하면 1기 졸업생의 피드가 닫혔다.**

### 그리고 검증이 이것을 놓쳤을 것이다

**롤백 검증도 통과했을 것이다.** 테스트가 **같은 가짜 이름**을 불렀기 때문이다 —
내가 만든 함수를 내가 부르니 초록이 나온다. 잡은 것은 테스트가 아니라 **실물 조회**였다.

> **측정 도구를 먼저 측정한다** 의 또 한 사례다. 이번에는 도구가 *다른 것을 찍은* 것이 아니라
> **자기가 만든 것을 찍었다.** 하네스 주석 계열의 다음 항으로 올릴지는 지휘부 판단에 맡긴다.

### 함께 나온 둘

- **시그니처 인자 순서**도 지어냈다 — `(cohort, mine, before, before_id, limit)` 로 적었으나
  정본은 `(cohort, before, before_id, limit, mine)` 다. 순서가 다르면 `DROP` 이 빗나가
  **같은 이름의 함수가 둘**이 된다.
- **롤백 검증의 픽스처도 지어냈다** — `users.membership_state` 라고 썼으나 실제는
  `public.memberships` 표다. 그 자리에 픽스처를 고쳐 두면 통합테스트와 **사본이 둘**이 되므로
  **걷어냈다.** 이 하네스는 **스키마 층만** 재고 동작은 통합테스트가 잰다.

셋 다 **정본에서 읽지 않고 추측한 것**이 원인이다. 지금은 이름·시그니처·본문을 전부 옮겨 왔다.

**회귀 잠금**을 걸었다 — 마이그레이션이 **DB 에 실재하는 함수**를 가리키는지, 그리고 없는 이름이
남아 있지 않은지 **양방향**으로 잰다.

## 2. ① 롤백 검증 — **적용 전** · 4/4

전 과정 `BEGIN … ROLLBACK`. **실데이터 한 행도 변하지 않았다.**

| # | 단언 | 결과 |
|---|---|---|
| 1 | 마이그레이션이 **실재하는 함수**를 가리킨다(`feed_list`·`feed_react`) · 없는 이름 0 | ✅ |
| 2 | **적용 전후 `feed_reactions` 행 수 동일** · PK 두 열 → 세 열 | ✅ |
| 3 | 권한이 원 파일과 같은 모양 — `anon` 실행 불가 · `authenticated` 실행 가능(두 함수) | ✅ |
| 4 | **되돌리는 문이 열린다** — ROLLBACK 뒤 PK 두 열 복귀 · 행 수 동일 · `feed_react` 반환 `text` 복귀 | ✅ |

4번이 이 절의 핵심이다. 판정을 **트랜잭션 밖에서** 다시 읽는다 — 되돌아갔는지는 밖에서 봐야 안다.

검증 뒤 실물 상태를 다시 확인해 **무변경**을 확인했다:
`행 수 1 · PK post_id,user_id · feed_list 반환 … my_reaction text)`

## 3. ② 적용 — COMMIT

**롤백 검증을 통과한 파일 그대로** 적용하고 원장에 **파일명 버전**으로 기록했다
(2차 선례 · MCP 가 적용 시각으로 자체 채번하는 경로를 쓰지 않는다 · ADR-122 ⑨).

```
적용 전 : {"rows":1,"pk":"post_id,user_id","react":"text"}
COMMIT 완료
적용 후 : {"rows":1,"pk":"post_id,user_id,emoji","react":"text[]"}
feed_list 반환 : … reactions jsonb, my_reactions text[])
원장 기록 : { version: '20260829090000', name: 'feed_reactions_multi' }

행 수 동일 : ✅ 1 → 1
```

**지휘부 요구 항목 — 적용 전후 `feed_reactions` 행 수 동일: `1 → 1` 실측 확인.**
*PK 를 넓히는 변경이라 기존 행이 전부 유효하다* 는 것은 주장이었고, 여기서 **실측이 됐다**.

원장 최신: `20260829090000` `20260828100000` `20260826234713` …

> **롤백 검증 하네스는 이제 스스로 건너뛴다.** 단언이 *적용 전 PK 는 두 열이다* 이므로
> 적용 뒤에는 통과할 수 없다 — **결함이 아니라 그 하네스의 성격**이다.
> 영구 실패로 두면 다음 사람이 *원래 빨간 것* 으로 배우고 그 순간 잠금이 죽으므로,
> **원장을 보고 이유를 찍으며 건너뛴다**(`[migration 20260829090000] 이미 적용됨 — …`).
> 건너뛴 것과 통과한 것은 다른 사실이므로 조용히 넘기지 않는다.

## 5. 오염 확인

```
{"feed_reactions":1,"feed_posts":4,"checkins":24,"real_enrollments":28,"test_rows":0}
```

- **`test_rows: 0`** — 통합테스트 픽스처(`instrument_id='__ftest__'`)가 **한 행도 남지 않았다.**
  전 과정 `BEGIN … ROLLBACK` 규약이 지켜졌다는 뜻이다.
- **`feed_reactions: 1`** — 롤백 검증·적용·통합테스트를 전부 지난 뒤에도 **그대로**다.
- 나머지 셋은 **기준값을 같은 질의로 잰 적이 없어 비교하지 않는다.** 값만 기록한다 —
  다른 질의로 잰 옛 숫자와 나란히 놓으면 그것이 지휘부와 숫자가 갈리는 여섯째가 된다(§11).

## 6. `architecture.md` 정합

**문서 델타 0 + 사유.** ADR-135 가 이 마이그레이션의 결정을 이미 담고 있고, 이번 회차는
**그 결정의 적용**이지 새 결정이 아니다. 함수명 정정은 **결함 수정**이라 새 ADR 을 만들지 않았다
(ADR-135 본문의 사양은 그대로 유효하다 — 바뀐 것은 그 사양을 어느 함수에 적용하느냐였다).

**다만 판단이 필요하면 지적해 주십시오** — 적용 직전에 잡은 결함이 ADR-135 본문에
*"대상 함수는 `feed_list` 다"* 로 한 줄 들어갈 값이 있다고 보시면 그렇게 하겠습니다.

## 8. 막힌 지점 · 다음

- **병합·배포는 착수하지 않았다.** 승인 범위가 적용까지이고, 다시 승인을 받는다.
- 병합·배포가 나면 **실기기 절차서 넷**이 유효해진다
  (`docs/reports/2026-08-29-5차-실기기-절차서-최박사.md` — 머리에 유효 조건 셋을 박아 두었다).
  그 조건 중 **첫째(마이그레이션 적용)가 이번에 충족**됐다.
- **지금 상태의 성격을 밝힌다 — 실측했다.**

  운영 배포본은 아직 **4차 코드**다(`/api/version` → `a5a49af` · `ref=main` · `builtAt 2026-08-28`).
  그 코드는 `my_reaction`(단수)을 읽는데 DB 는 이제 `my_reactions`(배열)를 준다.
  **DB 는 안전하다** — 쓰기 경로(`feed_react`)는 정상 동작하고 반응이 정확히 저장된다.
  영향은 **표시 층에 한정**되며, 과장하지 않고 셋으로 적는다:

  | 무엇 | 지금 | 심각도 |
  |---|---|---|
  | 게시·댓글·사진 | **정상** | — |
  | 반응 **집계 수**(`👏 3`) | **정상** — `reactions` 열은 바뀌지 않았다 | — |
  | **내 반응 강조**(테두리·배경) | **사라진다** — `my_reaction` 열이 없어 `null` 로 읽힌다 | 낮음(표시만) |
  | 누른 **직후의 숫자** | 틀릴 수 있다 — 옛 코드가 배열을 키로 쓴다. **새로고침하면 DB 값으로 교정**된다 | 낮음(일시적) |

  **되돌릴 필요는 없다고 본다** — 손실이 표시뿐이고 새로고침으로 교정되며, 되돌리면
  *되돌리기 성격이 시간에 따라 나빠진다*(2기 시작 전에 하라는) 지휘부 논거를 거스른다.
  다만 **창을 길게 두지 않는 편이 낫다**는 사실로 보고한다. 판단은 지휘부 몫이다.
