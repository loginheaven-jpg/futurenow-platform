## 4. **창이 닫혔다** — 배포 후 실측

지휘부가 *"DB 는 새 모양인데 운영은 4차 코드라 1기 졸업생이 피드를 열면 자기 반응 강조가 안 보인다.
배포가 그 창을 닫는다"* 고 했다. 닫혔는지를 **운영에서 직접** 쟀다.

```
/api/version        : c3f9790 · ref=main · env=production      ← 새 코드
로그인 착지          : /home
피드 순서 가드 발화   : ✅ 없음 (피드가 정상으로 열린다)
반응 버튼            : 6개 · aria-pressed 보유 → **복수 토글 UI**
현관 헤더            : "퓨처나우 FUTURE NOW 내 홈"  → ✅ 세션을 본다
```

- **가드가 발화하지 않았다** = 코드와 DB 의 모양이 맞았다는 실측이다. 가드는 어긋날 때만 운다.
- 현관 헤더가 **`내 홈`** 으로 나온다(소건 1-바) — 다만 **깜빡임 여부는 여기서 잴 수 없다.**
  이 브라우저는 빠르다. **그것이 2항이 실기기로 가는 이유**다.

## 5. 오염 0 — 배포 후 재측정 (지휘부 요구)

```
{"feed_reactions":1,"feed_posts":4,"checkins":24,"real_enrollments":28,"test_rows":0}

feed_list        오버로드 1
feed_react       오버로드 1
feed_post_list   오버로드 0      ← 가짜 이름 잔재 0

feed_reactions PK : post_id,user_id,emoji
feed_react 반환    : text[]
```

| 지표 | 적용 전 | 적용 후 | 배포 후 | 판정 |
|---|---|---|---|---|
| `feed_reactions` | 1 | 1 | **1** | **변화 0** |
| 통합테스트 픽스처(`__ftest__`) | — | 0 | **0** | 잔여 0 |
| `feed_post_list` 오버로드 | 0 | 0 | **0** | 유령 함수 0 |

`feed_posts`·`checkins`·`real_enrollments` 는 **같은 질의로 잰 기준값이 없어 비교하지 않는다.**
값만 기록한다 — 다른 질의로 잰 옛 숫자와 나란히 놓으면 그것이 숫자가 갈리는 여섯째가 된다(§11).

## 7. 다음 — **실기기 절차서 넷이 이제 유효하다**

`docs/reports/2026-08-29-5차-실기기-절차서-최박사.md` — 머리의 **유효 조건 셋이 모두 충족**되어
조건문을 충족 사실로 바꿨다(4차 선례와 같은 방식).

| 항 | 무엇 |
|---|---|
| 1 | **뒤로가기 연타** — 어느 지점에서도 로그인 화면이 나오지 않는지 |
| 2 | **로고 클릭** — 헤더가 `내 홈` 인지 · **그리고 잠깐 `로그인` 으로 보였다가 바뀌는 순간이 있는지** |
| 3 | **앱 닫았다 열기** — 다시 로그인하지 않아도 되는지 |
| 4 | **피드에서 박수와 기도를 함께** — 둘 다 켜진 채 남는지 |

**2항의 추가분이 이 회차의 요점이다**(지휘부 지시). 한 프레임 깜빡임은 **빠른 기기에서는 보이지 않고**,
클코1 의 브라우저도 빠르다. **느린 기기에서 한 번이라도 `로그인` 이 먼저 보이면 4차와 같은 오해가
그대로 재발한다.** 회신란에 `보였다 / 못 봤다` 한 줄을 따로 두었다 — **못 봤다도 결과**다.
