## 3. ★ 원인 — 파생이 아니라 관측으로 정했다 (지시 3)

**껍데기가 갈래마다 다른 트리를 돌려줬다.** React 는 형제 위치로 화해하므로
모양이 바뀌면 `{children}` 이 **언마운트되고 다시 마운트된다.**
그리고 `useSetChrome` 은 **언마운트 때 크롬을 지운다.** 그래서 되먹임이 돌았다:

```
크롬 설정  →  껍데기가 갈래를 바꿈  →  본문 재마운트
     ↑                                      │
     └──  갈래가 되돌아감  ←  언마운트 정리가 크롬을 지움
```

**관측(MutationObserver · 5초):** `<main>` **175회 교체** · `<header>` 88회 생김/87회 사라짐.
→ *「재호출이 많다」* 가 아니라 **「본문이 반복해서 다시 마운트된다」** 가 실측된 사실이고,
그래서 `resolving` 단계가 매번 처음부터 다시 돌아 **화면이 영원히 「불러오는 중」이었다.**

**ADR-162 근처가 맞았다** — 통로(`useSetChrome`)가 관련되어 있다. 다만 원인은 «SSR 에 헤더가 없다» 가
아니라 **«껍데기가 크롬에 따라 트리 모양을 바꾼다»** 였다. **후보를 답으로 쓰지 않았다.**

## 4. 고침 — 증상이 아니라 원인을 막았다

**재호출 방어를 덧대지 않았다.** 갈래를 **슬롯**으로 바꿔 `{children}` 의 자리를 **언제나 같게** 했다:

```tsx
const header = override ? <AppHeader …/> : chrome?.kind === 'bar' ? <AppHeader …/>
             : chrome?.kind === 'none' ? null : <PublicGnb …/>;
const footer = (override || bar || none) ? null : <SiteFooter …/>;
return (<>{header}<main>{children}</main>{footer}</>);
```

`null` 도 형제 자리를 차지하므로 위치가 흔들리지 않는다.

- **`PublicShell`** — 고쳤다(고리가 실제로 돌던 자리).
- **`MemberShell`** — **같은 구조 위험이 있었다**(본문 슬롯 3개). 통로를 쓰는 회원 화면이 아직 없어
  돌지 않았을 뿐이다. ***돌지 않았다*와 *돌 수 없다*는 다르므로** 함께 슬롯 하나로 고쳤다.
- **`ConsoleShell`** — 갈래가 **역할**로만 갈리고 역할은 한 트리 안에서 바뀌지 않는다.
  비상 상황에 콘솔 레이아웃을 흔들지 않기로 하고, **그 조건을 잠갔다**
  (조기 반환이 `override`·`chrome` 을 보면 레드).

**`useSetChrome` 의 언마운트 정리는 그대로 두었다.** 그것을 지우면 다음 화면이 옛 제목을 쓴다 —
**고리의 원인은 정리가 아니라 모양이 갈린 것**이었다. 잠금이 그 정리의 존재도 함께 잰다.

## 9. 남기는 사실 둘

1. **U-4 는 «예외 0 · 검증 전항 통과» 였는데도 이것을 놓쳤다.** 잠금 전부가 **정적**이었고
   재마운트는 **런타임 행동**이라 아무도 재지 않았다. 4폭 캡처도 `/join` 첫 단계(코드 입력)만 찍어
   **`?code=` 딥링크 경로를 한 번도 열지 않았다.** → 캡처 목록에 **딥링크 한 줄을 더할 것**을 제안한다.
2. **`postdeploy` 의 `/join?code=` 항목은 이 사고를 못 잡았다.** 200 과 크기만 보기 때문이다
   (그 줄에 *「하이드레이션 후 — 실브라우저로 눈 확인 필요」* 라고 적혀 있었고, 그 말대로였다).
   → **POST 횟수 상한**을 그 항목에 넣을 것을 제안한다(예: 5초에 3회 넘으면 실패).
