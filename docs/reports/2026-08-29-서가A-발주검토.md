## 1. ★ 반박 ① — §3 의 3단으로는 §6 의 「본인 회기 자료」를 표현할 수 없다

§3 은 등급을 **셋**으로 못 박았다: `public`(전원) · `forum`(포럼회원 이상) · `coach`(인도자·운영자).
§6 은 열람 조건을 **넷**으로 적었다: 본인 것 · **본인 회기 자료** · 전체 공개 · (보류면 닫힘).

**「회기 자료」는 등급이 아니라 소속이다.** 3단 어디에도 «어느 기수의 자료인가» 를 담을 칸이 없다.
`forum` 으로 두면 회기가 끝난 참여자(포럼회원이 아닌 사람)가 못 본다 — **최박사 확정 ③ 과 정면으로 어긋난다.**

**보완안(권고)**: **축을 둘로 나눈다.**

```
tier      public | forum | coach        ← 등급(누구까지)
cohort_id uuid null                      ← 소속(어느 기수의 것인가 · null 이면 기수 무관)
```

열람 = `public` ∨ (`forum` ∧ 이용등급 full) ∨ (`coach` ∧ 인도자·운영자) ∨ **내가 등록한 기수의 것** ∨ 내가 올린 것

**이러면 확정 ③ 이 저절로 성립한다** — 등록 이력은 `enrollments` 에 남고 `cohorts.status` 와 무관하므로
회기가 끝나도 그 기수 자료는 계속 열린다. **「기간 제한 없음」을 코드로 지키는 것이 아니라 구조가 지킨다.**

## 2. ★ 반박 ② — §6 의 「보류가 전체 공개 자료도 닫는다」는 **로그아웃으로 우회된다**

§3 은 `public` 을 «전원» 으로 정의했다 — **익명 방문자 포함**이다.
그러면 보류된 사람은 **로그아웃만 하면 같은 자료를 본다.** 그 차단은 **막지 못하고 표시만 바꾼다.**

5-2 에서 세운 규율이 여기 그대로 걸린다 — **막지 못하는 것을 막았다고 적지 않는다.**
(그때 51개 쓰기 정책이 `member_state` 를 안 본다는 사실을 «도달 불가» 로 정확히 적었던 그 자리다.)

**최박사 확정 ④ 「회원자격 보류면 닫힌다」의 뜻을 가려야 한다.**

| 해석 | 결과 | 우회 |
|---|---|---|
| ㉮ **회원 전용 자료가 닫힌다**(권고) | `forum`·`coach`·회기·본인 것이 닫히고 `public` 은 열림 | 없음 — 약속한 것을 전부 지킨다 |
| ㉯ 서가 전체가 닫힌다 | `public` 까지 닫음 | **로그아웃하면 열림** · §5(목록은 전원에게)와도 어긋남 |

**㉮ 를 권고한다.** ㉯ 를 택하시면 그 한계를 화면과 문서에 함께 적어야 한다.

## 3. ★ 반박 ③(실측) — §7 은 발주서 자신의 멈춤 조건에 걸린다

> §7: *"참여를 나타내는 값을 실측으로 고르고 근거를 적어라. **후보가 여럿이고 여는 사람 수가 크게 갈리면 멈추고 보고하라.**"*

**갈린다. 그래서 멈춘다.**

| 후보 | 여는 사람 | 쓸모 |
|---|---|---|
| ① 등록(`enrollments` · `kind='seminar'`) | **19명** | 발주가 «등록이 아니다» 라고 배제한 것 |
| ② 갈무리 **행이 있다**(`checkins`) | **12명** | 지휘부 실측의 그 값(19−12=**7명** 미작성) |
| ③ 갈무리를 **제출했다**(`submitted_at`) | **9명** | 가장 좁다 |
| ④ 진단 응답(`responses`) | **19명** | **①과 같다 — 구별력 0** |
| ⑤ 피드 글 | **0명** | 아직 아무도 안 썼다 |

**한 가지 정정**: 등록은 **21행이지만 사람은 19명**이다(두 사람이 두 기수에 있다).
지휘부의 «21행 중 7명» 은 **19−12=7** 과 같은 값이다 — 행이 아니라 사람으로 세면 그렇다.

**실질 선택은 12(행이 있다) vs 9(제출했다)이고 셋이 빠진다.**
제 권고는 **②(행이 있다)** 다 — *«열어 봤다»* 가 참여의 최소 표식이고,
③ 은 «마감 전에 제출을 못 한 사람» 을 서가에서까지 내보낸다. 다만 **판단은 지휘부·최박사 몫이다.**

## 4. ★ 반박 ④ — §4·§9 가 함께 열어 놓은 구멍: **파일을 무엇이 지키는가**

실측: `library_can_read` 를 부르는 곳은 **정책 하나뿐**이다.

```
storage.objects / library_objects_select / SELECT to anon, authenticated
  using ((bucket_id='library') AND library_can_read(name))
```

**§9 대로 그 함수를 지우면 이 정책도 함께 죽는다.** 그러면 **파일 자체를 지키는 것이 없다.**
§4 는 «목록 RPC 가 주소를 안 낸다» 만 말하고, **주소를 어떻게 내주는지**는 정하지 않았다.

| 안 | 성질 | 값 |
|---|---|---|
| ⑴ **서명 URL**(관문 통과 뒤 발급) | 발급 뒤 **TTL 동안 공유 가능** · 보류돼도 그 URL 은 산다 | 5-2 의 «액세스 토큰 잔여 수명» 과 **같은 성질**. TTL 을 짧게(60초) 두고 **볼 때마다 발급** |
| ⑵ **프록시 라우트**(서버가 읽어 흘린다) | 매 요청이 관문을 지난다 — **잔여 창 0** | 대역폭이 앱을 지난다 |

**뼈대 문장 «주소는 관문을 지난 사람에게만 간다» 는 ⑵ 처럼도 읽힌다.**
제 권고는 **⑴ + 짧은 TTL**(이미 쓰는 방식이고 단순하다). **결정 주십시오.**

## 5. 보완 수용 — 여섯

### ㉠ 익명에게 목록이 **터진다**(실측)

```
select public.member_tool_access(null);
→ ERROR 22023: no subject   (member_state 7행의 RAISE)
```

§5 는 목록을 **전원에게** 보인다고 했고 §3 은 판정을 `member_tool_access` 로 하라고 했다.
목록 RPC 가 그대로 부르면 **익명 방문자는 목록 대신 오류를 받는다.**
→ **`auth.uid() IS NULL` 을 먼저 갈라 `public` 만 내주는 길**을 조항으로 둔다.

### ㉡ `member_tool_access` 는 **`auth.uid()` 로만** 부른다

`member_state` 는 남의 uid 로 부르면 42501 이다(자기 자신이거나 운영자여야 한다).
정책이 `member_tool_access(created_by)` 같은 형태를 쓰면 **터진다.** 제약으로 명시한다.

*(부수 실측 — 위험 아님을 확인했다: `auth.uid()` 가 NULL 이면 그 권한 검사가 3치 논리로 **건너뛰어진다**.
그러나 `anon` 에게는 `member_state` **EXECUTE 권한이 없어**(ACL 실측) 밖에서 부를 길이 없다.
NULL 로 부를 수 있는 것은 `postgres`·`service_role` 뿐이다. **지금은 새지 않는다.**
다만 **이 함수를 anon 에게 여는 변경이 오면 그 순간 샌다** — 서가가 그 변경을 하지 않도록 여기 적어 둔다.)*

### ㉢ B 용 표는 **RLS 켜고 정책 0**(전면 거부)으로 만든다

«지금 만들되 안 쓴다» 에는 동의한다(스키마가 두 번 흔들리는 비용이 더 크다).
다만 **안 쓰는 표에 정책을 미리 지으면 부르는 사람이 없어 잠금이 아무것도 증명하지 못한다**(조항 ⑪).
**RLS 활성 + 정책 0 이면 아무에게도 열리지 않는다.** B 에서 정책을 지을 때 비로소 물릴 수 있다.

### ㉣ §12 개명은 **네 곳이 아니다** — 운영 코드 **16 파일**

```
GNB(SiteGnb) · 푸터/공개 시트(publicNav) · 회원 시트(memberSheet) · 콘솔 시트(consoleNav) ·
콘솔 껍데기(ConsoleShell) · 화면(library/page) · 홈 · 피드 · 차수 홈 · pending · 픽스처 둘 ·
**contracts/core-context.ts · contracts/domain.ts · core/context.ts**
```

**계약과 코어에도 그 낱말이 있다**(불변식 3 — 계약 변경은 승인 사항).
값인지 주석인지 가려 목록으로 올리겠다. 「처음으로」가 하나가 아니라 일곱이었던 것과 같은 형식이다.

**그리고 URL `/library` 를 바꾸는지 발주서가 말하지 않았다.** **유지를 권고한다** —
ADR-155 의 교훈(주소는 얼어야 하는 값)이고, 바꾸면 옛 링크가 죽는다.

### ㉤ §11 통로 — **ADR-162 의 성질이 따라온다**

`/library/[id]` 제목을 통로로 세우면 **그 제목도 SSR 원문에 없다**(하이드레이션 뒤에 선다).
`/join` 과 같은 창이고, **미리 적어 둔다**(새 결함으로 오해되지 않게).

### ㉥ §9 ㉢ 은 **이미 답이 나왔다** — 다만 이유가 다르다

예행에서 시그니처·본문·**권한**·`SECURITY DEFINER`·`search_path`·소유자가 **여섯 다 복구**됐다(변이 성립도 확인).
그러나 **승계된 것이 아니라 `postgres` 의 기본 권한** 덕이다(`ALTER DEFAULT PRIVILEGES`).
**적용 역할이 다르면 달라지므로 마이그레이션에 `GRANT` 를 명시로 적는다.**

## 6. 사실 정정 둘

- **`library_items` 에 `created_by` 가 없다**(현재 7컬럼: id·title·description·storage_path·tier·created_at·updated_at).
  §6 의 `created_by = auth.uid()` 는 **개조로 새로 생기는 칸**이다. **0행이라 백필 문제는 없다.**
- **§9 의 「기존 자료 대조」는 대조할 값이 없다** — `library_items` **0행** · `storage.objects(library)` **0개**.
  형식은 준비해 두었다(전후 `select *` 를 `full outer join` — 행 수 비교는 쓰지 않는다).
- **§3 의 진단은 맞다**: 현재 `library_can_read` 는 `v_tier='member'` 면 **로그인 전원**에게 참을 낸다(라이브 정의 확인).

## 7. 결정 요청 — 셋

| # | 무엇 | 권고 |
|---|---|---|
| 1 | **「회기 자료」를 어떻게 담는가** (§3 vs §6) | 축을 둘로: `tier` + `cohort_id` |
| 2 | **보류가 `public` 자료도 닫는가** (§6 vs §3) | ㉮ 회원 전용만 닫는다(우회 불가능한 것만 약속) |
| 3 | **파일 주소를 무엇이 지키는가** (§4 vs §9) | 서명 URL + 짧은 TTL + 볼 때마다 발급 |

**그리고 §7 의 참여 신호**(12 vs 9)는 발주서 자신의 지시대로 **멈추고 올린다.**

**셋이 정해지면 나머지는 발주대로 짤 수 있다.** 표 여섯·계약·화면·잠금·롤백 문·예행까지
아침 결재만 받으면 바로 적용되도록 지어 두겠다. **적용은 하지 않는다.**
