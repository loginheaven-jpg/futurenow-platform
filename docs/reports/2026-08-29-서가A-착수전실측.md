### ③ 라이브 실측 — **초안 전제가 맞다(0행 · 0개)**

```sql
select (select count(*) from public.library_items)                        as library_items_rows,
       (select count(*) from storage.objects where bucket_id='library')   as storage_library_objects,
       (select count(*) from storage.buckets where id='library')          as bucket_exists,
       (select count(*) from pg_proc p join pg_namespace n on n.oid=p.pronamespace
          where n.nspname='public' and p.proname='library_can_read')      as fn_count;
```

| library_items | storage.objects(library) | 버킷 | `library_can_read` |
|---|---|---|---|
| **0행** | **0개** | 있다(1) | 있다(1) |

**「이전이 아니라 재설계」라는 발주의 성격이 성립한다.** 옮길 자료가 없다.
다만 **버킷과 함수는 실재하므로** 「없는 것을 만든다」가 아니라 **「빈 것을 갈아 끼운다」**이다.

## Ⅱ. 마이그레이션 안전 준비 — 넷 다 확인

### 1) 옛 정의를 **라이브에서 그대로** 받아 두었다

```
signature      : library_can_read(text)
identity_args  : p_path text
result         : boolean
security       : SECURITY DEFINER · STABLE · SET search_path TO 'public'
owner          : postgres
acl            : {=X/postgres,postgres=X/postgres,anon=X/postgres,authenticated=X/postgres,service_role=X/postgres}
```

```sql
CREATE OR REPLACE FUNCTION public.library_can_read(p_path text)
 RETURNS boolean LANGUAGE plpgsql STABLE SECURITY DEFINER SET search_path TO 'public'
AS $function$
DECLARE v_tier text;
BEGIN
  SELECT tier INTO v_tier FROM public.library_items WHERE storage_path = p_path;
  IF v_tier IS NULL THEN RETURN false; END IF;
  IF v_tier = 'public' THEN RETURN true; END IF;
  IF auth.uid() IS NULL THEN RETURN false; END IF;
  IF v_tier = 'member' THEN RETURN true; END IF;
  RETURN public.user_role(auth.uid()) IN ('coach','admin');
END;
$function$;
```

**시그니처는 `pg_get_function_identity_arguments` 로 받았다**(지시대로) — `DROP FUNCTION` 이 물어야 할 것이 그것이다.

### 2) 예행 — **시그니처·본문·권한·보안·설정·소유자가 원문대로 복구된다**

`BEGIN` → 정책 DROP → 함수 DROP → 원문 CREATE → 정책 CREATE → 대조 → **`ROLLBACK`**.

| sig | def | acl | secdef | config | owner |
|---|---|---|---|---|---|
| 같음 | 같음 | **같음** | 같음 | 같음 | 같음 |

**★ 변이가 성립했는지 먼저 확인했다**(계열 ⑧). 지워지지 않았는데 「같다」를 얻으면 아무것도 증명되지 않는다:

```
drop 뒤 — 함수 0 · 정책 0 · library_can_read 를 부르는 정책 0
```

**★ 권한이 왜 돌아왔는지도 확인했다.** 5-2 선례는 *DROP+CREATE 는 권한을 승계하지 않는다* 였다.
여기서 같았던 이유는 **승계가 아니라 기본 권한**이다 —

```
current_user = postgres
public 스키마 함수 기본 권한:
  postgres      → {postgres=X, anon=X, authenticated=X, service_role=X}
  supabase_admin → {postgres=X, anon=X, authenticated=X, service_role=X}
```

즉 **`postgres`(또는 `supabase_admin`)로 만들 때만** 자동으로 같아진다.
**그래서 마이그레이션에 `GRANT` 를 명시로 적는다** — 적용 역할이 달라져도 결과가 같도록.
*운이 좋아 같았던 것을 설계로 바꾼다.*

### 3) 부르는 곳 전수 — **정책 하나**

```
storage.objects / library_objects_select / SELECT / to anon, authenticated
  using ((bucket_id = 'library') AND library_can_read(name))
```

정책·다른 함수 본문·뷰를 전수로 훑었고 **그 하나 말고는 없다.**
**함수를 지우면 이 정책이 함께 죽는다** — `CASCADE` 를 쓰지 않고 **정책을 먼저 명시로** 지운다.
`CASCADE` 는 정책을 조용히 데려가고, 조용히 사라진 것은 아무도 모른다.

### 4) 지우려는 이름이 **실물로 있는지** 먼저 조회했다 (계열 ⑦)

`pg_proc` 조회로 **1건** 확인. 5차 마이그레이션의 `feed_post_list`(저장소에만 있던 이름) 사고를 여기서 되풀이하지 않는다.

## Ⅲ. 대조는 행 수가 아니라 **값**으로

`library_items` 가 **0행**이라 지금은 대조할 값이 없다.
그래도 형식을 먼저 정해 둔다 — **개조 전후로 모든 컬럼 값을 대조한다**:

```sql
-- 전: create temp table _before as select * from public.library_items order by id;
-- 후: select * from public.library_items order by id;
--     full outer join 으로 «양쪽에만 있는 행» 과 «값이 다른 행» 을 둘 다 낸다.
```

**행 수 비교는 쓰지 않는다** — 행 수는 같은데 값이 바뀐 경우를 못 잡는다.

## 판단 필요 · 멈춘 자리

**멈춘 것은 없다.** Ⅱ 의 넷이 전부 확인됐으므로 *「되돌아오는 것을 확인하지 못했다」* 에 해당하지 않는다.
다만 **적용은 발주서 전문을 받고** 한다.

**적용 시 지킬 것 셋**(위 실측에서 나온 것):
1. **정책 먼저, 함수 나중**(`CASCADE` 금지).
2. **`GRANT` 를 명시로** 적는다(기본 권한에 기대지 않는다).
3. 새 함수가 서면 **정책을 다시 만들고**, 그 자리에서 `pg_get_functiondef` · `proacl` · `pg_policies` 를 **다시 조회해** 확인한다.
