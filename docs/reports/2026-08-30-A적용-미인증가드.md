## 1. 롤백 문을 먼저 열었다 — **예행까지 했다**

되돌리는 문은 **라이브 `pg_policy` 에서 그대로 옮겼다.** 지어내지 않았다.

트랜잭션 안에서 **적용 → 되돌리기 → 원문 대조 → 전부 ROLLBACK**:

```
[적용 전 정책] roles=["-"]
[롤백 예행] 적용됨   roles=["authenticated"]
            되돌림   roles=["-"] · 원문 일치 O      ← 표현식·역할까지 같다
            예행 종료 라이브 무변경 확인 O
```

**A 와 B 는 따로 되돌릴 수 있다.** A 는 옛 정책 복원(코드 무관), B 는 옛 함수 복원
(새 코드가 `DEFAULT` 로 계속 동작). 한 덩이로 묶지 않았다.

장부 버전이 **파일명과 같다**(ADR-122 ⑨ 의 자체 채번이 일어나지 않았다).

## 3. 검증 셋 — **전항 통과**

**⑴ `anon` 은 오류가 아니라 빈 결과**

```
auth.uid()=NULL · 행 0 · 오류 없음 O
```

**깨끗한 연결에서 쟀다.** 같은 트랜잭션에 `set_config('request.jwt.claims', …)` 가 남아 있으면
`auth.uid()` 가 NULL 이 아니라 **미인증을 재는 것이 아니게 된다** — 실제로 한 번 그렇게 잘못 쟀다.
그래서 **`auth.uid()` 가 정말 NULL 인지 먼저 단언**하고 그 다음에 행 수를 본다.

**⑵ `EXPLAIN` 에 `InitPlan 1` + `loops=1`**

```
InitPlan 1 O · loops=1 O
| Seq Scan on public.cohorts  (actual rows=1 loops=1)
| Filter: (is_admin(…) OR (((InitPlan 1).col1 <> 'expired') AND (…)))
| InitPlan 1
|   Output: member_state(…)
```

`member_state` 가 `Filter` 안이 아니라 **`InitPlan` 으로 올라갔다.** 이것이 정정의 요점이다.
**운영자가 아니면서 보이는 행이 있는 신원**으로 쟀다 — 운영자는 첫 `OR` 로 빠져나가 뒤가 평가되지 않는다.

**⑶ 인증 사용자 판정 전후 동일**

```
25명 중 불일치 0명 O · 합계 전 37 · 후 37
```

전 신원을 한 명씩 **그 사람의 눈으로** 세어 적용 전후를 대조했다. 전부 SELECT 이고
**어떤 계정·기수도 바꾸지 않았다.** 신원은 기록하지 않는다.

## 4. ⑴ 을 상주로 올렸고, **재는 것이 실재하는지 확인했다**

지시대로 상주 테스트 둘을 뒀다(`membership.integration.test.ts`) —
빈 결과 확인 + 정책이 `TO authenticated` 로 서 있는지.

**상주 테스트가 초록인 것은 그 자체로 증거가 아니다.** 그래서 변이를 넣었다 —
트랜잭션 안에서 `TO` 를 뺀 옛 정책으로 되돌린다.

```
변이 성립 확인 — roles=["-"] (TO 가 빠졌다)     ← **먼저 변이가 성립했는지 본다**(계열 ⑧)
  O anon 이 터진다 — 42501 permission denied for function member_state
라이브 원상 확인 — roles=["authenticated"]
```

**변이가 대상에 닿았고, 닿자 터졌다.** 상주 테스트의 *0행·오류 없음* 은 실재하는 조건을 잰다.

## 5. `is_admin` 자리 넷 — **코드 델타 0**

최박사 원문 *"이용 보류 는 누구에게도 걸수 있다."* 로 **대상은 확정**됐다.
다만 **걸린 운영자가 콘솔에서 무엇을 잃어야 하는지는 미정**이라, 지시대로
**자리 넷을 그대로 두고 주석만 갱신**했다. 이 항목의 코드 변경은 **0줄**이다.

주석은 이제 *절반이 확정됐다 / 여전히 의도가 아니라 보류다 / 대상은 확정 · 콘솔 영향은 미정* 을 말한다.
`toolGate` 의 잠금 문자열도 함께 옮겼다 — **의도적 변경이라 그 사실을 테스트 주석에 적었다.**

## 6. `expired` 문안 — **어디를 바꿨는지**

새 문구: **`이용이 보류되었습니다. 운영자에게 문의해 주십시오.`**

| # | 자리 | 처리 |
|---|---|---|
| ⑴ | `feed_assert_writable` (DB) | **새 마이그레이션 `20260831100000_hold_message.sql`** — 적용된 파일을 고치지 않는다(불변식 15). **적용하지 않았다** |
| ⑵ | `src/core/membershipVocab.ts` `TIER_LEAD.suspended` (화면) | 직접 교체 |
| ⑶ | `src/core/membershipVocab.test.ts` | 잠금 문자열 갱신 |
| ⑷ | `src/app/account/AccountForm.test.tsx` (2곳) | 기대값 갱신 |

**`held` 문장은 건드리지 않았다** — *확인 중* 과 *보류됨* 이 한 문장으로 뭉개지면 안 된다.
DB 본문은 `pg_get_functiondef` 로 **라이브 정의를 받아** 문자열 한 줄만 바꿨고,
원 주석도 지우지 않았다(§3 보존). 두 사본이 한 글자도 다르지 않음을 `toolGate` 가 잠근다.

**보고할 어긋남 하나** — 최박사 원문은 `문의해 주십시요` 이고 지휘부가 지정한 구현 문자열은
`문의해 주십시오` 다(한 글자). **임의로 다듬지 않았고 지휘부 지정값을 썼다.**
문안은 **얼어야 하는 값**이라 어느 쪽이 정본인지 한 번 확인해 주시기 바란다.

**알려진 창** — C 적용 전까지 화면은 새 문구, DB 는 옛 문구다. 뜻은 같고 경로가 다르다
(화면은 `내 정보` 설명 줄, DB 는 글쓰기 차단 시 던지는 예외). C 는 ③ 과 함께 적용하기를 제안한다.

## 7. 규율 승격 — `CLAUDE.md` §5

> **넓히는 변경은 스키마가 먼저, 좁히는 변경은 코드가 먼저다.**
> 인자·컬럼을 더하면 스키마가 먼저 있어야 새 코드가 쓸 것이 있고,
> 없애면 코드가 먼저 나가야 옛 코드가 없는 것을 부르지 않는다.
> **어느 쪽인지 정하지 않고 적용 순서를 잡는 것이 오류다.**

§11 의 *값의 두 분류* 와 같은 형식이다 — 금지가 아니라 **분류 의무**다.
