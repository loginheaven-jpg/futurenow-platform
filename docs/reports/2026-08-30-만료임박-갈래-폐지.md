## 1. ② 가 예고한 타입 오류 — **났고, 그것이 전부였다**

발주는 *참조하는 코드가 있으면 타입 오류로 즉시 잡힌다* 고 했다. 그대로였다.
`'pending' | 'expiring'` → `'pending'` 축소가 **네 자리**를 드러냈고(계약 · 매퍼 · 화면 뷰타입 · 화면 본문),
넷을 고친 뒤 `tsc` 가 0 이다. **축소가 스스로 목록을 만들었다** — 내가 찾아다닌 것이 아니다.

다만 타입이 못 잡는 자리가 하나 있었다: **SQL 쪽 갈래**. 그래서 잠금을 함께 뒀다
(`toolGate` 가 계약·화면에 `'expiring'` 리터럴이 0 임을 잰다).

## 2. 배포 순서를 못 박았다 — **깨지는 조합이 하나 있다**

인자(`p_expiring_days`)가 사라지므로 조합 넷 중 하나가 깨진다.

| 조합 | 결과 |
|---|---|
| 옛 코드 + 옛 함수 | 지금 (정상) |
| **새 코드 + 옛 함수** | **정상** — 옛 함수는 `DEFAULT 30` 이라 인자 없는 호출로 해석된다. 임박 행이 딸려 오지만 매퍼가 버린다 |
| 새 코드 + 새 함수 | 정상 |
| **옛 코드 + 새 함수** | ❌ **깨진다** — 옛 코드가 없는 인자를 보낸다 |

→ **① 코드 배포 → ② 마이그레이션 적용.** 이 순서면 창에 빈틈이 없다.

매퍼의 `filter(bucket === 'pending')` 한 줄은 **방어적 잡음이 아니라 그 창을 닫는 장치**다.
`bucket` 열을 남긴 것도 절반은 이 때문이다(나머지 절반은 되돌릴 자리).
주석이 그렇게 말해 두었고, 잠금이 그 한 줄의 존재를 잰다.

## 3. ④ — 뒤집은 것을 다시 뒤집었다

앞 판의 단언은 *지난 날짜도 임박 갈래에 남는다* 였다.
**그것은 물었어야 할 자리에서 테스트를 고쳐 초록을 만든 것이었다.** 이제 부재를 잰다.

지우지 않고 뒤집은 이유는 트리거 폐지 때와 같다 — **큐가 무엇을 담지 않는가**를 아무도
재지 않으면 다음 사람이 갈래를 되살려도 조용하다.

**대조군을 함께 뒀다.** `'-'` 하나로는 *갈래가 없어서* 인지 *큐가 통째로 비어서* 인지 못 가른다.

```
① 대조군 · 대기인 사람        → pending   ← 측정이 실제로 무언가를 잰다는 증거
② 창 안쪽 +30일               → '-'       ← 옛 판이라면 expiring
③ 지난 날짜                   → '-'       ← 옛 판이라면 영영 남았을 행
④ valid_until 값             → 살아 있다  ← 갈래를 걷었다고 값이 사라지면 되돌릴 수 없다
⑤ list_membership_queue(30)  → 42883     ← 옛 오버로드가 남으면 갈래가 되살아날 문이 남는다
```

**인자 형태가 적용 전후로 다르다.** 적용 전 `(30)` · 적용 후 `()`.
`()` 하나로 두 판을 덮으면 **적용 전에 조용히 다른 것을 재게 된다**(옛 함수가 `DEFAULT 30` 이므로).

적용 전에는 **레드로 두지 않고 시끄럽게 건너뛴다**. 실측 출력:

```
[승인 큐] 만료 임박 폐지 확인 건너뜀 — 마이그레이션 20260831090000 적용 대기
```

## 4. **변이가 성립하는지 먼저 확인했다** — 계열 ⑧ 을 내 새 테스트에 걸었다

건너뛰는 테스트는 *통과* 로 보이므로, 그 초록을 잠금의 증거로 읽으면 이번 계열 그대로다.
그래서 게이트를 강제로 `true` 로 두고 **라이브(미적용)** 에서 돌렸다.

```
× **만료 임박 갈래가 없다** — 폐지 확인 · 대조 쌍
AssertionError: 창 안쪽 +30일 — 옛 판이라면 expiring 이었다: expected 'expiring' to be '-'
```

**빨개졌고, 실패 문구가 옛 동작을 그대로 말한다.** 재는 것이 실재한다.
되돌리기는 **백업본 복사**로 했다(계열 ⑥ — `git checkout` 아님).

## 5. postdeploy — **얻는 방법을 적었다**

기대 커밋은 **따라가야 하는 값**인데 손으로 박고 있었다.
절차서 해시 건에서 *고정 해시는 push 할 때마다 낡는다* 는 규율을 세워 놓고
**이 도구에 내려보내지 않은 채 한 회차를 더 돌았다.** 그 사실을 주석에 남겼다.

이제 기본값이 `git ls-remote origin main` 조회다. 로컬 `git log` 를 보지 않는 이유는
`CLAUDE.md` §11 과 같다 — **배포가 서빙할 것은 원격이 들고 있는 것**이다.

**도구를 먼저 측정했다:**

```
[기대 커밋] git ls-remote origin main → 71fa30c
  O 배포 신원   71fa30c · ref=main · env=production · dpl_HfNFrkzmaznT74XNhr8NQJm5GXbT
[기대 커밋] 손으로 지정 → abc1234  (기본은 origin/main 조회다)
  X 배포 신원   상한 안에 abc1234 가 서지 않았다 (마지막: 71fa30c)
```

**운영 배포가 `71fa30c` 임이 이 실행으로 함께 확인된다** — 인수 착오였다는 판정 그대로다.

## 6. 발주 밖에서 하나 걷었다 — **보고한다**

승인 화면 하단의 문장을 함께 걷었다.

> *만료된 계정은 새 체크 응시가 닫히되, 이미 실시한 결과의 열람은 본인에게 계속 열려 있습니다.*

**지금 참이 아니다.** `expired` 는 이제 운영자가 손으로 두는 `이용 보류` 뿐이고,
`20260830090000` 이 그것으로 **피드·기수 조회까지** 막는다. 응시만 닫히는 상태가 아니다.

**틀린 문장을 남기지도, 묻지 않은 새 문장을 지어내지도 않았다.**
자리와 사유를 주석으로 남겼다 — 문안이 필요하면 최박사 소관이다.

## 7. ADR-122 ⑧ — 안전망 논거의 소멸을 그 자리에 적었다

⑧ 은 *복수 차수 수료자 기간 미갱신(대상 3명)* 을 남기며 **임박 목록을 안전망으로** 들었다.
그런데 그 한계를 만들던 **마감 트리거 자체가 ADR-147 에서 폐지됐다.**
지키던 위험이 없으므로 안전망만 남을 이유가 없다 — 이 걷기는 **버리는 것이 아니라
대상이 사라진 장치를 치우는 것**이다. ADR-122 본문에 한 줄로 표시했다(사본을 만들지 않고 참조로).
