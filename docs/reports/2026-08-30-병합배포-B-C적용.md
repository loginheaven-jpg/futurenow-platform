## 4. 롤백 예행 — 셋 다 통과

되돌리는 문은 **라이브 `pg_get_functiondef` 에서 받아** 만들었다. 지어내지 않았다.

```
[B 롤백 예행] 적용됨 ["list_membership_queue()"]
              되돌림 ["list_membership_queue(integer)"] · 정의+권한 원문 일치 O
              라이브 무변경 확인 O
[C 롤백 예행] 적용됨 ["feed_assert_writable(uuid)"]
              되돌림 ["feed_assert_writable(uuid)"] · 정의+권한 원문 일치 O
              라이브 무변경 확인 O
```

정의뿐 아니라 **권한(`proacl`)까지** 대조했다 — `DROP`+`CREATE` 가 권한을 승계하지 않기 때문이다.
장부에 `statements` 와 `rollback` 을 함께 실었다. **B 와 C 는 따로 예행하고 따로 적용했다.**

## 6. C 검증 — **문자열을 읽지 않고 띄워서 받았다**

정의 본문에 그 문장이 있다는 것과 **실제로 그 문장이 던져진다**는 것은 다른 사실이다.
게이트 잠금에서 *있는가/작동하는가* 를 가른 것과 같은 형식이라 후자를 잰다.

상주 테스트를 붙였다(대조군 포함):

```
① 대조군 · 막힐 이유 없음  → 던지지 않는다
② expired                  → 55000 · 이용이 보류되었습니다. 운영자에게 문의해 주십시오.
③ held                     → 55000 · 계정 확인이 필요해 지금은 글을 올릴 수 없어요. …
④ ②와 ③이 서로 다르다      → 단언한다 (뭉개지면 상태 구분이 사라진다)
```

## 7. 발견 — **잠금이 거짓을 지키고 있었다**

`20260830090000` 은 2026-08-30 에 적용됐는데 파일 머리에 *아직 적용되지 않았다* 가
그대로 남아 있었다. 그리고 `toolGate` 의 *적용 금지가 파일 머리에 적혀 있다* 가
**그 거짓을 요구하고 있었다.**

**잠금이 있었는데도 틀렸다.** 잠근 대상이 **「그 문장이 있는가」**였지 **「사실인가」**가
아니었기 때문이다. 적용 상태는 **따라가야 하는 값**인데 **얼어야 하는 값처럼 박혀** 있었다.

→ 세 파일 머리를 *적용됨 `<날짜>` + 검증 결과* 로 맞추고, 잠금도 그쪽으로 옮겼다.
   테스트 주석에 **다음 규칙**을 적어 뒀다 — *적용 전 파일에는 이 잠금을 걸지 않는다.*
   걸면 다시 같은 거짓을 지킨다.

**적용된 마이그레이션 셋의 편집은 주석뿐이고 DDL 델타 0 이다**(불변식 15 · 기계 확인).

## 8. 하네스가 한 번 틀렸다

검증 스크립트 첫 실행이 `42702 column reference "oid" is ambiguous` 로 멈췄다 —
`pg_proc` 와 `pg_namespace` 가 **둘 다 `oid` 를 가진다.**

**마이그레이션이 아니라 자를 잘못 만든 것**이었고, 예행을 먼저 돌리는 순서가
그것을 **적용 전에** 드러냈다. 적용 단계에서 났다면 원인 후보가 둘이 됐을 자리다.
