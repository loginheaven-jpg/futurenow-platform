## 1. ② — **`is_admin` 이 `member_state` 를 부르면 무한 재귀였다**

지시대로 `is_admin` 이 이용 보류를 보게 했다. 다만 **`member_state` 를 부를 수 없었다.**

```
member_state 본문 (라이브 실측):
  IF p_uid <> auth.uid() AND NOT public.is_admin(auth.uid()) THEN … 42501
```

**`member_state` 가 이미 `is_admin` 을 부른다.** 거기서 `is_admin` 이 다시 `member_state` 를
부르면 서로가 서로를 부른다. **정본을 열지 않았으면 그대로 넣었을 자리다**(계열 ⑦).

그래서 **저장값(`memberships.status`)을 직접 읽는다.** 등가인 이유가 분명하다 —
ADR-147 이 만료 산출을 폐지해 `member_state = 'expired'` ⟺ `status = 'expired'` 다.

**다만 이 등가는 「만료를 산출하지 않는다」에 기대고 있다.** 누가 만료 산출을 되살리면
두 곳이 조용히 갈린다 → **통합테스트가 두 값이 같은지 단언한다**(불변식 23).

### 자리 넷이 아니라 여기인 이유 — **실측**

```
is_admin 을 쓰는 정책   48개 (전체 88개 중)
is_admin 을 부르는 함수 27개
```

**지휘부는 42개라 하셨으나 실측은 48개다.** 세어 보고 적는다.
넷만 고치면 나머지 75곳이 다음 사고의 자리가 된다.

### 복구 경로 — 실측으로 확인

`decide_membership` 이 **자기 자신에게는 걸 수 없게** 막는다(`p_user_id = auth.uid()` → 42501).
운영자는 2명이므로 한 사람이 걸리면 **남은 운영자가 푼다.**
**둘 다 걸리면 앱으로는 못 푼다** — 되돌리는 문이나 DB 소유자 권한이 필요하다.
**알고 두는 위험**으로 파일에 적었다.

## 2. 적용하지 않고 **예행으로 검증했다**

트랜잭션 안에서 적용하고 재고 전부 ROLLBACK 했다. 라이브 원상 확인까지 했다.

```
적용 전  A=true · B=true
[예행]
보류 전  A=true  · B=true
보류 후  A=false · B=true    O 대조 쌍 성립
재귀 없음 member_state → expired  O
  등가 저장=expired     판정=expired  is_admin=false  O
  등가 저장=held        판정=held     is_admin=true   O
  등가 저장=individual  판정=cohort   is_admin=true   O
라이브 원상 A=true · B=true
라이브 is_admin 에 memberships 참조 없음 (O 미적용)
```

**B 가 끝까지 `true`** 인 것이 요점이다 — 운영자 전체가 꺼진 것이 아님을 그것이 말한다.

## 3. **남은 구멍을 보고한다 — 이대로 적용하면 반쪽이다**

DB 는 닫히는데 **화면은 열린다.**

```
앱 계층에서 users.role 을 직접 읽는 자리  21곳
  · /admin·/admin/approvals 진입 게이트    me.role !== 'admin' → redirect
  · MembershipView.isAdmin                 me.role === 'admin'
  · 코치 콘솔·홈·내비 등
```

이 자리들은 **보류를 보지 않는다.** 적용하면 보류된 운영자가 콘솔에 **들어가서**
RLS 가 다 막은 **빈 화면**을 본다 — 깨끗한 차단이 아니라 고장 난 화면이다.

**결함이 아니라 미완**이고, 지시하신 *자리 넷만 고치지 마라* 가 **한 층 위에서 반복되는 자리**다.
다만 **무엇을 보여 줄지는 문안 결정**이라(이용 보류 안내로 보낼지, `/pending` 으로 보낼지)
지어내지 않고 멈췄다. **지시 주시면 잇겠다.**

## 4. 문안 셋

| 자리 | 새 문장 |
|---|---|
| 방문회원 | 세미나에 참여하시거나 촉진자포럼에 가입하시면 진단 등 모든 도구를 이용하실 수 있습니다. |
| 참여자 | 세미나 기간 동안 모든 도구를 이용하실 수 있습니다. 기간이 끝나도 그동안의 기록은 계속 보실 수 있습니다. |
| 이용 보류 | 이용이 보류되었습니다. 운영자에게 문의해 주십시오. **(`주십시오` 정본 확정)** |

**잠금 둘을 새로 뒀다.**
- 넷 모두에서 **`만료` 라는 낱말 금지** — 폐지된 개념을 가리키게 된다.
- **약속을 좁히지 않는다** — 옛 잠금은 `진단 등 모든 도구` 문자열을 요구했는데, 새 참여자 줄은
  `모든 도구` 다. **좁아진 것이 아니라 예시가 빠진 것**이므로 검사를 *`모든 도구` 라고 말하는가* 로
  옮겼다. **뜻을 지키고 문자열만 옮겼다.**

### 사본 셋을 둘로 줄였다

`AccountForm.test.tsx` 가 문안을 **하드코딩**하고 있어 확정과 함께 세 곳이 빨개졌다.
상수를 참조하도록 바꿨다 — 이제 **화면 테스트는 「화면이 상수를 쓰는가」만** 재고,
문장 자체는 `membershipVocab.test.ts` 가 잠근다. **문안이 바뀌어도 화면 테스트는 안 바뀐다.**

### 보고할 겹침 하나

방문회원에게는 새 줄 아래 `UPGRADE_HOWTO` 가 **병기**된다(최박사 확정 2026-08-30).

```
새 줄        … 촉진자포럼에 가입하시면 … 이용하실 수 있습니다.
UPGRADE_HOWTO 촉진자포럼에 가입하고 정회원자격을 취득하시면 된다.
```

**둘 다 촉진자포럼 가입을 말하는데 조건이 다르다** — 앞은 *가입하면*, 뒤는 *가입하고 정회원자격까지*.
어느 쪽이 참인지는 제가 정할 자리가 아니라 **그대로 두고 보고한다.**

## 5. 「시끄럽게 건너뛴다」가 시끄럽지 않았다 — **부수 발견**

②의 테스트 넷을 기존 방식(조기 반환 + `console.log`)으로 붙였다가 확인해 보니
**기본 리포터가 그 출력을 삼킨다**(`--reporter=verbose` 에서만 4줄이 보인다).
그러면 건너뛴 것이 **통과로 세어지고** 초록의 뜻이 달라진 것을 아무도 모른다 —
**이번 회차에 잠금이 거짓을 지킨 것과 같은 모양**이다.

`it.skipIf` 로 바꾸니 **스킵 수가 7 → 11 로 움직여 기본 실행에서도 보인다.** 그것이 진짜 소리다.

## 6. 후속 목록에 올렸다

**진단 홈의 완료 항목에 결과 보기 링크가 없다.** `canJourney`(응시 가부)로 열람 링크까지
가르는 것이 원인이므로 **응시 링크와 열람 링크를 분리**한다. 결함이 아니라 불편이라
이번에 하지 않았다. 차수 홈에 조건 없는 리포트 링크가 살아 있어 최박사 모델은 그 경로로 성립한다.
