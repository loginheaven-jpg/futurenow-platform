## 1. §1 목록이 둘 어긋납니다

```
헤더있음 O  /          헤더없음 O  /library  /news  /news/[id]  /contact  /recruit
헤더있음 O  /about     헤더없음 O  /login  /reset  /reset/confirm
X /join   — **헤더가 이미 있다**
X /signup — **헤더가 이미 있다**
```

발주는 이 둘을 *헤더가 없다(신설)* 로 두었으나, **U-0 실측이 이미 밝힌 그대로**
두 화면은 두 단계 아래에서 헤더를 그립니다.

```
/join    _screens/entry/{AuthGate, CodeInput, CohortPreview, ProfileForm, StartGuide} : AppHeader
/signup  _screens/entry/AuthGate : AppHeader
```

**이것은 목록 오류가 아니라 작업 종류가 다른 것입니다** — 신설이 아니라 **이관**이고,
그 다섯 부품은 **`/preview/entry` 도 함께 씁니다.**

### Q1. `/join`·`/signup` 을 어떻게 하시겠습니까

- **(가) 함께 이관** — 다섯 부품에서 `AppHeader` 를 걷고 공개 껍데기가 그린다.
  그러면 **`/preview/entry` 갤러리도 헤더를 잃습니다.** 갤러리는 부품 전시라 큰 문제는
  아니어 보이나 **제가 정할 자리가 아닙니다.**
- **(나) 이번엔 제외** — `/join`·`/signup` 을 U-1 대상에서 빼고 예외 목록에 남긴다.
  그러면 이번 덩이는 **10화면**이 되고, 수용 기준의 *무헤더 12 → 2* 도 다시 잡아야 합니다.

**제 안은 (가)** 입니다. (나)는 공개 영역에 껍데기가 둘로 갈린 상태를 남기고,
갈리면 한쪽만 고치는 날이 옵니다. 다만 `/preview/entry` 손실을 승인해 주셔야 합니다.

## 2. Q2. `/` 는 **라우트 그룹**이 있어야 layout 을 가질 수 있습니다

Next 에서 `src/app/layout.tsx` 는 **전 라우트의 루트**입니다. `/` 하나에만 껍데기를 씌우려면
`src/app/(public)/page.tsx` 처럼 **라우트 그룹**으로 옮겨야 합니다(URL 은 그대로).

즉 공개 화면 디렉터리를 `(public)/` 아래로 **이동**해야 합니다.

**이동에 걸리는 참조 셋**(실측 · 전부 import 경로 한 줄):

```
src/app/page.tsx:26                     @/app/recruit/intake
src/app/reset/confirm/ResetConfirmClient.tsx:8   @/app/login/loginOutcome
src/app/signup/SignupClient.tsx:10               @/app/login/loginOutcome
```

`/recruit` 은 자기 `layout.tsx` 를 갖고 있어 함께 옮겨집니다(중첩은 유지됩니다).

**발주가 *바뀌는 것은 헤더·푸터가 서는 자리뿐* 이라 했는데 디렉터리 이동은 그보다 넓습니다.**
그래서 착수하지 않고 올립니다.

- **(가) 라우트 그룹 승인** — 규칙 1을 `/` 에서도 지킵니다. 이동은 기계적이고 URL 무변경입니다.
- **(나) `/` 만 예외로** — `page.tsx` 가 껍데기를 직접 부릅니다. 잠금은 통과하지만(껍데기는 헤더 부품이 아님)
  **규칙 1이 첫 화면에서만 깨집니다.** 권하지 않습니다.

## 3. 착수 전에 확인해 둔 것 — 답이 오면 바로 씁니다

**헤더·푸터 props 는 전부 상수입니다.** `PUBLIC_NAV` · `SITE_ORG` · `PUBLIC_FOOTER_LINKS` ·
고정 로고. 페이지마다 다른 것은 `currentPath` 하나뿐이고, `PublicGnb` 가 이미 클라이언트
부품이므로 **`usePathname()` 으로 스스로 알 수 있습니다** — 화면이 넘길 필요가 없습니다.
→ **껍데기로 올리는 데 막히는 prop 이 없습니다.**

**푸터 `note` 도 두 화면이 같은 문장**입니다(인도자 회원가입 링크). 상수 하나로 섭니다.

**ISR 실측** — 이 덩이의 급소입니다.

```
/          revalidate = 300     ← ISR
/recruit   revalidate = 300     ← ISR
/about     지시 없음(정적)
/news /library /contact  force-dynamic
```

`/` 와 `/about` 은 **이미 서버에서 쿠키를 읽지 않습니다**(ADR-138 · 세션 읽기는
`PublicGnb` 가 클라이언트에서 쿠키 이름만 봅니다). **그 방식을 그대로 껍데기로 옮기면
ISR 이 유지됩니다** — 새로 고를 것이 없고, 근거를 파일에 적겠습니다.
