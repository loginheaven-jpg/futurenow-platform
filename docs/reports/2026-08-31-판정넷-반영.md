## 1. 가② — **물으신 것보다 넓은 답이 나왔다**

**앱 21곳은 안전합니다.** 전부 DB 뒷받침이 있습니다(게이트·표시·`coach||admin` 쓰기 가드).
*역할만 보고 쓰기를 허용하는데 DB 가 안 막는 자리* 는 **0개**입니다.

**그런데 다른 층에 구멍이 있습니다.**

```
auth.uid() 로 통과하며 member_state 를 보지 않는 쓰기 정책   51개
  (실측 2026-08-31 · 산출 명령은 마이그레이션 주석에 있다)
```

`is_admin` 을 고쳐도 **자기 자신 경로**(`user_id = auth.uid()`)와
**코치 소유 경로**(`coach_id = auth.uid()` · `is_cohort_coach(...)`)는 닫히지 않습니다.

> `cohorts_update` · `cohorts_delete` = `(coach_id = auth.uid()) OR is_admin(...)`
> → **보류된 코치가 자기 차수를 그대로 고칩니다.**

**그러므로 보류의 완결성은 RLS 가 아니라 로그인·세션 차단에 달려 있습니다.**
51곳에 조건을 하나씩 붙이는 길도 있으나 그것은 **규칙을 51곳에 두는 일**이고,
세션을 끊으면 **호출 자체가 성립하지 않아** 한 번에 닫힙니다.
**세션 무효화가 근본 처리라는 판정이 제 실측보다 더 옳았습니다.**

### 남는 것 하나 — **재지 못했습니다**

이미 발급된 액세스 토큰의 잔여 수명입니다. 세션 행을 지우면 갱신은 막히지만
JWT 는 서명으로 검증되므로 **만료 전 한 번은 통과할 수 있습니다.**

`currentUser()` 와 미들웨어가 **둘 다 `auth.getUser()`** 를 부르므로(로컬 디코드가 아니라
**GoTrue 왕복**입니다) 실제로는 거기서 막힐 가능성이 높습니다. **그러나 재지 못했습니다** —
살아 있는 계정을 잠가야 잴 수 있습니다.

**확인하지 않은 것을 안전하다고 적지 않았습니다.** 적용 시점에 테스트 계정으로 잽니다.

## 2. 가① — 세션 무효화 (예행 확인)

```
세션  4 -> 0   O 끊긴다
잠금  banned_until=infinity
해제  banned_until=null
세션은 되살리지 않는다 — 현재 0개 (다시 로그인하면 된다)
라이브 원상 — is_super_admin 없음 (미적용)
```

`refresh_tokens`·`mfa_amr_claims` 는 `session_id` 가 `ON DELETE CASCADE` 라 함께 사라집니다(실측).
다만 **`session_id` 가 NULL 인 옛 행**이 남을 수 있어 사용자 기준으로 한 번 더 지웁니다.

**세션은 되살리지 않습니다.** 지운 것을 되돌릴 수 없고, 풀린 사람은 다시 로그인하면 됩니다 —
가장 단순하고 틀릴 자리가 없습니다.

## 3. 나 — 항목째 뺐습니다

*되돌리는 법* 을 **문장만 걷고 자리를 남기지 않았습니다.** 남기면 다음 사람이
**다른 문장을 지어 넣고**, 그것은 걷으라 하신 것을 다른 말로 되살리는 셈입니다.
일반 회원에만 남기는 안도 택하지 않았습니다.

테스트가 **키 집합 자체**(`['loses','noteRequired','who']`)와 `되돌리` 문자열 부재를 함께 잽니다 —
문장 하나를 지우는 것보다 **자리가 없다는 사실**을 재는 편이 되살아나지 않습니다.

운영자 문장도 지시대로 줄였습니다: *이 분은 로그인하실 수 없게 되고, 운영 화면도 함께 닫힙니다.*

`console.log` 로 스킵 사유를 알리는 자리는 이제 **0건**입니다.

## 5. 라 — 결심을 형식으로 옮겼습니다

ADR-148~152 본문의 테스트 집계를 걷고 **얻는 방법**으로 바꿨습니다.
정책 수처럼 설계 근거가 된 실측은 **잰 날짜와 산출 명령을 함께** 남겼습니다(얼어야 하는 값).
커밋 검산은 값이 아니라 **관계식**으로 남겼습니다.

`CLAUDE.md` §11 에 조항으로 올렸습니다 — 완주 보고의 `통과/스킵/총` 한 줄은 그대로입니다.
그 문서는 **그 시점의 보고**이고, 낡는 것이 문제가 되는 자리는 **오래 남는 정본**이기 때문입니다.

## 7. 앞 보고의 검증 지시 ⑴ — 무엇을 정정했는가

지시 원문은 *운영자 둘의 `member_state` 가 `individual` 인지* 였습니다.

**한 명은 `cohort` 가 나옵니다.** 활성 세미나에 있고 판정 우선순위가
`held > expired > cohort > 저장` 이기 때문이며 **정상**입니다.

정정한 단언: *저장값이 `individual` 이고, 판정이 `expired`·`pending` 이 아니다.*
안전망의 뜻(조건을 잘못 써도 두 운영자가 통과한다)은 그대로 지켜집니다.

## 8. 남은 문구 어긋남 — **없습니다**

지시하신 대로 다시 훑었습니다. 로그인 문구와 `내 정보` 문구가 다른 것은
**둘 다 최박사 원문**이고 자리가 다르므로 어긋남이 아닙니다. 그 외에는 없습니다.
