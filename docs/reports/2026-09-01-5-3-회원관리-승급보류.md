## 1. 서버가 산출하고 화면은 그린다

계약을 **확장**했습니다(지휘부 승인분).

```
MemberSummary + memberState   ← member_state 판정을 그대로 싣는다
              + isSuperAdmin  ← 화면이 이메일로 판정하지 않는다
```

**저장값에서 다시 유도하지 않았습니다.** 유도하면 판정이 SQL 과 코드 둘에 살고 한쪽만 고쳐집니다.
마이그레이션 0 발주라 일괄 RPC 를 새로 만들지 않고 사람 수만큼 부릅니다(운영자 전용 · 실측 25명 · 병렬).
**한 사람을 못 읽어도 목록이 무너지지 않게** 접고, 그 접힘을 대조군 테스트가 잽니다.

## 2. ★ 승급이 곧 해제다 — 실측

```
전      status=(행 없음)  판정=cohort    banned=-         세션=3
보류 후  status=expired    판정=expired   banned=infinity  세션=0
승급 후  status=individual 판정=cohort    banned=-         세션=0   ← 해제됐다
원상    status=(행 없음)  판정=cohort    banned=-         세션=3
```

별도 「해제」를 만들지 않았고, **`expired` 인 행에서 승급 버튼이 활성**입니다(테스트가 `disabled` 부재를 잽니다).

## 3. 서버 가드 — **화면을 우회해 직접 호출**했습니다

```
자기 자신 보류                    막힘 42501
슈퍼어드민 보류(슈퍼가 눌러도)      막힘 42501
슈퍼어드민 보류(일반 운영자)        막힘 42501
운영자 보류(일반 운영자)           막힘 42501
운영자 보류(슈퍼어드민)            통과
일반 회원 보류(운영자)             통과
보류된 사람 승급(=해제)            통과
```

화면의 노출 규칙은 이 결과를 **비추기만** 합니다 — 막혀도 감추지 않고 비활성 + 사유입니다.
*안 보이면 왜 없는지 모릅니다.* 판정은 순수 함수로 떼어 화면 없이 9개 테스트가 잽니다.

