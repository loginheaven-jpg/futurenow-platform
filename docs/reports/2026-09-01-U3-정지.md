## 2. §1② 에서 멈춥니다 — **다섯이 사라집니다**

`consoleNav` 는 **3 묶음 11 항목**을 냅니다.

```
인도자   콘솔 홈 · 모든 차수 · 차수 개설
이 기수  기수 대시보드 · 회차 갈무리 · 진단 결과 · 가치 카드 · 동행
운영     본부 · 가입 승인 · 자료실
```

**각 목적지가 화면 안에서도 닿는가**(정규식 실측):

```
모든 차수      O 4곳      기수 대시보드  O 4곳
차수 개설      O 2곳      회차 갈무리    O 4곳
진단 결과      O 2곳
────────────────────────────────────────
가치 카드      X 0곳  ← 사이드바에만 있다
동행           X 0곳  ← 사이드바에만 있다
본부           X 0곳  ← 사이드바에만 있다
가입 승인      X 0곳  ← 사이드바에만 있다
자료실         X 0곳  ← 사이드바에만 있다
콘솔 홈        X 0곳  ← 다만 상단바의 `콘솔` 이 그 자리를 대신한다(규칙 3)
```

**사이드바를 걷고 상단바 하나 + 탭 줄 한 단계로 가면 다섯이 갈 곳이 없습니다.**
탭 줄 한 단계는 현재 문맥(‘이 기수’ 다섯)으로 이미 찹니다.

발주는 「넘치는 항목은 화면 안으로 내린다」고 하셨는데, 그 다섯은 **화면이 아직 링크하지 않는 곳**이라
내리려면 **화면에 링크를 새로 만들어야** 합니다. 그런데 「하지 말 것」이
**목적지를 바꾸지 않는다 — 늘어나는 것은 헤더이지 링크가 아니다** 라고 못 박고 있습니다.

**두 조항이 부딪히고, 어느 쪽이든 제가 정하면 화면에서 무언가가 사라지거나 링크가 늘어납니다.**
「없어지는 것이 하나라도 있으면 멈추고 보고하라」에 걸리므로 멈춥니다.

## 3. 안 셋 (제 안은 ㉮)

**㉮ 상단바에 메뉴 시트를 단다** — 회원 껍데기와 **같은 `MenuSheet` 한 벌**.
상단바 = 로고 · **콘솔** · 내 홈 · 메뉴. 탭 줄 = 현재 문맥 항목.
→ **사라지는 것 0 · 새 링크 0 · 부품 0벌 추가.** 최박사 상위 방향
(*메뉴는 한 자리에서만 열린다* · *껍데기는 하나이고 방마다 담기는 항목만 다르다*)과도 맞습니다.
다만 발주 §2 의 「탭 줄 한 단계까지만」이 시트를 뜻하는지가 갈립니다.

**㉯ 다섯을 화면 안으로 내린다** — 콘솔 홈·기수 대시보드에 링크를 새로 만든다.
→ 발주 「목적지를 바꾸지 않는다」와 부딪히고, **어디에 어떤 이름으로 둘지가 새 설계**입니다.

**㉰ 다섯을 이번엔 사이드바에 남긴다** — 부분 이관.
→ 사이드바가 남으므로 최박사 확정(사이드바 제거)에 어긋납니다. 권하지 않습니다.
