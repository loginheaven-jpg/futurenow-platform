## 1. §0 측정 — 예상과 같았다

```
ConsoleShell   <header> 0 · <nav class="console-nav"> 1     ← 사이드바만 그린다
일곱           전부 variant="sub" + 화면마다 다른 title·backHref
               (회차 갈무리 현황 · 갈무리 카드 미리보기 · 그룹 리포트 · 갈무리 격자 ·
                갈무리 기록 · 개인 리포트 · 가치 카드)
```

제목은 **소스에서 뽑았습니다**(보고서에서 옮겨 적지 않았습니다).

```
python -c "…re.search(r'<AppHeader\b([\s\S]{0,260}?)/>', src)…"
```

## 2. 두 자리가 무엇을 나눠 갖는가

| 자리 | 담기는 것 |
|---|---|
| **탭 줄**(한 단계) | 「이 기수」 — 기수 대시보드 · 회차 갈무리 · 진단 결과 · 가치 카드 · 동행. **차수 밖에서는 서지 않는다** |
| **시트**(상단바 메뉴) | 콘솔 전역 — 「인도자」(콘솔 홈 · 모든 차수 · 차수 개설) · 「운영」(본부 · 가입 승인 · 자료실) |

**시트는 회원 껍데기와 같은 `MenuSheet` 한 벌**입니다.

---

## 3. ★ 사라진 것 — **하나 있습니다. 결재를 청합니다**

**사이드바 11 항목: 사라진 것 0.** 실측상 다섯이 사이드바에만 있었으므로 시트가 없었다면 사라졌습니다.

**그러나 `subtitle` 셋이 사라집니다.**

```
/coach/cohort/[id]/group    subtitle = 사전·사후 비교 · 차수 평균 (또는 사전 · 차수 평균)
/coach/cohort/[id]/matrix   subtitle = 차수 이름
/coach/cohort/[id]/values   subtitle = 차수 이름
```

표는 **라우트의 성질**만 듭니다. 차수 이름·비교 문구는 **서버 데이터**라 라우트에서 나오지 않습니다.
**화면에서 무언가 사라지는 것은 최박사 결재 사항**이므로 병합 전에 올립니다.

되살리려면 껍데기가 화면에서 부제를 받아야 하고, 그것은 **화면이 껍데기에 값을 넘기는 통로**를
새로 여는 일입니다(U-2 에서 `/join` 단계 크롬 때문에 미룬 것과 같은 기제).

**사라지지 않고 옮겨간 것 하나**: 본부↔인도자 콘솔 지름길(`HeaderActions` 의 `navHref`) → **시트**.

## 4. 실측 — 헤더 하나 · 사이드바 0 · 탭 한 단계

```
/coach                              내비헤더=1 사이드바=0 탭줄=0  제목 "콘솔"
/coach/cohorts                      내비헤더=1 사이드바=0 탭줄=0  제목 "모든 차수"
/coach/new                          내비헤더=1 사이드바=0 탭줄=0  제목 "차수 개설"
/coach/cohort/{id}                  내비헤더=1 사이드바=0 탭줄=1  제목 "기수 대시보드"
/coach/cohort/{id}/checkin          내비헤더=1 사이드바=0 탭줄=1  제목 "회차 갈무리 현황"
/coach/cohort/{id}/checkin/preview  내비헤더=1 사이드바=0 탭줄=1  제목 "갈무리 카드 미리보기"
/coach/cohort/{id}/group            내비헤더=1 사이드바=0 탭줄=1  제목 "그룹 리포트"
/coach/cohort/{id}/matrix           내비헤더=1 사이드바=0 탭줄=1  제목 "갈무리 격자"
/coach/cohort/{id}/values           내비헤더=1 사이드바=0 탭줄=1  제목 "가치 카드"
```

**`/admin` · `/admin/approvals` 는 브라우저로 재지 못했습니다** — QA 계정이 코치라 리다이렉트됩니다.
표에 있고 `admin/layout` 이 `ConsoleShell` 을 두르므로 구조상 서지만, **미실측으로 남깁니다.**

### 측정에서 세 번 걸렸습니다

```
⑴ <header> 를 통째로 세어 본문의 의미 태그(피드 요약)를 «두 줄» 로 읽었다 — 창이 넓었다
⑵ 로딩 셸을 쟀다(`불러오는 중…`)
⑶ 리다이렉트 전 URL 을 착지로 읽었다
```

셋 다 계열 ⑨/①의 얼굴입니다. 조건 대기와 좁힌 선택자(`header:has(.site-gnb__burger)`)로 고쳤습니다.

## 5. ③ eslint 도구 대조 — **둘 다였습니다**

```
같은 명령(npx eslint .) · 옛 판독은 tail -2 라 `✖ N problems` 요약줄을 잘라냈다
10dc19f (U-1 배포본)  8 warnings
d92b1dd (U-2 병합)   20 warnings   ← 실제 증가 12(전부 U-2 가 남긴 죽은 변수)
지금                   3 warnings   ← 정리 후. 셋 다 U-1 이전부터 있던 것
```

**판독 창도 좁았고 실제로도 늘었습니다.** 도구의 값은 *전에 안 보던 것을 보게 됐다* 이고,
그 덕에 죽은 변수 12개와 쓸모없어진 `eslint-disable` 둘이 드러났습니다.

하네스 계열 **⑩** — *도구를 바꿀 때는 도구부터 대조한다.*
