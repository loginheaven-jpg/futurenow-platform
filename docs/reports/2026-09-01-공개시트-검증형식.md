## 1. Ⅰ 공개 시트 — 지어낸 문장 0

```
머리 이름   퓨처나우      ← SITE_ORG('퓨처나우 · 청계로벤하임') 의 앞부분
묶음 제목   이용 안내      ← SiteFooter 내비가 aria-label 로 쓰던 이름
```

**값이 아니라 관계를 잠갔습니다.**

- `SITE_ORG.startsWith(SITE_NAME)` — 한쪽만 고치면 레드
- 푸터의 `aria-label="이용 안내"` 와 `PUBLIC_MENU_TITLE` 일치
- `_screens/site` 의 `MenuSheet` 파일이 **하나**인가 — 두 벌이 되면 레드

**실측**

```
/ · /library · /about   site-gnb__burger = 1 · 이용 안내 = 1
390 캡처                 로고 + 로그인 + 햄버거   ← 최박사가 첫 관찰로 짚으신 자리
```

## 2. Ⅱ 검증 형식 — 도구가 뽑고 사람은 붙인다

규칙 넷을 그대로 넣었습니다.

- ㉠ `Test Files` 에 `passed` 아닌 것이 있으면 **그 줄이 곧 실패 판정**
- ㉡ 붙이는 것은 **출력 전문**(§4)
- ㉢ 한 지표라도 빠지면 `process.exit(1)`
- ㉣ **도구 자신을 잠갔다** — `tests/verifyHarness.test.ts`

**변이 둘로 확인했습니다.**

```
Test Files 를 판정에서 뺌            → 레드 «Test Files 를 실패 판정에 쓰지 않는다»
Duration 을 빠짐 검사 목록에서 뺌     → 레드 «Duration 이 빠짐 검사 목록에 없다»
```

두 번째 변이는 **처음에 성립하지 않았습니다**(제 치환이 실패). 계열 ⑧대로
**변이가 대상에 닿았는지 먼저 확인**하고 다시 쟀습니다. 그 과정에서 잠금이
*문자열이 있는가* 를 재고 있던 것도 드러나 **빠짐 검사 목록 안을** 재도록 조였습니다.

## 3. 하네스 계열 ⑨ — 세 번은 형식이다

> **판정의 근거가 판정하려는 것보다 좁다.**
> ⑴ *시끄럽게 출력한다* 가 출력이지 집계가 아니어서 스킵이 통과로 셌다
> ⑵ 잠금이 문장의 존재를 쟀고 사실을 안 쟀다
> ⑶ 초록 판정이 `Tests` 줄만 보고 `Test Files` 를 안 봤다 — 수집 실패 다섯이 숨었다
>
> 셋 다 **값은 맞았고 창이 작았다.** 세 번 같은 자리면 주의가 아니라 형식이다.

`CLAUDE.md` §11 에 조항으로, `shots.mjs` 계열 ⑨로 올렸습니다.
