## 0. 먼저 — 지휘부 인식과 실물이 **한 군데 어긋납니다**

「2단계」라고 하셨는데, **활성 기수가 하나뿐인 순수 참여자는 로그인해도 `/home` 을 안 지납니다.**
`landingFor` 가 기수 홈으로 **직행**시킵니다(ADR-173 · 실측 확인).

그러면 그분들은 `/home` 을 언제 보나 — **시트의 「내 홈」을 누를 때**입니다.
즉 지금 구조는 「2단계 통과」가 아니라 **「두 집이 있는데 하나는 잘 안 쓰인다」**에 가깝습니다.

**그래도 합치는 것이 옳습니다.** 이유가 바뀝니다 —
「단계를 줄인다」가 아니라 **「같은 것을 두 곳에서 다르게 말하는 것을 없앤다」**입니다.

## 1. Q1 — 합치면 어떤 문제가 있나 (실측)

### 1.1 ★ 막히는 것 셋

| # | 무엇 | 왜 막히나 |
|---|---|---|
| ⓐ | **기수가 0인 사람의 집이 사라진다** | `/my/cohorts/[id]` 는 그 차수가 내 것이 아니면 `/my/cohorts` 로 튕깁니다. **가입만 한 사람·기수 종료자·개인 회원**은 그 라우트에 머물 수 없습니다. 지금 그분들의 유일한 집이 `/home` 입니다 |
| ⓑ | **파라미터 없는 착지가 반드시 하나 필요하다** | 역할 게이트 폴백 `redirect('/home')` **14곳** · `router.push('/home')` 2곳 · `href="/home"` 3곳 · `screenChrome` 의 `back:'/home'` 2곳 · `CoachInfoGate` 「나중에 할게요」 · `/c/[code]` 실패 안내. 이들은 **차수 id 를 만들 수 없는 상태**에서 홈으로 보냅니다 |
| ⓒ | **역할 카드가 자기 자신을 가리키게 된다** | 「내 기수로 가기 → 기수 홈」 카드가, 홈이 곧 기수 홈이 되면 **자기 링크**가 됩니다 |

### 1.2 ★ 합치면 **드러나는** 기존 결함 넷 (합치기가 만든 것이 아닙니다)

| # | 무엇 | 실측 |
|---|---|---|
| ㉠ | **「1개」 판정이 세 곳에서 다르다** | `/my/cohorts/page.tsx` = **전체**(보관 포함) · `roleTarget` = **활성만** · `MemberHome` = **전체**. 합치면 한 화면의 같은 질문이 됩니다 — 하나로 정해야 합니다 |
| ㉡ | **「참여 중 N · 완료 N」이 사실을 잘못 말한다** | `total = 전체 기수 수`, `done = preDone`(**사전 진단 완료**)입니다. **기수 종료가 아닙니다.** 그래서 기수 하나짜리 사람이 「참여 중 1 · 완료 1」로 보입니다 — **같은 기수를 두 번 셉니다**(첨부 화면이 그 상태입니다) |
| ㉢ | **홈이 회원 자격을 모른다** | `/home` 은 `getMyMemberState()` 를 **한 번도 부르지 않습니다.** `pending`·`held`·`individual` 이 홈에서 구별되지 않고 전부 「기수 없는 사람」 한 모양입니다 |
| ㉣ | **같은 목적지가 한 화면에 두 번** | 운영자·인도자는 지금 `/home` 에서 `/admin`·`/coach` 를 **역할 카드로 한 번, 「운영」 구획에서 또 한 번** 봅니다. 기수 홈도 `journey`·`feed`·`report` 가 「나의 기록」과 「진단 카드」에 **두 번씩** 있습니다 |

## 2. Q2 — 어떻게 줄이나 : **권고안**

### ㉮ 살아남는 주소는 **`/home`** 입니다

| | 이유 |
|---|---|
| ⓐ 해결 | 기수 0인 사람도 그대로 `/home` 에 삽니다 |
| ⓑ 해결 | 파라미터 없는 착지가 그대로 삽니다 — **20여 곳을 안 고칩니다** |
| ⓒ 해결 | 역할 카드의 「내 기수로 가기」는 **사라집니다**(홈이 곧 기수 화면) |

**`/my/cohorts/[cohortId]` 는 지우지 않습니다.**
returnTo 화이트리스트에 등재돼 있어(ADR-176) **지우면 통과한 딥링크가 404** 가 됩니다.
그 라우트는 **「그 기수를 보는 화면」**으로 남기고, `/home` 은 **「지금 내 기수를 보는 화면」**이 됩니다.
기수가 둘 이상이면 `/home` 이 활성 기수를 그리고, 다른 기수는 그 주소로 갑니다.

**부수 이득** : ADR-173 의 「참여자는 막바로 기수로」가 **저절로 충족**됩니다 —
홈이 곧 기수 화면이므로 **착지 규칙에서 참여자 분기를 뺄 수 있습니다.**
인도자·운영자 직행(`/coach`)은 그대로 둡니다.

### ㉯ 대시보드 구성 (지시하신 그대로 + 실물에 맞춤)

```
┌─ 상단 벨트 (로고 · 메뉴 · 햄버거)
├─ 머리      {이름} 님의 여정 / PART N · GOAL — 회차 부제        ← 기수 홈 그대로
├─ 회차 줄   ①②③✓④⑤⑥⑦   1/7 완료            ← SessionChipStrip (이미 있는 부품)
├─ 오늘의 갈무리 카드   {N}회차 — 부제 / 상태 / [적으신 것 보기]   ← 기수 홈 그대로
├─ 바로가기(버튼 3)     되비추기 │ 동행 피드 (마지막 쓴 날) │ 사전 체크 (리포트 보기 / 이어 하기)
├─ 내 한 걸음                                                    ← 기수 홈 그대로
└─ 가치 카드                                                      ← 기수 홈 그대로
```

**「나의 기록」 4행 → 버튼 3**으로 바꿉니다(지시).
**서가는 행에서 빠지고 시트로** 갑니다 — 기수와 무관한 자료이고 시트 「자료」 구획에 이미 있습니다.

**소식·내 세미나·내 리포트·코드로 참여·운영 카드**는 **시트로** 옮깁니다(지시: 「메뉴들은 햄버거 휘하」).

### ㉰ 회차 표시 — **이미 있는 부품이 그 일을 합니다**

`SessionChipStrip` 이 네 상태를 그립니다 :

| 상태 | 지금 표현 |
|---|---|
| `done` | **네이비 면 + 체크 SVG** |
| `current` | **골드 면** |
| `open` | 기본 면 |
| `locked` | 점선 + 회색 (**감추지 않습니다** — 여정의 전체 길이가 보여야 합니다) |

**규율 확인 완료** — 의미색(경고색)을 안 씁니다. **불변식 9 안전.**
**불변식 11**(갈무리에 막대·게이지·순위 금지)도 안전합니다 — 진행 점은 **막대가 아니고**, 이미 기수 홈이 쓰고 있습니다.

★ **다만 「참여한 회차」가 무엇인지 결정이 필요합니다**(§3-④).

### ㉱ 시트 — 이름·현재 홈·출구

- **이름과 역할 슬롯이 부품에 이미 있습니다**(`site-sheet__name` + `<small>` 역할). **부품을 안 고칩니다.**
- ★ **지금 회원 시트에는 `/`(서비스 홈)도 `/home`(사용자 홈)도 `/coach`(콘솔)도 **없습니다.**
  요구 「언제든 갈 수 있어야」가 **미충족**입니다 — 이번에 **더합니다.**

## 4. 착수하면 하는 일 (결재 뒤)

1. `/home` 을 대시보드로 재구성 — 기수 홈 구조를 옮겨 온다. **새 부품 0.**
2. 「나의 기록」 4행 → **버튼 3**. 서가는 시트로.
3. `/home` 고유 다섯(소식·내 세미나·내 리포트·코드 참여·운영)을 **시트로**.
4. 시트에 **서비스 홈 · 사용자 홈 · 콘솔(겸직자)** 문을 더한다.
5. 「1개」 판정 **하나로** 통일 · 중복 링크 정리 · ㉡ 표기 교정.
6. `landingFor` 에서 **참여자 분기 제거**(홈이 곧 기수 화면).
7. 옛 잠금 넷을 **새 사실로 옮겨 적는다**(지우지 않는다).
8. 실행으로 잰다 — 역할 넷 × 기수 0/1/2+ × 폭 둘.

**문안은 한 글자도 새로 만들지 않습니다.** 필요해지면 **안을 내고 멈춥니다**(최박사 결재).
