# 설계 제안 — 네비게이션 정비 (착수 전)

- 근거 : 지휘부 지시 2026-09-02 「아래 제안을 바탕으로 자네 설계제안을 정리해 주세요」
- 잰 날 : 2026-09-02 · **한 줄도 고치지 않았다**

---

## 0. ★ 먼저 — 실측이 인식과 한 군데 다릅니다

> 지시 — 「현재는 **진단, 로그인 누르면 사라진다**」

**비로그인 상태에서는 벨트가 어디서도 사라지지 않습니다.** 라이브 실측(2026-09-02) :

```
[비로그인]
  /                   벨트 O · 메뉴 6 · 우측 「로그인」
  /about              벨트 O · 메뉴 6 · 우측 「로그인」
  /login              벨트 O · 메뉴 6 · 우측 「로그인」   ← 사라지지 않는다
  /home/assessments   → /login?returnTo=%2Fhome%2Fassessments
                      벨트 O · 메뉴 6 · 우측 「로그인」   ← 사라지지 않는다
  /library · /recruit 벨트 O · 메뉴 6
```

「진단」을 누르면 **로그인으로 튕기지만 벨트는 그대로**입니다.
보신 것은 **화면이 바뀐 것**이지 벨트가 사라진 것이 아닙니다.

**진짜로 사라지는 자리는 로그인 이후입니다** — 그것이 이 정비의 대상입니다.

```
[로그인 후]
  /                   벨트 O · 메뉴 6 · 우측 「내 홈」
  /home               벨트 O · 메뉴 0 · 햄버거          ← 메뉴 여섯이 사라진다
  /home/assessments   벨트 O + 제목바 O · 메뉴 0        ← 머리가 둘이다
  /coach              벨트 X · 제목바 O                 ← 벨트가 통째로 사라진다
  /my/cohorts         벨트 X · 제목바 O                 ← 같음
```

**세 갈래로 흩어져 있습니다.** 지시의 뜻 —
*「벨트는 유지되고 로그인 버튼이 햄버거로 바뀌기만 한다」* — 은
**한 갈래로 모으자**는 것으로 읽었습니다.

## 1. 벨트 일관성 — 왜 지금 셋으로 갈렸나

크롬은 표(`screenChrome.ts`)가 라우트마다 셋 중 하나를 정합니다.

| 종류 | 무엇이 서나 | 어디에 |
|---|---|---|
| `gnb` | 공개 벨트(로고·메뉴 6·로그인) | `/` · `/about` · `/library` · `/home` · `/my/cohorts/[id]` … |
| `bar` | 제목바(뒤로·제목·햄버거) | `/coach/**` · `/my/**` · `/account` · `/feed` … |
| `none` | 민무늬 | `/join` · `/library/[id]` · `/c/**` **넷** |

**갈린 이유가 있습니다.** `bar` 가 서는 화면들은 **제목과 뒤로가 필요**합니다 —
「회차 갈무리 현황」·「갈무리 격자」처럼 깊이가 있는 자리입니다.
벨트에는 그 둘을 놓을 자리가 없습니다.

그리고 `/home` 에서 메뉴 여섯이 사라지는 것도 사양입니다 —
`SiteGnb` 의 `variant='member'` 가 *「로고 + 햄버거뿐. 폭과 무관하게 시트가 내비다」* 입니다
(`design_system.md` §9.7).

**그러므로 「벨트를 늘 둔다」는 세 가지를 함께 풀어야 합니다** :
⑴ 제목과 뒤로를 어디에 두는가 ⑵ 로그인 뒤 메뉴 여섯을 유지하는가 ⑶ 머리가 둘이 되지 않는가.

### 1.1 안 셋

| 안 | 방식 | 얻는 것 | 잃는 것 |
|---|---|---|---|
| **A. 벨트 + 제목바 두 겹** | 벨트를 늘 두고 필요한 화면만 그 아래 제목바 | 가장 작은 변경. **이미 `/home/assessments` 가 그 모양** | 세로 **70px+** 를 늘 먹는다. 폰에서 크다 |
| **B. 벨트가 제목바를 흡수** | 벨트 하나가 로고·메뉴·뒤로·제목을 다 든다 | 머리가 하나. 세로 손실 0 | `SiteGnb`·`AppHeader` 를 합치는 큰 작업. §9.7 부품 둘 개정 |
| **C. 벨트 유지 · 제목은 본문으로** | 벨트는 늘, 제목은 화면 첫 줄, 뒤로는 벨트 왼쪽 | 머리가 하나. 중간 크기 | 화면마다 제목 자리를 새로 잡아야 함 |

**권고 — 폭으로 가릅니다(A와 B의 절충)**

- **lg↑(데스크톱)** : **A** — 벨트를 늘 두고 그 아래 제목바. 세로가 넉넉해 두 겹이 부담이 아니고,
  **메뉴 여섯이 늘 보입니다**(지시의 핵심).
- **md↓(폰)** : **현행 유지** — 제목바 하나. 폰에서 두 겹은 화면의 1/5 를 먹고,
  메뉴 여섯은 어차피 햄버거 안에 있습니다.

**왜 폭으로 가르나** — 지시의 뜻이 *「메뉴가 늘 보이게 하자」* 인데
**폰에서는 지금도 메뉴가 안 보입니다**(햄버거). 그러니 폰에서 두 겹을 만드는 것은
얻는 것 없이 세로만 잃습니다. 데스크톱에서만 값이 납니다.

### 1.2 로그인 버튼 ↔ 햄버거

지시 그대로입니다. 지금도 `publicHeaderAction(signedIn)` 이 **로그인 ↔ 내 홈**을 바꿉니다 —
그것을 **로그인 ↔ 햄버거**로 바꾸면 됩니다. 다만 :

- 지금 로그인 후 `/` 에서 우측이 **「내 홈」 글자**입니다. 햄버거로 바꾸면 **내 홈으로 가는 길이 시트 안으로** 들어갑니다.
- **시트에 그 항목이 있는지 확인이 필요합니다** — 없으면 로그인한 사람이 자기 집으로 가는 길을 잃습니다.

### 1.3 ★ 반드시 지켜야 하는 제약 둘

**⑴ `PublicShell` 의 트리 모양을 바꾸지 않습니다.**
그 파일에 이런 규약이 있습니다 — 갈래마다 **다른 모양**을 돌려주자
`{children}` 이 언마운트·재마운트되고, 실측으로 **5초에 `<main>` 175회 교체 · 서버 액션 초당 37회**가 났습니다.
`/join` 이 「불러오는 중」에서 못 벗어나고 서버가 503 을 냈습니다.
**머리와 발만 갈리고 `{children}` 의 자리는 언제나 같아야 합니다.**

**⑵ 크롬 표의 잠금이 함께 움직여야 합니다.**
`screenChrome.test.ts` 가 「빠진 라우트 0」과 `none` 개수 **넷**을 잽니다.
표를 고치면 그 잠금도 같은 커밋에서 옮겨야 합니다.

## 2. 로그인 이후 분기

### 2.1 지금 무엇이 있나 — **case3·case4 의 뼈대는 이미 있습니다**

`roleTargets(role, cohorts)` 가 **역할 카드를 여럿** 냅니다(5차 T-5 · 겸직).
`/home` 이 그 카드를 그립니다. 순서 규칙도 있습니다 — **운영/인도자가 먼저, 참여자가 뒤.**

| 지금 | 카드 |
|---|---|
| `admin` | 본부 + (자기 기수 있으면) 참여자 |
| `coach` | 인도자 콘솔 + (자기 기수 있으면) 참여자 |
| `user` · 기수 1 | 내 기수로 가기 |
| `user` · 기수 여럿 | 기수 목록 |
| `user` · 기수 0 | 체크 보기 |

### 2.2 지시와의 차이 — **셋**

**차이 ①  case1·case2 — 「막바로 진입」이 안 됩니다.**
역할이 하나여도 `/home` 에 카드 한 장이 서고 **한 번 더 눌러야** 합니다.
지시는 카드를 건너뛰고 바로 가라는 것입니다.

**차이 ②  case4 — 운영자에게 인도자 카드가 없습니다.**
`role` 이 **단일값**(`admin`|`coach`|`user`)이라 `if (role === 'coach')` 가 운영자에게 안 걸립니다.
**권한은 있는데**(운영자가 `/coach` 에 들어가면 전 차수를 봅니다) **홈에 길이 없습니다.**

**차이 ③  「운영자 메뉴에 순수 운영자 기능만」이 지금은 안 그렇습니다.**
운영자 전용 조작이 **인도자 콘솔 안에 흩어져 있습니다**(실측) —
`coach/cohort/[id]` 의 참여자 이동·삭제, 데이터 있는 차수 삭제(ADR-67),
`coach/cohort/[id]/checkin` 의 사진 삭제, `coach/cohorts` 의 전 차수 보기.

### 2.3 제안

**⑴ 착지 규칙을 `roleTargets` 하나가 정합니다** — 판정을 늘리지 않습니다.

```
카드가 1장  → 그 목적지로 바로 보낸다 (case1·case2)
카드가 2장+ → /home 에서 고르게 한다  (case3·case4)
```

**이미 있는 함수의 산출을 그대로 씁니다.** 새 판정을 만들지 않는 것이 요점입니다 —
「막바로 갈 것인가」를 다른 곳에서 다시 정하면 **판정이 두 곳**이 됩니다.

**⑵ 운영자에게 인도자 카드를 준다** — `roleTargets` 에 한 줄입니다.

```
admin  → 운영자 · 인도자 · (기수 있으면) 참여자   ← 지시 case4 의 세 버튼
coach  → 인도자 · (기수 있으면) 참여자           ← 지시 case3 의 두 버튼
```

지금 `if (role === 'coach')` 를 `if (role === 'coach' || role === 'admin')` 로 넓히는 일이고,
**권한 모델은 한 글자도 안 바뀝니다** — 운영자는 이미 `/coach` 에 들어갑니다(ADR-74).
**없던 문을 만드는 것이 아니라 있는 문을 홈에서 가리키는 것**입니다.

**⑶ 「커다란 버튼」은 새로 만들지 않습니다.**
지금 `SiteRoleCard` 가 그 자리입니다(시안 B `.role-card`). 크기·강조를 조정하면 되고,
**새 부품을 지으면 `design_system` §9.7 개정이 선행**해야 합니다(불변식 20).

**⑷ 운영자 기능 정리는 별건으로 뺍니다.**
차이 ③ 은 화면 이동이 아니라 **기능을 옮기는 일**이고, 옮기면 인도자 콘솔의 동작이 바뀝니다.
운영자가 겸임으로 인도자 일을 하는 지금 구조(§12.2)와도 닿습니다.
**어느 기능이 「순수 운영자」인지 목록을 먼저 확정**해야 합니다 — 그 목록은 지휘부 몫입니다.

## 3. 위험 — 셋

**⑴ 「막바로 진입」이 홈을 건너뛰면 홈의 다른 것도 건너뜁니다.**
`/home` 에는 역할 카드 말고도 **타일·소식·안내**가 있습니다.
참여자를 기수 홈으로 바로 보내면 그것들을 **영영 안 보는 사람**이 생깁니다.
→ 벨트/시트에 「내 홈」이 남아 있어야 합니다(§1.2 와 같은 확인).

**⑵ 로그인 착지는 `returnTo` 와 겹칩니다.**
지금 `/home/assessments` 를 누르면 `?returnTo=` 를 달고 로그인으로 갑니다.
**`returnTo` 가 있으면 그쪽이 이겨야 합니다** — 막바로 진입이 그것을 덮으면
링크를 받고 온 사람이 엉뚱한 데 착지합니다.

**⑶ 성질을 파생하지 않습니다.**
U-4 에서 *「뒤로가 있으면 `sub`」* 로 화면 성질을 파생시켰다가 `/join` 다섯 중 넷이
잘못 내려앉았습니다. **「카드가 1장이면 막바로」는 규칙이지 파생이 아니어야 합니다** —
`roleTargets` 의 산출을 그대로 세는 것이라 안전하지만, 그 셈을 **한 곳에서만** 해야 합니다.

## 4. 회차를 어떻게 나눌까 — 제안

| 회차 | 범위 | 왜 이 크기인가 |
|---|---|---|
| **N-1. 로그인 후 분기** | `roleTargets` 에 운영자 인도자 카드 + 카드 1장이면 막바로 착지 | **화면을 안 건드린다.** 순수 함수 하나와 착지 한 줄이라 되돌리기 쉽다 |
| **N-2. 벨트 일관성** | lg↑ 에서 벨트 + 제목바 두 겹 · 로그인↔햄버거 | 껍데기를 건드린다. **트리 규약** 때문에 따로 가야 안전하다 |
| **별건 ①** | 참여자홈·기수홈 통합 | 지휘부가 이미 「별도로 의논」이라 했다 |
| **별건 ②** | 운영자 전용 기능 모으기 | 목록 확정이 먼저다 |

**N-1 을 먼저 권합니다.** 지시 넷 중 셋(case1~4)이 거기서 풀리고,
화면을 안 건드려 **N-2 의 위험과 섞이지 않습니다.**

## 5. 판단을 청합니다 — 넷

**㉮ 벨트** — lg↑ 두 겹(권고) / 전 폭 두 겹 / 벨트가 제목바 흡수(큰 작업) 중 어느 것입니까.

**㉯ 로그인 후 우측** — 「내 홈」 글자를 햄버거로 바꾸면 **내 홈으로 가는 길이 시트 안으로** 들어갑니다.
시트에 그 항목을 두는 것으로 갈음할까요, 아니면 「내 홈」을 남길까요.

**㉰ 막바로 진입과 `returnTo`** — 링크를 받고 온 사람은 `returnTo` 가 이기는 것으로 확정해도 될까요.

**㉱ 「순수 운영자 기능」 목록** — 지금 인도자 콘솔에 섞여 있는 넷
(참여자 이동·삭제 / 데이터 있는 차수 삭제 / 갈무리 사진 삭제 / 전 차수 보기) 중
**무엇을 운영자 메뉴로 옮길지** 정해 주십시오. 옮기면 인도자 콘솔의 동작이 바뀝니다.

**아직 아무것도 고치지 않았습니다.** ㉮㉯㉰ 만 답해 주시면 N-1 부터 착수합니다.
