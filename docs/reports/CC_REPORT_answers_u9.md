## 1. ② 「작성중 / 미작성」 — **절반만 이행했습니다**

### 「작성중」은 진단 응답에서 **만들 수 없습니다.** 근거 넷을 전부 적습니다(불변식 22).

| # | 막는 것 | 실측 |
|---|---|---|
| ⓐ | **RLS** | `response_drafts` 정책 **넷 어디에도** `is_cohort_coach`·`is_admin` 절이 없다 → **인도자 세션에는 0행**. 초안을 내보내는 DEFINER RPC 도 없다(마이그 67개 전수) |
| ⓑ | **계약** | `getDraft` 에 `userId` 인자가 없다 → 넓히면 **불변식 3**(지휘부 승인) |
| ⓒ | **신호 품질** | 서버 초안은 참여자가 **「중간 저장하고 나중에 이어서」 버튼을 눌러야만** 쓰인다. 자동 저장은 `localStorage` 뿐이라 **서버에 닿지 않는다** |
| ⓓ | **선례** | **ADR-167** 이 같은 3단계를 «제출된 응답만 온다»로 기각했고 지휘부가 수용했다. `groupModel.ts` 가 «**별건으로도 만들지 않는다** — 제출 전 초안을 보는 것은 **열람 범위의 성격이 다른 변경**»을 못박았고 잠금이 걸려 있다 |

**ⓒ 가 결정적입니다 — 앞의 둘을 다 고쳐도 남습니다.** RLS 를 열어도 화면에 뜨는 「작성중」은
*실제로 작성 중인 사람*이 아니라 ***「중간 저장」 버튼을 눌러 본 사람***입니다.
**잘못된 「작성중」은 없는 것보다 나쁩니다** — 「이 사람은 하고 있으니 독려하지 말자」는 판단을
근거 없이 만들어 내기 때문입니다.

> **갈무리가 3단계인 이유는 다릅니다.** `checkin_save` 가 **자동으로 서버에 쓰고**(`has_content` 를
> 쓰기 시점에 계산) `checkins_select` 가 담당 인도자·운영자를 포함합니다. **신호가 실하고 권한이 열려 있습니다.**
> 그래서 갈무리 화면은 이미 「제출 / 작성 중 / 미작성」을 그립니다.

⚠ 한 가지 덧붙입니다: 그 잠금(`group.page.test.ts`)은 **그룹 리포트 세 파일만** 뭅니다 —
회기 대시보드는 덮지 않습니다. 「잠금이 초록이니 이 자리는 열려 있다」로 읽으면 ⑨-a(창이 좁다)를 반복합니다.

### 그래서 **낱말 하나로 풀었습니다 — 「미작성」**

지적의 실제 표적은 「아직 안 함」이 **한 화면에 두 뜻**이라는 것이었고, 그것은 이름만 갈라도 풀립니다.
**새 문안이 아닙니다** — 갈무리 인도자 화면이 이미 쓰는 어휘입니다.

- 마무리 구획: 「아직 안 함 — …」 → **「미작성 — …」**
- 명단 묶음: 「아직 안 함」 **그대로**(응답 0건 — 다른 뜻)

## 2. ③ 마무리는 **「시작」**입니다

사전은 «풀다 만 것을 이어서» 라 「이어 하기」가 맞지만, 마무리는 **방금 열린 것**입니다.
한 번도 시작하지 않은 사람에게 「이어 하기」는 **없던 일을 있었다고 말하는 것**입니다.

**역시 새 문안이 아닙니다** — 체크 허브가 마무리에 **이미 「시작」**을 쓰고 있었습니다.
같은 대상을 두 화면이 다르게 부르던 **사본도 함께 풀렸습니다**.

## 3. **U-8 이 만든 중복을 걷었습니다** — 반증자가 잡았습니다

개시 뒤 「마무리 체크」가 **한 화면에 둘**이었습니다 — 관리 패널의 「개시됨」 뱃지와
본문 독려 구획의 제목이 같은 `TOOL.post` 입니다. 개시는 **단방향**이라 열린 뒤 패널에 남는 것은
**아무 동작도 없는 뱃지**뿐이고, 「열렸다」는 사실은 **본문 구획이 서 있는 것 자체로** 말합니다.
→ **개시 뒤에는 패널의 마무리 줄을 걷습니다.** 개시 전에는 그대로입니다.

# 6. 검토 요청에 대한 의견 — **관리 패널과 본문**

> 「회기의 인도자 홈에서 보이는 것은 '그룹리포트와 사전응답보기'이다. 상단의 관리 버튼을 누르면
> 관리화면이 토글되는데 이름, 소개 등의 화면이다. 그런데 그 화면 아래에 그룹리포트, 사전응답
> 메뉴가 연이어 나온다. 두번째 화면에 이미 통합되어 있는데 이 두 화면을 따로 가져갈 필요가 있을까?」

## 결론부터 — **합칠 「두 화면」이 없습니다.**

관리는 별도 화면이 아니라 **본문 머리에 끼어드는 토글 패널**입니다.
본문(3숫자 → 그룹 리포트 → 마무리 → 명단 → 참여 코드)은 `manageOpen` 을 **읽지 않고 항상** 그려집니다.
열면 본문이 **사라지는 것이 아니라 패널 높이만큼 아래로 밀립니다.**

**「그 화면 아래에 연이어 나온다」고 보신 것은 두 번째 사본이 아니라 밀려 내려간 원래 본문입니다.**

| | 관리 패널(접힘) | 본문(항상) |
|---|---|---|
| 담기는 것 | 이름 · 소개 · 정원 · **마무리 개시** · 마감 · 삭제 | 3숫자 · 그룹 리포트 · 마무리 독려 · 명단 3묶음 · 참여 코드 |
| 겹치는 것 | **없습니다** (「마무리 체크」 하나가 겹쳤고 이번에 걷었습니다) | |

## 그런데 그렇게 읽히신 데는 이유가 **셋** 있었습니다

1. **진짜 중복이 하나 있었습니다** — 「마무리 체크」. **제가 U-8 에서 만들었고 이번에 걷었습니다.**
2. **패널이 본문 «머리»에 낍니다** — 열면 본문 전체가 아래로 밀려 「다른 화면으로 갔다」로 읽힙니다.
3. **열림 표시가 없습니다** — 「관리」 버튼 라벨이 열려도 그대로이고 `aria-expanded` 도 없어,
   **지금 무엇이 열려 있는지가 화면 어디에도 없습니다.**

## 그리고 이름과 실물이 어긋난 자리 하나 — **「사전 응답 보기」**

그런 이름의 메뉴는 **저장소에 없습니다.** 그 자리는 **명단 행 → 개인 리포트**입니다.
그런데 그 리포트는 **사전 고정이 아닙니다** — 명단이 싣는 것은 그 사람의 **돌봄 표시 응답, 없으면 최신 응답**이고
wave 를 가르지 않습니다. 즉 **마무리 개시 뒤에는 같은 행이 사후 리포트를 엽니다.**
「사전 응답」으로 알고 누르면 다른 것이 열립니다.
