불변식 22 대로 **근거를 전문 인용하고 각각 따로 판정한다.**

> **`subtitle` 은 표가 들지 않고 본문이 든다**(최박사 결재 2026-09-01). 차수 이름·비교 문구는

> 비교 문구를 **본문 첫 줄**에 그린다. **헤더 부제 통로가 서면 U-4 에서 옮길지 판단한다** —
> 지금은 통로가 없고, 통로를 만드는 것은 새 기제라 이 회차의 범위가 아니다.
> — `src/app/_lib/screenChrome.ts:133-139`

> ⚠ **`subtitle` 은 자리만 있고 쓰지 않는다.** 인도자 부제는 최박사가 **본문 첫 줄**로
> 직접 고르셨고(§2), 통로가 생겼다고 코드가 헤더로 되돌리면 **확정을 코드가 뒤집는 것**이다.
> — `src/app/_screens/shell/chromeContext.tsx:18-21` (U-4 판)

**판정 셋.**

| # | 근거 | 판정 |
|---|---|---|
| ⑴ | 「`subtitle` 은 표가 들지 않는다」 | **지켰다.** U-5 는 `subtitle` 을 쓰지 않는다. 회기 이름은 `SCREEN_CHROME` 표를 지나지 않고 **회기 레이아웃이 직접** 그린다 |
| ⑵ | 「본문이 든다」 | **지켰다.** `/matrix`·`/values` 의 **본문 첫 줄 회기 이름을 지우지 않았다** — 최박사가 직접 고른 줄이라 재가 없이 코드가 지울 자리가 아니다 |
| ⑶ | 「통로가 서면 옮길지 판단한다」 | **판단이 유보된 지점이고, 지휘부가 그 판단을 내렸다.** 다만 칩은 부제가 아니라 **문**(누르면 회기 목록)이라 성질이 다르다 |

**그래서 남는 것 — 실측.** `/coach/cohort/…/matrix` 와 `/values` 두 화면에서
**회기 이름이 두 곳(띠 칩 · 본문 첫 줄)에 보인다.**
(`/group` 은 본문에 회기 이름이 없어 해당 없음 — 실측으로 확인했다.)

> **재가 청구**: 그 두 화면의 **본문 첫 줄을 지울지**, 아니면 **칩을 그 두 화면에서만 뺄지**.
> 어느 쪽이든 한 줄 변경이고, 지금 상태(둘 다 보임)는 **되돌리기 쉬운 쪽**이라 그대로 두었다.

## 1. 무엇을 했는가

**띠 셋 → 둘.** 벨트 + 제목바 + 탭 줄이었다. 지휘부 지적이 정확했다 —
*「2열이 없어도 3열에서 현재 위치가 표시되는데?」* 탭이 이미 «지금 어디»를 말한다.

| 제목바가 들던 것 | 어디로 갔는가 |
|---|---|
| 제목 | 회기 안은 **탭**, 회기 밖은 **본문 첫 줄**(`.console-title`). 이름은 여전히 `SCREEN_CHROME` 표에서만 온다 |
| 뒤로 | **폐지**(결재) |
| 도구(`HeaderActions`) | **시트**. 「내 정보」는 계정 구획 |
| 햄버거 | **벨트 하나로** — 전에는 한 화면에 문이 둘이었다 |

**회기 띠** = 회기 칩(왼쪽 고정) + 탭(오른쪽 흐름). 칩은 부제가 아니라 **문**이고
누르면 `/coach/cohorts` 로 간다(결재 물음 1 답).

**시트**는 참여자와 같은 네 구획 — 「내 자리」·「인도자」·「자료」·「계정 + 로그아웃」.
「운영」은 「내 자리」에 합쳤고 「내 홈」은 뺐다(인도자의 홈이 곧 그 화면이다).

## 2. 설계에서 바꾼 것 하나 — **통로를 안 쓰고 회기 레이아웃이 그린다**

시안은 회기 이름을 `chromeContext` 통로로 껍데기에 올리는 그림이었다. **실측으로 버렸다.**

- 통로는 `useEffect` 로 값을 얹는다 → **첫 그림에 이름이 없다.**
  칩이 한 프레임 뒤에 끼어들며 **탭을 오른쪽으로 민다.**
- `/coach/layout.tsx` 는 `[cohortId]` 세그먼트 **위**에 있어 Next 16 이 params 를 주지 않는다
  (저장소의 어떤 layout 도 params 를 읽지 않는다 — 실측). 그래서 값이 위로 갈 길이 통로뿐이었다.
- **세그먼트 안쪽에 레이아웃을 두고 거기서 띠를 그리면** 이름이 **서버 HTML 에 실린다.**
  깜빡임도 밀림도 없고, **최박사 결재가 걸린 파일을 한 줄도 건드리지 않는다.**

**대가**: 단일행 `cohorts` select 왕복이 회기 화면마다 하나 는다(그 아래 여덟 중 일곱은
이미 각자 `getCohort` 를 부르므로 같은 렌더에서 두 번이 된다). 합치려면 화면들을
`requestScope` 로 옮겨야 하고 그것은 이 회차의 범위가 아니다 — **판단 청구 항목**이다.

## 4. 곁가지로 잡은 결함 셋

1. **`tests/chromeContext.test.tsx` 가 없었다.** `chromeContext.tsx:21` 이
   *「그 테스트가 아무도 쓰지 않음을 잠근다」* 라고 적는데 `git log --all` 이 **빈 출력**이다.
   **잠금이 없는데 잠금이 있다고 적혀 있었다** — ⑦ 계열의 한 층 아래다(초록조차 없이 문장만).
   하마터면 **없는 제약에 설계를 맞출 뻔했다.** U-5 가 그 파일을 실제로 지었다.
2. **그 문장 자체도 거짓이었다.** 새 잠금을 저장소 전체에 걸자 **곧바로 붉어졌다** —
   `/join` 이 단계 부제를 `subtitle` 로 넘기고 있다. 결재문이 든 것은 *「차수 이름·비교 문구」*
   였으므로 **틀린 것은 결재가 아니라 주석**이다. 창을 인도자 화면으로 좁히고 주석을 고쳤다.
   `/join` 은 이제 **대조군**이다 — 자가 실물에서 실제로 무는지를 그것이 증명한다(⑧).
3. **회기 0 인 인도자 시트에 「참여 신청」이 떴다.** `noCohort` 가 역할을 안 봤다.
   지휘부 정의(*「회기 0 인 사람들은 가입은 했지만 세미나 참여신청을 하지 않은 사람들」*)는
   **참여자**에 대한 것이었다. 인도자에게는 아무 문도 두지 않는다(빈 목록으로 보내지 않는다).

그리고 **사본 둘**을 합쳤다 — `coach/layout.tsx` 와 `admin/layout.tsx` 가 머리 주석 한 줄만
다르고 나머지가 한 글자도 같았다. `ConsoleLayout` 하나로 모았다.
`export … from` 으로 넘겼더니 **`shellAudit` 의 전이 추적이 껍데기를 못 봐** 무헤더 라우트가
5 → 18 로 늘었다(문서가 거짓이 될 뻔했다). **드러내 감싸도록** 되돌렸다.
