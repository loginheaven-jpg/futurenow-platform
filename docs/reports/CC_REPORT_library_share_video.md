## 2. 설계서를 읽고 나서 설계가 바뀐 것 — 셋

정찰 전에는 「목록에 썸네일을 그리려면 `LibraryItem` 에 칸을 더해야 하고 그것은 불변식 3 이다」로
가고 있었습니다. 마이그레이션 롤백 문까지 써 두었습니다. **설계서가 그 전부를 무르게 했습니다.**

### 2.1 ③ 은 목록이 아니라 **상세**다 → 계약 변경이 사라졌다

> 설계서 §4.2 — 「`kind='video'` 는 **상세에서 그린다.** 목록에는 영상 id 가 실리지 않는다」

상세 화면은 `openLibraryItem` 이 관문을 지난 뒤 `url` 을 **이미 손에 들고 있습니다.**
그러므로 계약을 넓힐 이유가 없습니다. **써 두었던 마이그레이션과 롤백 문을 버렸습니다.**
불변식 3 을 건드리지 않았고 목록은 한 글자도 바뀌지 않았습니다.

### 2.2 「누르기 전 유튜브 요청 0회」가 수용 기준이다 → 프록시가 필요하다

> 설계서 §4.2 · 발주 §6.3 — 「영상 재생 : 누르기 전 유튜브 요청 **0회** · 누른 뒤 재생」

`<img src="https://i.ytimg.com/…">` 를 박으면 **화면을 여는 것만으로** 방문자 IP·Referer 가 구글로 갑니다.
서가는 비로그인도 보는 화면이라 그 대상이 «자료를 누른 사람» 이 아니라 **«지나간 사람»** 입니다.
그래서 `/library/[id]/thumb` 를 세워 서버가 받아 **바이트로 흘립니다** — `[id]/file/route.ts` 를 글자 그대로 본떴습니다.

### 2.3 ① 은 「주소가 하나」다

> 설계서 §6.1 — 「자격에 따라 다른 주소를 만들지 않는다. 주소가 자격을 담으면 그 주소가 곧 열쇠가 되고,
> 카톡으로 옮겨 다니는 열쇠는 막을 방법이 없다」

토큰·서명이 붙을 자리가 없습니다. 잠금이 그것까지 잽니다.

### 6.3 ★ 설계서와 as-built 가 갈린 자리 — 손대지 않았습니다

설계서 §6.2 ④ 는 **비로그인 → `/login?returnTo=/library/{id}` → 그 자료로 착지**를 정합니다.
그런데 as-built 는 못 보는 자료에 **`notFound()`** 를 냅니다 — 서가 A 가
*「«없다» 와 «못 본다» 를 한 얼굴로 답한다 — 존재를 알리지 않는다」* 로 **다르게** 지었습니다.

- **공개 등급은 왕복이 이미 돕니다**(로그아웃도 보므로). 지금 서가 자료 셋이 전부 공개 등급입니다.
- **포럼·인도자 등급은 404 입니다.** 링크를 받아도 로그인 화면이 아니라 404 를 봅니다.

설계서는 「`safeReturn.ts` 에 두 줄을 더하는 것이 전부」라 했으나 **as-built 에서는 성립하지 않습니다** —
`/library` 가 `PROTECTED_PREFIXES` 에 없어 프록시가 `returnTo` 를 애초에 붙이지 않고,
목적지도 잠금 화면이 아니라 404 입니다. 그래서 **두 줄을 더하면 죽은 코드가 됩니다.**

**넣지 않았습니다.** 설계서 자신이 *「먼저 올리면 통과는 되는데 목적지가 404 다」* 라고 경고한 자리이고,
`notFound()` 를 리다이렉트로 바꾸는 것은 **「존재를 알리지 않는다」를 뒤집는 판정**이라 제 몫이 아닙니다.
**잠금 화면을 만들 것인가**가 결정되면 그때 라우트와 **같은 커밋**에 올리겠습니다.

## 9. 실행으로 잰 검증 (배포 후 · 2026-08-31)

**정적 검사로는 「누르기 전 유튜브 요청 0회」를 못 잰다** — 그것은 런타임 행동이다(계열 ⑨-c).
그래서 실브라우저로 열고 **나가는 요청을 전부 세어** 판정했다.

- 병합 `b78f82b` · `git ls-remote origin main` → `b78f82bd3fdb7d96cc1c8fa8d184e2dc48871de1`
- 배포 `/api/version` → `b78f82b` · `env=production` · `node scripts/postdeploy.mjs` 전항 통과

### 9.1 ③ 얼굴판 — 급소가 지켜졌다

```
O 목록 /library        유튜브 요청 0회 · HTML 에 영상 id 없다
O 자료 화면(누르기 전) 유튜브 요청 0회 · 우리 썸네일 1개
     「링크 복사」있다 · 「재생」있다 · 「새 창에서 보기」있다
O 썸네일 프록시        200 · image/jpeg · 16,271바이트 · private, no-store
O 누른 뒤              iframe https://www.youtube-nocookie.com/embed/p8HDt61uMfA?…
O 없는 자료 썸네일      404 (존재를 알리지 않는다)
```

**목록 HTML 에 영상 id 가 0건**이다 — 설계서 §4.2 의 「목록에는 영상 id 가 실리지 않는다」가
문자열로 확인됐다(화면에 안 보이는 것과 HTML 에 없는 것은 다르다 · 발주 §6.2 가 그것을 요구했다).

**자가 한 번 잘못 쟀다** — 「누른 뒤 유튜브 요청 0회」로 찍혔는데 **그것은 내 자의 오류다.**
`waitForSelector('iframe')` 직후에 셌고 iframe 로드를 기다리지 않았다. 판정 기준은 **「누르기 전」**
이고 그쪽은 `networkidle` 까지 기다려 제대로 쟀다. **잰 값을 그대로 적고 무엇이 틀렸는지 밝힌다.**

### 9.2 ② 제목 자동 입력 — 실제로 채워진다

```
제목 칸  : 「꿈을 프로젝트로 구체화하라」
POST 수  : 1 회 (blur 한 번이므로 1이어야 한다)
덮어쓰기 : 안 한다 O
추적자   : 안 새어 나왔다 O
```

- **재호출 1회** — U-4 의 초당 37회를 되풀이하지 않는다. `onBlur` 한 번이다.
- **사람이 쓴 제목을 덮지 않는다** — 「내가 쓴 제목」을 넣고 다른 주소를 물려 봤더니 그대로였다.
- **추적 파라미터가 새지 않는다** — `?si=TRACKER` 를 넣었는데 제목 어디에도 없다.
  나가는 주소를 **우리가 다시 조립**하기 때문이다.

### 9.3 ① 링크 복사

자료 화면에 단추가 서고 복사 대상은 `${origin}/library/{id}` 하나다(잠금이 오리진 박기를 막는다).
**클립보드 자체는 브라우저 권한이라 자동으로 재지 않았다** — 실패 경로(`navigator.clipboard` 부재)는
정적 잠금이 «주소를 화면에 띄우는가»로 잰다. 손으로 확인하실 자리다.

- **부재 부품 셋**(§6.2) — 복사 단추·영상 카드·재생 아이콘.
- **설계서 §6.2 로그인 왕복**(§6.3) — 잠금 화면을 만들 것인가가 결정되면 라우트와 같은 커밋에 올린다.
