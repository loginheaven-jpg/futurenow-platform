## 2. 한 것 다섯

| | 무엇 | 왜 |
|---|---|---|
| ⑴ | 직렬 조회 둘을 `Promise.all` 로 | 서로를 인자로 쓰지 않는데 줄을 서 있었다 |
| ⑵ | **따라갈 수 없는 링크를 미리 받지 않는다** | ADR-175 의 **발원지** |
| ⑶ | 끊겨 있던 참여자 딥링크 넷을 이었다 | 프록시는 싣는데 소비 쪽이 버렸다 |
| ⑷ | **속도 상한을 실행 잠금으로** | 속도를 재는 잠금이 **하나도 없었다** |
| ⑸ | 전집합 실측 | 「어떤 경로로도」는 세어 봐야 안다 |

**⑴ 에서 인증 게이트는 그대로 앞에 둡니다**(불변식 19 — 게이트가 먼저).
병렬로 묶은 것은 게이트 **뒤**의 조회뿐이고 당겨오는 것은 **본인의 차수**입니다(RLS).
잠금이 «조회가 게이트보다 앞에 오면» 붉어집니다.

## 4. ★ 딥링크 넷이 실제로 끊겨 있었습니다

프록시는 보호 경로 **전부**에 `?returnTo=` 를 싣는데(`loginRedirectSearch`)
소비 쪽 화이트리스트(`safeReturn.ts`)가 버리고 있었습니다.

| 딥링크 | 고치기 전 | 고친 뒤 |
|---|---|---|
| `/account` | ★ 엉뚱한 곳 | **O 0.9초 도착** |
| `/my/cohorts/{id}/journey` | ★ 엉뚱한 곳 | **O 0.8초 도착** |
| `/my/cohorts/{id}/report` | ★ 엉뚱한 곳 | **O 0.8초 도착** |
| `/my/cohorts` | ★ 엉뚱한 곳 | **O** — 아래 주 참조 |
| `/my/cohorts/{id}` | 「도착」처럼 보임 | **O 0.8초 도착** |

> ★ **자가 두 번 속았습니다.**
> ⑴ `/my/cohorts/{id}` 는 고치기 전에도 「도착」으로 찍혔는데 **그 사람의 착지가 마침 같은 주소**였을 뿐입니다.
> ⑵ `/my/cohorts` 는 고친 뒤에도 차수 홈으로 갑니다 — 그건 **그 화면 자신의 규칙**입니다
>   (`page.tsx:18` 「차수 1개면 목록은 불필요한 경유」). `returnTo` 는 살아서 도착했고 그 뒤에 옮겨 간 것입니다.

**`/coach` · `/admin` · `/preview` 는 일부러 뺐습니다** — 막혀서가 아니라 **정책이라서**입니다(§8 결재 청구).
잠금이 «살아남는 것»과 «일부러 뺀 것»을 **한 표에** 두어, 뺀 것이 통과해도 붉어집니다.

## 6. ★ 정직하게 — **⑴ 은 눈에 띄는 값을 못 냈습니다**

직렬을 병렬로 묶은 뒤 서버액션은 **290ms → 262~334ms** 로 흔들림 안입니다.
**측정 가능한 이득이 없습니다.** 변경 자체는 옳지만(의존 없는 것을 줄 세우지 않는다)
**속도가 좋아졌다고 적지 않습니다.**

지금 남은 무게는 ⑴ 이 아니라 **§7 ⒜ 의 중복 조회**입니다 — 그것이 착지 문서 400~520ms 안에 있습니다.

## 7. ★ 관측했으나 **손대지 않은 것 셋** — 발주를 청합니다

| | 무엇 | 왜 안 했나 |
|---|---|---|
| ⒜ | 레이아웃과 페이지가 **각자 `createServerContext()`** 를 불러 `users` SELECT·동의·차수가 **한 화면에 두 번씩** 돈다(캐시가 인스턴스 단위라 안 듣는다) | 처방은 core 한 곳(`cache()`)이지만 **파급이 넓다.** §3 규율대로 **범위를 먼저 보고하고 승인받는다** |
| ⒝ | 운영자 `/coach` 의 `listUsers` 가 **1+2N 왕복**을 인도자 이름 맵 하나에 쓴다 | 로그인 길이 아니라 **그 화면의 문제**다. 별건 |
| ⒞ | `loadCurrentUser` 가 프록시 헤더 경로에서 프로필이 없어도 **`null` 이 아니라 합성 객체**를 낸다 | 그래서 서버 게이트 `if (!me) redirect('/login')` **26곳이 사실상 발화하지 않는다.** 코치 프로필 조회가 비면 `role:'user'` 로 내려앉아 `/coach` 에서 튕길 수 있다. **core 이고 보안 성격이라 손대지 않았다** |

⒞ 는 ADR-175 의 첫 가설(「25곳에 `returnTo` 를 달자」)이 **왜 원인이 아니었는지**도 설명합니다 —
그 줄들은 애초에 발화하지 않습니다.

## 8. ★ 결재를 청합니다

1. **`/coach` · `/admin` · `/preview` 를 `returnTo` 화이트리스트에 넣을 것인가.**
   지금은 뺐습니다. 넣으면 인도자·운영자도 딥링크로 로그인해 제자리로 갑니다.
   **오픈 리다이렉트 위험은 없습니다**(내부 경로 · 앵커 고정 · 외부 차단은 그대로).
   위험이 아니라 **정책**이라 올립니다.
2. **§7 ⒜ 의 core 캐시 처방** 착수 여부(범위 보고 후 승인 규율).
3. **운영자 역할은 재지 못했습니다** — QA 계정에 운영자가 없습니다(`.env.local` 에 `QA_ADMIN_*` 없음).
   case 4 는 **단위 잠금으로만** 확인했습니다. 실측이 필요하면 QA 운영자 계정을 주십시오.
