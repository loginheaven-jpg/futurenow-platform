## 1. ★★ ② 는 **제 전 회차 권고의 위치가 틀렸습니다**

ADR-176 §7 ⒜ 에 「처방은 core 한 곳(`cache()`)」이라 적었습니다.
**정본을 읽어 보니 core 에 두면 조용히 깨집니다.**

| | 왜 core 가 아닌가 | 무엇이 조용한가 |
|---|---|---|
| ⑴ | `src/core/context.ts` 는 **서버·클라이언트 공용**이다(`ConsentGate`·`SignupClient`·`JoinClient`·`CoachInfoGate` 가 브라우저에서 `createCoreContext` 를 만든다) | 비-react-server 빌드의 `cache` 는 **경고도 에러도 없이 순수 통과**다. 서버는 묶이고 **브라우저는 메모를 통째로 잃는다.** 타입으로도 초록으로도 안 잡힌다 |
| ⑵ | `createServerContext(options)` 는 **인자를 받는다.** 넘기는 곳은 `join/actions.ts` 하나 | 인자를 떨어뜨린 래퍼를 두면 `validators` 가 사라지는데 `validateWith` 는 스키마가 없으면 **예외도 로그도 없이 원값을 통과**시킨다 — **§9 zod 경계가 초록인 채로 빈다** |

그래서 **core 를 안 고치고** `src/app/_lib/requestScope.ts` 를 앱 층에 뒀습니다.
**「승인받았으니 적힌 대로」가 아니라 「승인받은 목적을 안전한 자리에서」** 이행했습니다.

### 1.1 정본에서 확정한 사실 (next 16.2.9 · react 19.2.4)

- **메모 범위는 「요청」이 아니라 「렌더 패스」다.** 문서가 두 어휘를 섞어 쓰지만 구현이 정본이다.
- **서버 액션·라우트 핸들러에서는 메모가 아예 안 된다**(Flight Request 가 없어 호출마다 새 Map).
  → 그래서 **「변이 뒤 같은 컨텍스트로 재조회」하는 피드·소식 액션 여섯에 이 처방은 닿지 않는다.**
  닿는 것은 **인스턴스 필드 메모를 조회 메서드로 넓히는 쪽**이고 **그것은 하지 않았다.**
- **에러 재렌더는 같은 HTTP 요청에서 두 번째 Flight 스트림을 만든다** → **로더 안에 부수효과를 두지 않는다**(잠금이 잰다).
- `cache()` 는 **거절도 메모한다** — 화면이 새 컨텍스트로 **우연히 회복되던** 경우가 없어진다.
  **알고 받아들였습니다.** 실패가 한 번으로 끝나고 정직하게 드러납니다.
- **삼킴 성질을 부르는 자리에 남겼습니다** — 껍데기는 차수 조회를 삼키고 홈은 안 삼킵니다.
  로더가 대신 삼키면 그 차이가 사라집니다(성질을 파생하지 않는다 · U-4 형태).

## 2. ★ ② 의 이득은 **잴 수 있는 크기가 아니었습니다**

| | `/home` (고친 것) | `/home/assessments` (안 고친 대조군) |
|---|---|---|
| 고치기 전 (N=7) | 중앙 432ms (342~912) | 중앙 341ms |
| 고친 뒤 (N=7) | 중앙 395ms (347~642) | 중앙 361ms |

**대조군도 같은 폭으로 움직였습니다 — 소음입니다.**

그래서 **판정할 수 있는 자로** 다시 쟀습니다(교대 표본 N=21, 같은 시점 둘을 짝지어 뺌) :

```
  /home             중앙 332ms · 하위25 324 · 상위75 346 · 최소 316
  /home/assessments 중앙 329ms · 하위25 321 · 상위75 351 · 최소 315   (안 고친 대조군)

  짝지은 차이 중앙 = 2ms · 하위25 -13 · 상위75 13
```

**소음 바닥이 ±13ms 인 자에서 차이가 2ms 입니다.**
`/home` 은 대조군보다 **하는 일이 더 많은데도**(소식·피드 기수·갈무리·회차) 같게 나옵니다 —
시사적이지만 **통제된 앞뒤 대조가 아니므로 이득을 주장하지 않습니다.**

**이 변경은 속도가 아니라 「같은 것을 두 번 묻지 않는다」는 옳음 위에 섭니다.**
DB 왕복이 착지마다 셋 줄어든 것은 사실이고, **그 값이 응답 시간에서 보이지 않는 것도 사실**입니다.

### 2.1 그래서 **열둘로 넓히지 않았습니다**

ADR-178 에 「이 짝의 실측 이득을 보고 정한다」고 적었고, **이득이 소음 아래**였습니다.
나머지 회원 화면 열 곳으로 넓히면 파일마다 두 줄씩 바뀌는데 **잴 수 없는 것을 위해 그 차이를 만들지 않습니다.**
DB 부하 관점의 근거는 남아 있으므로 **판단이 필요하면 올려 주십시오**(§6).

## 3. ① 권한 딥링크 — 실측

```
  coach · /coach             O 0.8초  → /coach
  coach · /coach/cohorts     O 0.8초  → /coach/cohorts
  coach · /coach/new         O 0.8초  → /coach/new
```

★ **경로를 손으로 열거하지 않았습니다.** 실물이 열여덟인데 적는 순간 낡고,
**라우트가 느는 날 딥링크가 조용히 끊깁니다 — 그것이 방금 고친 결함 자체입니다**(§11 ⑴).
**접두사 + 세그먼트 모양**으로 재고, **잠금이 저장소를 걸어 실제 라우트를 전부 먹입니다.**
동적 세그먼트는 실제 uuid 로 바꿔 먹입니다. 패턴을 벗어나는 라우트가 생기면 **잠금이 먼저 웁니다.**

**넓혀도 오픈 리다이렉트가 아닙니다** — 앞이 `/` 단일로 고정이고,
**갈 자격은 목적지 자신의 게이트가 판정합니다.** 화이트리스트가 자격을 대신 판정하지 않습니다.

## 4. ★★ 잠금이 **제가 만든 구멍**을 잡았습니다

허용 글자에 `.` 을 넣었더니 **`/coach/../admin` 이 통과**했습니다.
내부 경로라 오픈 리다이렉트는 아니지만 **경로 탈출 시늉을 받아 줄 이유가 없어** 뺐습니다
(실제 라우트 열여덟에 점이 하나도 없습니다).

### 4.1 그리고 **물려 보고 배운 것** — 명시 외부 차단 줄은 오늘 아무것도 안 막습니다

`//`·백슬래시·`://` 를 막는 줄을 **지우고 재도 초록**이었습니다.
그것은 「막지 못한다」가 아니라 **「막을 것이 없었다」**입니다 —
정규식이 전부 `^/` 로 고정이라 외부 꼴은 애초에 아무 패턴도 안 맞습니다.

**그러면 지켜야 할 것은 그 줄이 아니라 「전부 고정되어 있다」는 성질**입니다.
그것을 잠갔습니다(패턴마다 앞 고정 · 끝 닫힘 · 이중 슬래시 금지).
**명시 줄은 그대로 뒀습니다** — 느슨해지는 날의 뒷받침입니다.

### 5.1 ★★ 잠금이 **네 번 층을 잘못 잡았고** 넷 다 고쳤습니다

| 안 문 잠금 | 왜 | 어떻게 고쳤나 |
|---|---|---|
| 「앞이 고정됐는가」 | **`/^` 로 시작하는 줄만 골라** 고정 안 된 패턴이 **창 밖으로 떨어졌다**(⑨-a) | 정규식 줄 **전부**를 본다 |
| 「한 번만 부르는가」(행동) | **vitest 가 클라이언트 React 를 풀어 `cache` 가 통과** — **거짓 빨강**이 났다 | 그 사실 자체를 박았다. `cache` 가 memo 를 하기 시작하면 **그 잠금이 운다** |
| 「팩토리를 우회하는가」 | 우회하든 아니든 **호출 수가 같아** 못 가른다 | 이 환경에 행동 창이 없으므로 **구조로**(아래로 내려가는 문이 하나인가) |
| 그 구조 셈 | **주석의 언급까지 세어** 깨끗한 파일에서 3이 나왔다 | 주석을 걷고 **코드만** 센다 |
| 외부 차단 줄 | 지워도 초록 — **막을 것이 없었다** | 줄이 아니라 **성질**을 잠갔다 |

**옛 잠금 넷은 지우지 않고 새 사실로 옮겨 적었습니다** —
`/admin` 을 「막히는 예」에서 「허용」으로 옮겼고, 그 줄이 지키던 것은 「권한 화면 금지」가 아니라
**「목록에 없으면 버린다」**였으며 그것은 그대로입니다(예를 여전히 목록 밖인 값으로 바꿨습니다).
무차별 치환이 **운영자 카드 주소까지** 바꿔 놓은 것도 잠금이 잡아 되돌렸습니다.

## 6. ★ 남은 것 — 판단을 청합니다

1. **운영자 실측이 여전히 막혀 있습니다.** QA 운영자 계정이 없습니다(`.env.local` 에 `QA_ADMIN_*` 없음).
   case 4 착지와 `/admin` 딥링크는 **단위 잠금으로만** 확인했습니다. 계정을 주시면 실측하겠습니다.
2. **요청 스코프를 나머지 회원 화면 열 곳으로 넓힐 것인가** — **속도 근거는 없습니다**(§2).
   DB 왕복이 화면마다 하나씩 주는 근거만 남습니다.
3. **`loadCurrentUser` 의 합성 객체**(ADR-176 §7 ⒞) — **여전히 손대지 않았습니다.**
   이번에 처방을 검토하다 **되돌이 위험**을 하나 더 찾았습니다:
   조회 실패에 `null` 을 내면 게이트가 `/login` 으로 보내는데, `/login` 은 세션이 살아 있으면
   **다시 그 화면으로 돌려보냅니다** — **고리가 됩니다.** 그래서 「에러면 null」은 안전한 처방이 아닙니다.
   **손대려면 되돌이를 끊는 설계가 먼저**입니다. 발주를 청합니다.
