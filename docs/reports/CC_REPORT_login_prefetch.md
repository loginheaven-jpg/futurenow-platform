## 1. ★★ 제 첫 가설은 **측정이 기각했습니다**

N-1 보고서에 「원인은 `/home/assessments/page.tsx:28` 의 `redirect('/login')` 로 보입니다」라고
적었습니다. 되는 쪽(`/feed`)과 안 되는 쪽의 **유일한 차이가 `returnTo` 유무**였기 때문입니다.

```
redirect('/login')                     25곳
redirect('/login?returnTo=/feed')       1곳   ← 되는 쪽
```

그래서 `/home/assessments` 에도 `returnTo` 를 달아 **배포하고 다시 쟀습니다.**
**여전히 못 갔습니다.** → **되돌렸습니다**(`27ade52`).

**고치기 전에 배포해서 재지 않았다면 틀린 처방을 정본에 박을 뻔했습니다.**

## 2. 원인 — 게이트가 아니라 **캐시**였습니다

추측을 멈추고 계기를 달았더니 망 기록이 답을 줬습니다.

```
[/home/assessments] ★ 못 감
   URL  /login?returnTo=%2Fhome%2Fassessments
   망   307 /home/assessments?_rsc=…  |  FAIL /library?_rsc=…  |  FAIL /news?_rsc=…  …
```

**`307 /home/assessments?_rsc=…` 가 로그인 화면이 열리는 순간 이미 찍혀 있습니다.**

1. 미인증으로 `/login` 을 연다
2. 벨트의 「진단」(`/home/assessments`) 링크를 Next 가 **프리페치**한다
3. 미들웨어가 미인증이라 **307 로 로그인으로 되돌린다**
4. **그 응답이 라우터 캐시에 남는다**
5. 로그인 뒤 그리로 가면 **캐시가 그대로 쓰여** 로그인 화면으로 돌아온다 — 영원히

`/feed` 는 **벨트에 없어** 프리페치되지 않았고, 그래서 캐시가 없었고, 그래서 멀쩡했습니다.

### 2.1 물려서 확인했습니다

`_rsc` 요청만 막고 나머지는 전부 그대로 둔 채 **3회씩**:

```
그대로        착지 0/3   못감 · 못감 · 못감      막은 요청 0/0/0
프리페치 막고   착지 3/3   1.0s · 0.8s · 0.8s     막은 요청 12/12/12
```

대조군도 맞습니다 — **벨트에 없는** 보호 화면은 프리페치가 안 돼 멀쩡했습니다
(`/feed` 1.3초 · `/my/values` 0.8초).

> ★ **첫 물림은 증거가 아니었습니다.** glob 패턴 `**/*_rsc=*` 로 걸었더니 **「막은 요청 0건」**인데
> 결과만 달라졌습니다. **변이가 안 심어졌는데 초록이 바뀐 것**이라 그 줄로는 아무 말도 못 합니다(계열 ⑧).
> URL 조건자로 다시 걸어 **12건을 실제로 막고** 3회씩 반복해서야 위 표가 나왔습니다.

**즉 「진단」이 벨트 메뉴 여섯 중 유일한 보호 화면이라 혼자 걸렸습니다.**
ADR-174 가 벨트를 넓힌 것과 무관하고, 공개 벨트에 그 링크가 있던 **내내** 그랬습니다.

## 3. 왜 문서를 새로 받는가

**신원이 방금 바뀌었으므로 그 전에 받아 둔 것은 전부 낡았습니다.**

어느 항목이 낡았는지 **골라내려면 추론해야 하고, 그 추론이 틀린 것이 바로 이 결함**입니다.
문서를 새로 받으면 추론할 것이 없습니다.

**고르지 않은 다른 처방들** :

| 대안 | 왜 안 골랐나 |
|---|---|
| 「진단」 링크에 `prefetch={false}` | **증상 하나만** 없앤다. 다음 보호 링크에서 재발한다 |
| `router.refresh()` 뒤 `router.replace()` | 무효화와 이동 사이에 경합이 남는다 |
| 25곳에 `returnTo` 를 단다 | **원인이 아니다**(§1에서 기각됨) |

`replace` 는 유지했습니다 — `assign` 이면 히스토리에 `/login` 이 남아
뒤로가기가 로그인 폼을 보입니다(4차 F-5 B행). 잠금이 그것도 잽니다.

## 4. ★ 창의 층을 맞췄습니다 (⑨-c)

**「프리페치 캐시를 쓰는가」는 런타임 행동이라 정적 검사로는 원리상 못 잡습니다.**
그래서 창을 둘로 나눴습니다.

| 층 | 무엇을 재나 | 어디 |
|---|---|---|
| **실행** | 진짜로 착지하는가 | `scripts/postdeploy.mjs` 실브라우저 착지 검사 |
| 정적 | 고친 것이 되돌아오는가 | `roleTarget.landing.test.ts` |

실행 검사는 **조건으로 끝나고 상한(25초)이 있고 넘기면 시끄럽게 실패**합니다.
자격이 없으면 **통과가 아니라 실패**로 적습니다 — 못 잰 것과 통과는 다릅니다.

### 4.1 ★★ 잠금 하나가 **안 물어서** 다시 만들었습니다

「`bad(` 가 있는가」로 물었더니 **같은 이름의 `bad(` 가 하나 더 있어**
`ok` 로 바꿔 심어도 초록이었습니다(⑬ — 「있는가」로 묻는 잣대는 의심 대상).

**catch 블록만 보도록** 창을 좁히자 붉어졌습니다.

### 4.2 물려 본 결과

| 변이 | 결과 |
|---|---|
| `router.replace` 로 되돌린다 | **붉어짐** |
| `window.location.assign` 으로 바꾼다(히스토리에 남음) | **붉어짐** |
| postdeploy 의 실행 창을 없앤다 | **붉어짐** |
| 못 잰 것을 `ok` 로 적는다 | **붉어짐** (창을 좁힌 뒤) |

## 7. ★ 관측했으나 **손대지 않은 것** — 발주를 청합니다

서버 게이트 **26곳 중 `returnTo` 를 다는 곳은 `/feed` 하나뿐**입니다.
나머지 25곳은 세션이 서버에 안 보이는 순간 **목적지를 잃습니다.**

**그런데 그 일이 실제로 일어난다는 측정이 없습니다.** 이번 결함은 다른 원인이었고,
없는 결함에 잠금을 걸면 **오측을 영구화합니다.** 그래서 고치지 않았습니다.

산출 : `grep -rn "redirect('/login')" src/app --include=*.tsx | grep -v '\.test\.'`

### 7.1 함께 관측한 것 하나 더 — 결함이 아니라 설계 결과입니다

`returnTo=/home` 으로 로그인한 참여자는 **`/home` 이 아니라 기수로 착지합니다.**
`outcome.redirect === LOGIN_HOME` 이라 착지 판정이 걸리기 때문입니다.

지시 case 1(「참여자 → 막바로 참여기수 메뉴로 진입」)과는 맞지만
「링크가 우선이다」와는 어긋나 보일 수 있습니다. **실사용상 문제는 없습니다** —
로그인한 뒤 시트의 「내 홈」을 누르면 `returnTo` 없이 직접 이동이라 홈에 머뭅니다(실측).
판정이 필요하면 올려 주십시오.
