## 2. 왜 폭으로 가르는가 — 그리고 왜 CSS 로 가르는가

폰은 이미 메뉴가 시트 안이라 두 겹이 **얻는 것 없이 세로만 먹습니다**
(벨트 44 + 제목바 40 = 84px, 844px 화면의 10%). 그래서 **lg↑ 에서만** 겹칩니다.

**가르기는 CSS 가 합니다.** 트리를 폭에 따라 바꾸면 껍데기의 「트리 모양을 바꾸지 않는다」가
깨집니다 — U-4 재마운트 사고(5초에 `<main>` 175회 · 초당 37회 POST · 503)가 그 자리에서 났습니다.
**늘 그리고 CSS 가 감춥니다.** 트리가 한 벌이라 **JS 가 0** 이고 하이드레이션이 어긋날 자리가 없습니다.

벨트는 **`head` 슬롯 안**에 들어가 `{children}` 의 자리가 한 칸도 안 움직입니다. 잠금이 그 모양을 잽니다.

## 3. ★★ 배포해서 잡은 것 — 한 화면에 여는 문이 둘이었다

잠금 아홉이 초록이고 네 지표도 전항 통과인 채로 배포했더니
**`/my/cohorts` 에 햄버거가 둘**이었습니다(벨트 + 제목바).

콘솔에는 처음부터 시트를 안 넘겼는데 **회원 껍데기만 빠뜨렸고**,
**그 잠금을 콘솔에만 걸어 둔 것이 놓친 원인**입니다. 둘 다 재도록 넓혔습니다.

### 3.1 그런데 넓힌 잠금이 **안 물었습니다**

변이를 심어도 초록이었습니다. `indexOf('belt-slot')` 이 **주석에 있는 그 낱말**에 걸려
창이 실제 JSX 를 한 번도 안 덮었습니다.

**초록이 「막을 것이 없었다」가 아니라 「그 자리를 안 봤다」였습니다**(⑨-c).

→ 창을 `className="belt-slot"` 부터 `</div>` 까지로 좁히고,
**창이 비면 우는 단언**(`toContain('SiteGnb')`)을 붙였습니다(계열 ⑦). 다시 물리니 붉어집니다.
