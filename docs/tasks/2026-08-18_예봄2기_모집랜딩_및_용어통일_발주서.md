## 0. 목적과 마감

퓨처나우 예봄 2기 모집을 연다. 세 가지가 필요하다.

1. `future.yebom.org` 하위에 **모집 랜딩 페이지**를 신설한다
2. 참여자·인도자 화면의 **측정 도구 명칭을 '사전 체크'로 통일**한다
3. 2기 운영에 필요한 **기수 구분·신청 확정·마감 처리**를 붙인다

**마감 기준일 : 8월 25일(월).** 모집 마감이 **9월 6일(일)**이므로 카드뉴스는 8월 안에 배포된다. 배포된 카드에는 '사전 체크'로 쓰여 있고 링크가 `/join`을 가리키므로, **배포 시점에 S-1과 S-2가 살아 있어야 한다.** 화면 문구가 어긋나거나 링크가 404면 첫 접촉에서 신뢰가 깎인다. S-3은 첫 신청자가 들어오기 전까지만 완료되면 된다.

일정이 무리라면 **S-1만 먼저 8월 25일에 배포하고, S-2를 8월 28일로 분리하는 안**을 회신한다.

## 1. 불변식 — 손대지 않는다

이 목록을 어기는 변경은 발주 범위 밖이다. 필요하다고 판단되면 실행 전에 보고한다.

- **라우트·테이블명·컬럼명·타입명·API 필드명은 그대로 둔다.** 이번 작업은 표시 문자열 교체다. 코드 식별자까지 바꾸면 마이그레이션과 회귀 위험이 붙는데, 참여자는 식별자를 보지 않는다

- 기존 1기 데이터를 수정하거나 이관하지 않는다

## 2. S-1 · 용어 통일

### 2.1 명칭 원장

| 시작 시점 측정 도구 | **사전 체크** |

| 인도자용 해석 산출물 | **사전 체크 리포트** / **마무리 체크 리포트** |

`진단`·`자기진단`·`점검`·`자기점검`·`설문`·`평가`·`점수`는 화면 문자열에서 제거한다.

**분석 용어는 유지한다.** 활력지수·위기신호·함정유형·준비도 프로필·간격 레이더는 인도자 전용 개념이고 정확한 이름이 필요하다. 그대로 둔다.

### 2.3 인도자 콘솔

콘솔도 같은 명칭으로 통일한다. 인도자가 참여자 앞에서 다른 낱말을 쓰면 그 자리에서 어긋난다.

## 3. S-2 · 모집 랜딩 페이지

### 3.1 기본 사양

| 항목 | 값 |
|---|---|
| 경로 | **`future.yebom.org/join`** (확정). 쿼리 파라미터 `code` 를 받는다 |
| 성격 | 정적 페이지. 인증 불필요, 로그인 없이 열람 |
| 기준 | 모바일 우선. 카톡 인앱 브라우저에서 깨지지 않을 것 |

| 원고 | `예봄2기_모집카드뉴스_원고_확정.md` 전문. **문구를 임의로 고치지 않는다** |
| 시안 | `예봄2기_카드뉴스_시안.html` — **색·타이포·간격의 기준**. 카드 13장의 시각 언어를 세로 스크롤로 옮긴다 |

### 3.1.1 시안을 어떻게 쓰는가

시안은 정사각 카드 기준으로 만들어졌고 랜딩은 세로 스크롤이다. 그대로 베끼지 않는다.

**가져올 것** — 네이비 바탕, 골드 강조선, 도면 격자(투명도 0.055), 모서리 등록표, 눈썹문(letter-spacing .22em 골드), 구분선 투명도, 표 구조, 인용 좌측 골드 세로선.

**버릴 것** — 카드 번호(`03 / 13`), 1:1 고정 비율, 카드 11 전용 축소 스케일. 셋 다 카드뉴스 매체에만 필요한 장치다.

**바꿀 것** — 시안의 글자 크기는 1080px 캔버스 기준이다. 랜딩에서는 실제 뷰포트 기준으로 다시 잡는다. 비율만 유지한다.

### 3.1.2 QR 을 넣지 않는다

**랜딩에는 QR 코드를 두지 않는다.** 이미 그 URL에 도착한 사람에게 같은 URL의 QR을 보여주는 것은 무의미하다.

| 매체 | 신청 유도 방식 |
|---|---|
| 카드뉴스 이미지 | QR + 링크 문자열. 이미지에서는 누를 수 없으므로 둘 다 필요하다 |
| 랜딩 페이지 | **CTA 버튼만.** QR 없음, 링크 문자열 노출 불필요 |

시안 카드 13의 QR 자리는 랜딩에서 **주 CTA 버튼**으로 대체된다.

카드뉴스 13장과 랜딩은 같은 원고를 쓴다. 카드뉴스는 이미지로 배포되고, 랜딩은 링크로 전달된다. **문구가 갈리면 안 된다.**

마감 안내 문구는 확정 전이다. 자리만 만들고 문자열은 상수로 뺀다.

### 3.6 초대 코드 `?code=`

배포 링크는 `https://future.yebom.org/join?code=ZR4KB` 다.

- 랜딩은 `code` 값을 받아 **계정 생성과 사전 체크 완료까지 유지**한다. 중간에 유실되면 기수 귀속이 끊긴다
- 코드 값과 기수의 연결 관계를 어디에 두는지 설계해 보고한다. 하드코딩하지 않는다 — 3기에 그대로 재사용한다
- **코드 없이 접속한 경우의 처리를 정해 보고한다.** 세 안 중 하나를 고르고 근거를 밝힌다
  - ① 그대로 열되 기본 기수(2기)로 귀속
  - ② 그대로 열되 신청 단계에서 코드 입력 요구
  - ③ 안내 화면 후 차단
- 코드가 유효하지 않은 경우도 같은 기준으로 처리한다

**S-3의 기수 태그와 겹친다.** 이 코드가 기수 식별을 겸한다면 §4.1의 기수 부여 방식을 여기에 통합한다. 착수 전에 어느 쪽으로 묶을지 회신한다.

## 4. S-3 · 운영 데이터

### 4.1 기수 구분

**먼저 확인하고 보고한다.** 응답에 기수(코호트) 값이 이미 있는가.

- 있으면 : 2기 값 부여 방식만 정하면 된다
- 없으면 : 필드를 추가한다. 기존 1기 데이터에는 1기 값을 채운다. **기존 행을 지우거나 옮기지 않는다**

기수 값이 없으면 1회차 오프닝의 그룹 평균 레이더가 1기와 섞여 오염된다. 이 작업이 S-3의 핵심이다.

### 4.2 신청 확정 시점

**사전 체크 완료 시각을 신청 확정으로 본다.** 계정만 만들고 체크를 마치지 않은 상태는 '작성 중'이며 정원을 차지하지 않는다.

인도자 콘솔에 다음이 보여야 한다.

- 신청 확정자 목록 — 체크 완료 시각 오름차순. 순번 표시
- 작성 중 목록 — 계정만 만든 사람. 확정자와 구분되게

### 4.3 마감 처리

- 인도자 콘솔에서 **수동 스위치**로 마감한다. 자동 마감은 넣지 않는다
- 마감 시 : 랜딩 CTA 비활성 + 사전 체크 진입 차단 + 안내 화면
- **이미 시작해 작성 중인 응답은 마감 후에도 제출할 수 있게 둔다.** 중간에 끊기면 그 사람의 10분이 버려진다. 초과분은 인도자가 개별 판단한다

## 5. 검수 기준

세 채널을 모두 통과해야 슬라이스를 닫는다. 하나라도 빠지면 완료로 보지 않는다.

| 채널 | 확인 방법 |
|---|---|
| 라인 diff | 변경 파일 전수. 불변식 위반 없음을 diff로 증명 |
| 계약·DB 델타 | 기수 필드 추가분과 기존 스키마 영향 범위. 마이그레이션 적용 전후 행 수 일치 |
| 실행 검증 | 실제 브라우저. `fetch 200`은 근거로 인정하지 않는다 |

**감사 전 반드시 저장소를 새로 클론한다.** 오래된 클론은 거짓 결과를 낸다.

### 5.1 실행 검증 항목

- 모바일 실기기에서 랜딩 전 섹션 열람 (iOS Safari, Android Chrome, **카톡 인앱 브라우저**)
- 랜딩 → 계정 생성 → 사전 체크 → 완료 화면까지 실제 1회 완주
- 완주 응답에 2기 기수 값이 붙었는지 DB에서 확인
- 콘솔에서 확정자·작성중 구분 표시 확인
- 마감 스위치를 켠 뒤 랜딩 CTA와 체크 진입이 모두 막히는지 확인, 다시 끄기
- 계좌 복사 버튼 동작
- 카톡에 링크를 붙여 OG 미리보기 확인

### 5.2 용어 잔존 검증

전수 검색어(§2.4)로 참여자 표면과 콘솔을 훑고, **잔존 0건**을 검색 결과로 보고한다. 남겨야 할 것이 있으면 이유와 함께 목록으로 낸다.
