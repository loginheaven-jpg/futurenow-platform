## 0. 왜 세 덩이인가

소건 넷으로 예고했으나, 회원 체계 의논의 산출물이 소건 ①과 **같은 화면·같은 자리**를 만진다.
공개 현관의 로그인 상태 표시와 대기 칩은 한 자리이고, 따로 발주하면 두 번 짓는다.
만지는 층으로 다시 묶는다.

| 덩이 | 층 | 마이그레이션 |
|---|---|---|
| **5-1 로그인·회원 표시** | 표시(화면) | **0** |
| **5-2 운영자 도구** | 운영자 화면 + 사건 로그 | 1 |
| **5-3 피드 복수 반응** | 피드 4층 | 1 |

## 1. 순서와 일정

| 덩이 | 내용 | 시기 |
|---|---|---|
| **5-1** | 로그인 체감 수리 · 공개 현관 상태 표시 · 대기 칩 · 내 정보 등급 · 역할 카드 복수 · `/signup` 링크 · 용어 | **8/29~9/2** |
| **5-3** | 이모지 복수 반응 | 9/3~9/6 |
| **5-2** | 승인 취소 · 사용자 관리 · 사건 로그 · 가입 경위 승격 | 9/8~9/13 |
| — | **2기 시작** | 9/20 |

**5-1을 먼저 한다.** 최박사가 실기기에서 겪은 증상 셋이 여기 걸려 있고, 2기 참여자 아홉 명이
같은 것을 겪는다. 마이그레이션 0이라 위험도 가장 낮다.

**5-3을 5-2보다 앞에 둔다.** 피드는 2기가 매일 쓰는 화면이고, 운영자 도구는 시작 후에도 된다.

## 2. 확정 사항 (의논 결과 — 발주의 전제)

| # | 확정 |
|---|---|
| 1 | **초기화면 = 공개 현관(`/`).** 승인 전 사용자는 리다이렉트가 아니라 **잔류**한다. `/home` 개방 유지 |
| 2 | 용어 노출 — **준회원 = 방문회원 · 정회원 = 포럼회원.** 내부 값(`pending`·`individual`)은 불변 |
| 3 | 승인의 뜻 = **포럼회원 자격 부여.** 판단 근거는 가입 경위. 향후 서비스 연동 시 큐 자체가 소멸 |
| 4 | 인도자 = 신청 + 운영자 승인. 겸직 허용(데이터는 이미 그러함) |
| 5 | 좌석 집계에서 인도자·운영자 제외 — 현행 필터가 이미 그 뜻(코드 0) |
| 6 | 자격 **무기한**. 기간 만료 없음. 운영자가 강등·비활성 가능 |
| 7 | 탈퇴 = **계정 비활성 기본**. 전체 삭제는 본인 요청 시 별도 절차(이번 범위 밖) |
| 8 | 승인 취소 = 삭제가 아니라 **새 사건**. 영향 범위 표시 + 근거 메모 필수 |

## 3. 증상 셋과 원인 하나 (5-1의 근거)

최박사 실기기 증언 셋이 **같은 원인**을 가리킨다 - **로그인 상태를 화면이 말하지 않는다.**

| 증언 | 실측 | 진짜 원인 |
|---|---|---|
| "다시 로그인해야 한다" | 세션 쿠키 영속 400일 · 매 요청 갱신 | `/login`이 인증자를 안 돌려보냄 |
| "뒤로가기하면 로그아웃" | `signOut` 호출 지점은 `LogoutButton` 하나뿐 | `router.push`로 `/login`이 히스토리에 남음 |
| "로고 누르면 로그아웃" | 로고는 `signOut`을 부르지 않음 | **공개 현관이 세션을 아예 안 봄** |

**셋 다 실제 로그아웃이 아니다.** 표시를 고치면 증상이 사라진다.
