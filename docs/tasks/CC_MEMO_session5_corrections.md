## 0. 판정 — 일곱 건 전부 수용

소스로 전량 검증했다. **반박 셋은 내 오류이고, 그중 둘은 지시서가 자기 검증 조건을 스스로 어긴 것이다.**

| # | 내용 | 성격 |
|---|---|---|
| 반박① | 마음 낱말이 **둘** 겹친다 | 지휘부 오류 — 대조 누락 |
| 반박② | `step.mirror` 가 타입에 없다 | 지휘부 오류 — 범위 초과 |
| 반박③ | 미등록 가드가 **넷**이다 | 지휘부 누락 — **4회차와 같은 자리** |
| 보완① | `1~4회차` → `2~4회차` | 지휘부 오류 |
| 보완② | `점수` 가 3회차 문안에 있다 | 지휘부 누락 |
| 보완③ | `from/to` 규칙과 실제가 어긋난다 | 규칙 갱신 필요 |
| 보완④ | 심화 ② 책 참조 위치 | 지휘부 누락 |

## 1. 반박① 마음 낱말 — 대안을 채택한다

**내가 `홀가분함` 을 1회차 `후련함` 하고만 비교했다.** 실제 충돌은 3회차 `홀가분함`(문자열 동일)과 4회차 `든든함`(문자열 동일) **둘**이다. `든든함` 은 §1-#4 가 다루지도 않았다.

지시서 §7 이 스스로 `1·2·3·4회차와 겹치지 않는다` 를 검증 항목으로 넣었으므로, **그 테스트를 쓰는 순간 두 건이 레드로 뜬다.** 문안과 검증이 서로 모순인 채로 발행했다.

**대안을 채택한다.**

```
가뿐함 · 믿음직함 · 의욕 · 부담스러움 · 조바심 · 딱 맞는 말이 없음
```

| 자리 | 원안 | 확정 | 근거 |
|---|---|---|---|
| 면죄 | `홀가분함` | **`가뿐함`** | 짐이 내려간 감각을 유지하면서 3회차 `홀가분함`·1회차 `후련함` 과 갈린다 |
| 설계 | `든든함` | **`믿음직함`** | 4회차 `든든함` 회피. `할 만함` 은 3회차 `해볼 만함` 과 가까워 기각 |

겹침을 허용하는 쪽은 택하지 않는다. **검증을 내리면 6·7회차에서 같은 판단을 매번 다시 해야 하고, 그때는 낱말이 더 남지 않는다.** 지금 규칙을 지키는 편이 싸다.

§1-#4 의 나머지 논지(어감 겹침까지 막으면 낱말이 안 남는다)는 그대로 유효하다. **문자열 기준을 지키되 어감은 겹쳐도 된다** — 그 원칙이 이번에 `가뿐함`·`믿음직함` 을 가능하게 했다.

## 2. 반박② `step` 되비추기 — ⓐ를 채택한다

`CheckinSession['step']` 에 `mirror` 가 없다(`index.ts:88~99`). `lastStep` 안에만 있고, 렌더도 `neededBacks` 도 세 자리만 훑는다. **지시서 §3-9·§4 는 타입·순수함수·컴포넌트·미리보기 넷을 고쳐야 성립하는데, §5 파일 목록에 셋이 없다.**

내가 머리말에 `범위: session5.ts 신설 + 레지스트리 + 테스트` 라 못 박아 놓고 본문에서 렌더 경로 변경을 요구했다.

**ⓐ — `lastStep` 되비추기에 합친다.**

```
mirror: {
  label: '지난 시간의 한 걸음과 첫 도미노',
  keys:  ['step_what', 'step_when', 'domino_what'],
  back:  1,
  empty: '이번 회차부터 한 걸음이 쌓입니다.',
}
```

**코드 변경 0이고 정보를 잃지 않는다.** 그리고 클코1이 짚은 대로 **위(지난 것)와 아래(다음 것)를 한 상자에서 대조**하게 되어 오히려 나을 수 있다.

§3-9 에서 `mirror` 줄을 **삭제한다.** `step.help` 가 이미 `오늘 활동 5에 적으신 2주차 칸이 곧 이번 주입니다` 로 출처를 지목하므로 위치를 잃어도 참여자가 어디서 옮겨 오는지 안다.

**ⓑ를 택하지 않은 이유.** `step.mirror` 가 6·7회차에서 반복될지 아직 모른다. 반복이 확인되지 않은 일반화는 ADR-94 기준에 걸린다 — **도구가 있는가를 먼저 묻는다.** 6회차 발주서가 다음 한 걸음 위 되비추기를 또 요구하면 그때 ADR로 세운다.

## 3. 반박③ 미등록 가드 넷 — 그리고 통합을 승인한다

넷이 맞다. 특히 `readModel.test.ts:294` 는 `buildCheckinRead(5, …)` 형태라 **`getCheckinSession(5)` 문자열 검색으로는 영원히 안 잡힌다.**

**넷 전부 `(6)` 으로 이어 쓴다.** 지우지 않는다 — 미등록 회차가 링크로 새어 나가지 않는다는 가드다.

```
readModel.test.ts:294   buildCheckinRead(6, …) → []
session2.test.ts:95     getCheckinSession(6) === null
session3.test.ts:49     getCheckinSession(6) === null
session4.test.ts:54     getCheckinSession(6) === null
session5.test.ts        getCheckinSession(6) === null   ← 신설
```

**그리고 통합을 이번 범위에 넣는다.** 클코1은 6회차 이월을 제안했으나 **앞당긴다.**

같은 누락이 4회차에서 한 번, 5회차에서 또 한 번 났다. **두 번 반복된 것은 사람 문제가 아니라 양식 문제다.** 6회차에도 같은 자리에서 또 빠질 것이 거의 확실하고, 그때 고치는 비용이나 지금 고치는 비용이나 같다.

`registry.guard.test.ts` 를 신설한다.

```ts
// 등록되지 않은 회차는 어느 경로로도 새어 나가지 않는다.
// 회차를 등록할 때 이 파일 한 곳만 고친다 — 가드가 흩어져 있어 4·5회차에서 연속으로 누락됐다.
const REGISTERED = [1, 2, 3, 4, 5] as const;
const NEXT = 6;

it('등록된 회차는 전부 조회된다', ...);
it('다음 회차는 getCheckinSession 이 null', ...);
it('다음 회차는 buildCheckinRead 가 빈 배열', ...);
```

기존 넷은 **삭제한다.** 통합 파일이 같은 것을 더 강하게 지키므로 남기면 중복이고, 중복은 다시 어긋난다.

## 4. 보완① `1~4회차` → `2~4회차`

`session1.ts` 에 `lastStep` 이 0건이다. 1회차는 되비출 지난 걸음이 없어 `step.lastStep?` 가 선택 필드다.

§7 체크리스트와 §9 완주 조건의 `1~4회차 last_step_result 선택지 넷 불변` 을 **`2~4회차`** 로 고친다. 그대로 두면 `undefined.options` 를 읽어 터진다.

## 5. 보완② 금지어 검사를 5회차로 스코프

`session3.ts:21·61` 에 `점수` 가 리터럴로 있다. **워크북에서 참여자가 실제로 점수를 매긴 활동**을 가리키는 말이지 측정 도구의 이름이 아니다. ADR-107 검토에서도 같은 이유로 남겼다.

§9 의 `§8 금지 어휘가 참여자 문안에서 0건` 을 **`5회차 문안에서 0건`** 으로 좁힌다. §7 의 ADR-108 잠금 블록은 이미 `koreanLiterals('session5')` 로 한정돼 있어 그대로 둔다.

**공용 `BANNED`(허락 어휘 여섯)에는 손대지 않는다.** 그것은 전 회차 공통 규범이다.

`체크` 도 안전하다 — `session2.ts` 의 것은 주석이고 `koreanLiterals` 가 주석을 걷는다.

## 6. 보완③ `from/to` 규칙을 갱신한다

`index.ts:13` 주석이 `쌍(from→to)은 교체·변화를 뜻한다` 로 좁게 적혀 있는데, 4회차가 이미 인과(`domino_what → domino_effect`)로 한 번 넓혔고 5회차는 조건(`trigger_if → trigger_then`)이다.

**규칙을 실제에 맞춘다.**

```
//   쌍(from→to)은 **방향이 참인 관계**에 쓴다 — 교체·인과·조건.
//   나란한 두 값(영역+바람)에는 쓰지 않는다 — 화살표가 거짓말을 한다.
```

규칙과 실제가 어긋난 채로 두면 6·7회차에서 또 판단이 필요해진다는 지적이 옳다.

## 7. 보완④ 심화 ② 책 참조 — 뺀다

`(책 230~231쪽)` 이 `만약` 과 `나는` 사이에 끼어 짝 읽기가 끊긴다는 지적이 맞다. 그리고 **같은 참조가 `pairText`(§3-3)에 이미 붙어 있어 한 카드에 두 번 나온다.**

둘째 필드로 옮기지 않고 **심화 ②에서 아예 뺀다.** 중복이 사라지고 짝 읽기도 산다. 같은 쪽을 두 번 가리킬 이유가 없다.

```
[0] label: '오늘 만든 신호를 이번엔 첫 도미노에 걸어 본다면 — 만약'
[1] label: '나는'
```

§11 표에서 `domino_if.label` 행을 삭제한다. **참조는 넷이 된다.**

## 8. 2기 시점 정정

검토서 §10 이 짚었다 — 부록의 `2기 시작 전에 전 회차 결산 선택지를 다섯으로 통일한다` 는 이월 항목이 **이미 시점을 놓쳤다.** 2기 사전 체크가 6명 완료되었고 1회차가 9/20이다.

**시점을 `2기 1회차 갈무리가 열리기 전` 으로 다시 잡는다.** 아직 `checkins` 행이 없으므로 저장값 파손 위험이 없다. 9/20 전에 처리하면 된다.

**이번 범위에 넣지 않는다.** 5회차 착수가 우선이고, 통일은 문안 한 줄씩 다섯 파일이라 별건으로 빠르다. `architecture.md` 이월 항목에 시점을 고쳐 적는다.

원 지시서 §9 에 반영한다.

```
정정
□ 「1~4회차 last_step_result 선택지 넷 불변」 → 「2~4회차」
```

## 11. 이 검토에 대하여

반박 셋이 전부 사실이었고 **둘은 지시서가 자기 검증 조건을 스스로 어긴 것**이다. §7에 겹침 검증을 넣어 놓고 겹치는 낱말을 지정했고, 머리말에 범위를 못 박아 놓고 본문에서 그 범위를 넘었다.

**같은 종류의 결함이 4회차에서도 나왔다**(`back?: 1 | 2` 가 §4-0 근거와 어긋난 건). 내가 쓴 문서를 내가 검수하면 같은 눈으로 보게 되어 이런 것이 안 보인다.

미등록 가드 누락은 **4·5회차 연속**이다. 그래서 통합을 이월하지 않고 이번에 넣는다. 두 번 반복된 것은 양식 문제다.
