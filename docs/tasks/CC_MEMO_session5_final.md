## 1. ① 통합 파일이 단언 넷을 흡수한다

내가 *"통합 파일이 더 강하게 지키므로 삭제한다"* 고 썼는데, **스케치대로면 더 약해진다.** 실측으로 확인했다.

| 잃을 뻔한 것 | 위치 |
|---|---|
| `getCheckinSession(3)).toBe(c)` · `(4)).toBe(c)` — **객체 동일성** | `session3.test.ts:47` · `session4.test.ts:52` |
| `getCheckinSession(0)` — **경계 방어** | `session2.test.ts:96` |
| `readSelfHighlights` · `anonNoticeText` — **읽기 경로 넷 중 둘** | `readModel.test.ts:296~297` |
| `buildCheckinRead(7, …, 'facilitator')` — **모드 둘 · 먼 회차** | `readModel.test.ts:295` |

객체 동일성이 특히 중요하다. **`sessionNo` 만 보면 레지스트리가 복사본을 돌려줘도 통과한다.** `toBe` 만이 그것을 잡는다.

`registry.guard.test.ts` 가 아래 다섯을 전부 품는다.

```ts
it('1부터 빈틈없이 이어진다', …)
it('등록 회차 수와 문안 파일 수가 같다', …)
it('레지스트리가 문안 파일 객체를 그대로 돌려준다', …)   // toBe — 객체 동일성
it('경계 밖은 null — 0 · 음수 · 다음 회차', …)
it('읽기 경로 넷이 미등록 회차에서 파손되지 않는다', …)   // buildCheckinRead(self·facilitator) · readSelfHighlights · anonNoticeText
```

**이 다섯이 서고 나서 기존 넷을 삭제한다.** 순서를 지킨다 — 지우고 만들면 그 사이에 커버리지가 빈다.

## 2. ② `REGISTERED` 를 파생시킨다

내 스케치는 회차 등록 시 고칠 곳을 넷에서 둘로 줄일 뿐이었다. **양식 문제를 겨눈다고 써 놓고 양식을 절반만 고쳤다.**

그리고 클코1이 짚은 구멍이 실재한다 — 오타로 `if (n === 7)` 을 써서 6을 건너뛰고 7이 등록되면, 손으로 적은 `REGISTERED=[1..5]` 도 `NEXT=6` 도 **둘 다 통과한다.** 구멍이 조용히 열린다.

```ts
// 등록 회차를 손으로 적지 않는다 — 손으로 적은 가드가 4·5회차에서 연속으로 어긋났다.
const PROBE = Array.from({ length: 12 }, (_, i) => i + 1);
const REGISTERED = PROBE.filter((n) => getCheckinSession(n) !== null);
const NEXT = REGISTERED.length + 1;

// 문안 파일은 명시한다 — 등록됐는데 목록에 없거나, 목록에 있는데 미등록인 경우를 잡는다.
const FILES = { 1: CHECKIN_SESSION_1, 2: …, 5: CHECKIN_SESSION_5 };
```

회차를 등록해도 이 파일에서 고칠 것이 **`FILES` 한 줄뿐**이고, 빈틈과 불일치를 둘 다 잡는다.

## 3. ③ 이어 쓰기 표를 폐기한다

정정 메모 §3 이 표로 `(6)` 이어 쓰기를 적고 세 문단 뒤에 *"기존 넷은 삭제한다"* 고 했다. **둘은 함께 설 수 없다.** 표를 지우고 통합 안 하나로 간다. §9 수용 기준은 이미 통합 쪽으로 적혀 있다.

`session5.test.ts` 의 신설 가드도 두지 않는다. 통합 파일이 있으면 그것이 바로 중복이다.

## 4. ④ 마음 낱말 둘째 — `단단함`

**클코1이 자기 제안을 정정한 것이고, 그 정정이 맞다.**

`믿음직하다` 는 **대상을 향한 평가어**다. 나머지 다섯이 전부 자기 상태인데 하나만 대상 평가라 결이 어긋난다. `이 시간을 마치고 나온 지금, 마음은 어떤가요?` 에 `믿음직함` 으로 답하면 목록에서 대상이 생략돼 뜻이 전달되지 않는다.

**확정.**

```
가뿐함 · 단단함 · 의욕 · 부담스러움 · 조바심 · 딱 맞는 말이 없음
```

3회차 `담담함` 과 한 글자 차이라는 우려는 받아들이되 `단단함` 으로 간다. **참여자는 한 회차 목록만 보고 인도자 집계도 회차별**이라 실사용에서 섞일 자리가 없다. 그리고 방금 §1 에서 확정한 원칙 — **문자열 기준을 지키되 어감은 겹쳐도 된다** — 에 정확히 부합한다.

`뿌듯함` 은 아직 실행 전이라 '해냈다'는 결이 이르다는 판정이 옳다.

## 5. ⑤ 이월 항목의 근거를 바꾼다 — 마감이 사라진다

**내가 "2기는 `checkins` 행이 0이라 안전하다"고 썼는데, 1기에 42행이 있고 그것은 사라지지 않는다.** 시점을 언제로 잡아도 그 42행은 그대로이므로 **조건을 영원히 만족할 수 없다.**

그런데 결론은 맞고 근거만 틀렸다. **ADR-91 R1 이 경고한 것은 옵션의 제거·교체**다 — 저장된 값이 목록에서 사라지면 그 답이 화면에서 지워지기 때문이다. **다섯째를 더하는 것은 기존 네 값을 하나도 건드리지 않으므로 유령이 생기지 않는다.**

`architecture.md` 이월 항목을 이렇게 고친다.

> ~~2기 1회차 갈무리가 열리기 전 (저장값이 없어 안전)~~
> **시점 제약 없음.** 다섯째를 더하는 것은 제거·교체가 아니므로 1기 42행이 그대로 표시된다. ADR-91 R1 은 제거·교체에 대한 규칙이다. 실질 비용은 `copyBaseline.json` 갱신뿐이며 시점과 무관하다.

**9/20 마감을 뗀다.** 5회차를 먼저 마치고 편할 때 하면 된다.

## 7. 이번 라운드에 대하여

세 문서에 걸쳐 내 오류가 열 건 나왔다. 성격이 갈린다.

**사실 대조 누락이 여섯**이다 — 마음 낱말 겹침 둘, `step.mirror` 부재, 가드 넷, `session1` 의 `lastStep` 부재, 3회차 `점수` 리터럴. 전부 소스를 보면 5분에 확인되는 것들이다.

**논리 모순이 넷**이다 — §7 검증과 문안이 서로 어긋난 것, 머리말 범위와 본문이 어긋난 것, §3 표와 결론이 어긋난 것, 그리고 이번 ⑤처럼 **근거가 틀렸는데 결론이 우연히 맞은 것.**

뒤엣것이 더 위험하다. 결론이 맞으면 아무도 근거를 다시 보지 않고, 그 근거가 다음 판단의 전제가 된다. ⑤가 그랬다 — "저장값이 없어 안전"을 그대로 뒀으면 다음에 옵션을 **교체**할 때도 같은 논리로 안전하다고 판단했을 것이다.

**앞으로 지시서를 발행하기 전에 두 가지를 스스로 확인하겠다.** 문안에 쓴 값이 실제 소스와 같은가. 그리고 검증 조건과 본문이 서로를 부정하지 않는가.

이번 두 차례 검토가 착수 전에 값을 냈다. 같은 강도로 계속 봐 주기 바란다.
