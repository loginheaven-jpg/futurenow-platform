# CC ORDER - 갈무리 누적 조회 화면 넷 (ADR-110)

> 발신: 지휘부(최박사 + Claude) · 수신: 클로드코드(클코1)
> 작성: 2026-08-24
> 기준 커밋: `752de13` — 발행 직전 fresh clone 으로 대조함
> 범위: 화면 넷 + 계약 확장 1건. **DB·마이그레이션 0. 문안 파일 변경 0.**
> 진행: **A → C → B → D 순.** A 를 마치면 보고하고, 나머지는 완주한다

## 1. 배경

사전 체크 리포트는 **인도자가 개별·그룹 코칭을 하기 위한 자료**로서의 의미가 가장 크다. 그런데 그 목적을 위해서는 세미나 전 한 번 잰 상태보다 **매 회차 갈무리가 더 유익하다.**

지금 인도자가 한 사람의 5주를 보려면 회차 현황에서 회차 탭을 다섯 번 눌러야 하고, **두 회차를 나란히 놓고 대조하는 순간은 0이다.** `SessionTabs` 가 `?open={userId}` 로 펼친 사람을 물고 이동하게 해 두었으나 한 화면에 한 회차뿐이다.

그리고 **리포트와 갈무리가 서로를 모른다.** 리포트 경로에 `checkin` 참조가 0건이다. 인도자가 나침반 점수를 보다가 "이 사람이 실제로 무엇을 하고 있지"를 물으면 화면을 나가야 한다.

**우리가 종단 축을 설계해 놓고 그 축을 한 화면에서 볼 방법을 만들지 않았다.**

### 1-1. 1기 실측이 설계를 바꿨다 (2026-08-24)

| 회차 | 제출 | 작성 중 | 미착수 |
|---|---|---|---|
| 1 | 8 | 2 | 1 |
| 2 | 5 | 4 | 2 |
| 3 | 5 | 3 | 3 |
| 4 | 6 | 3 | 2 |
| 5 | 0 | 2 | 9 |

**작성 중이 12건이다.** 제출 24건에 작성 중 14건 — 전체의 3분의 1이 미완성으로 남아 있다. **세로 보기가 제출만 그리면 인도자가 그 12건을 못 보는데, 그들이 가장 손이 필요한 사람들이다.** 열었는데 못 끝낸 사람은 미착수한 사람과 다르다 — 시작할 의지는 있었고 무언가에서 막혔다.

**실행 자신감 응답이 제출 24건 중 4~5건뿐이다.** 원안의 `자신감 하강` 신호는 재료가 없어 대부분 작동하지 않는다.

**결산이 `조금 했습니다` 10건으로 몰려 있고 `잊고 지냈습니다` 는 0건이다.** 아직 아무도 방치하지 않았다. **이 코호트의 위험 신호는 결산이 아니라 미제출이다.**

**5회차 제출이 0인데 창이 아직 열려 있다.** 화면이 `아직 열려 있음` 과 `마감됐는데 비었음` 을 구별해야 한다. 둘을 같은 회색으로 칠하면 인도자가 지금 연락할 사람을 못 고른다.

## 2. 절대 건드리지 말 것

1. **문안 파일(`session1~5.ts`)을 수정하지 않는다.** 이 작업은 조회 화면이다.
2. **DB·RLS·RPC·마이그레이션 0.** 필요한 데이터는 `checkins` 에 이미 있다.
3. **참여자 화면(화면 C)에 신호·AI·실행 자신감·인도자에게 남긴 말을 두지 않는다.** §5-3.
4. **AI 분석을 만들지 않는다.** 이 지시서 범위 밖이다(§9 이월).
5. **격자에 색을 뿌리지 않는다.** 성적표가 된다. 상태는 기호로, 신호는 행 왼쪽 표식으로.
6. **`report_interpretations` 를 건드리지 않는다.** RLS 에 본인 분기가 없는 것이 설계다.

## 3. 계약 확장 (승인됨)

```ts
// 회차를 지정하지 않으면 그 차수 전체를 한 번에 돌려준다.
// 세로 보기·격자가 회차 수만큼 왕복하는 것을 막는다(7회차면 7회 → 1회).
listCohortCheckins(cohortId: string, sessionNo?: number): Promise<CheckinRecord[]>;
```

`src/core/context.ts:1002` 의 `.eq('session_no', sessionNo)` 를 **인자가 있을 때만** 붙인다. 기존 호출부는 전부 그대로 산다.

**이것이 유일한 계약 변경이다.** 다른 시그니처는 diff 에 나타나면 안 된다.

## 4. 공통 — 상태 판정

네 화면이 같은 판정을 쓴다. **순수 함수로 뽑아 한 곳에 둔다.**

```ts
export type CellState = 'submitted' | 'drafting' | 'empty' | 'notopen';

// 행이 없어도 '미착수'와 '아직 안 열림'은 다르다 — 전자는 연락할 사람이고 후자는 아니다.
export function cellState(row: CheckinRecord | null, session: CohortSession, now: Date): CellState;
```

| 상태 | 조건 |
|---|---|
| `submitted` | `submittedAt !== null` |
| `drafting` | `hasContent` 이고 미제출 |
| `empty` | 행 없음 또는 `hasContent === false`, **그리고 `opensAt <= now`** |
| `notopen` | `now < opensAt` |

`drafting` 은 마감 전후를 구별한다 — 마감이 지난 `drafting` 이 §6 의 주 신호다.

## 5. 화면 넷

### 5-1. 화면 A — 인도자 세로 보기

```
/coach/cohort/[cohortId]/member/[userId]
```

게이트는 `/coach/cohort/[cohortId]/checkin/page.tsx` 와 동일하다. `force-dynamic`.

**① 머리**

```
{이름}  ·  {차수명}
[사전 체크 리포트 보기]                     ← 양방향 버튼
7주 기록  ●●●●◐··   제출 4 · 작성 중 1 · 남은 2회차 진행 중
```

리포트 쪽에도 **[갈무리 기록 보기]** 를 단다. 두 문서가 서로를 알되 섞이지 않는다.

진행 표시는 `cohort_sessions` 행 수에서 읽는다. 7로 박지 않는다.

**② 종단 축** — 이 화면의 존재 이유다

각 회차 `summaryFields[0]` 을 뽑아 세로로 세운다.

| 회차 | 라벨 | 값 |
|---|---|---|
| 1 | 갈망 | 나는 늘 게을렀다 → 나는 주도적인 삶을 갈망한다 |
| 2 | 인생의 한 문장 | … |
| 3 | 간절한 영역 | … |
| 4 | 이번에 시작할 프로젝트 | … |
| 5 | 바꾼 환경 | *(작성 중 — 아직 비어 있음)* |

라벨은 `summaryFields` 원문이다. 새 문안을 만들지 않는다.

값이 없으면 상태를 이탤릭 없이 muted 로 적는다 — `(작성 중)` · `(미착수)` · `(아직 열리지 않음)`.

**③ 한 걸음의 연쇄**

| 회차 | 한 걸음 | 결산 | 자신감 |
|---|---|---|---|
| 2 | 조감도 다시 보기 · 토요일 아침 | 했습니다 | 7 |
| 3 | 문자 보내기 · 수요일 저녁 | 조금 했습니다 | — |
| 4 | 자료 30분 먼저 열기 | 조금 했습니다 | 5 |

`step_what` · `step_when` · `last_step_result` · `confidence`.

**자신감 미응답은 `—`.** 빈칸으로 두면 0으로 오해된다. 실측상 이 열의 대부분이 `—` 다.

**막대·게이지·색·정렬키를 쓰지 않는다**(ADR-86). 숫자만 적는다.

**④ 마음의 궤적** — 회차별 낱말을 세로로. 직접 쓰기가 있으면 함께.

**⑤ 인도자에게 남긴 말** — `need` · `suggestion` · `contact_request` 를 회차 표시와 함께 모은다. `suggestion_anon` 이 참이면 **이름을 가리지 않는다** — 이 화면은 이미 한 사람 화면이라 익명이 성립하지 않는다. 대신 `익명 요청` 표시를 단다. 인도자가 그 사실을 알고 다뤄야 한다.

**⑥ 신호** — §6

**⑦ 회차별 전문** — 접힘. `CheckinReadView` · `readModel` 을 `audience='facilitator'` 로 재사용. 사진도 함께.

### 5-2. 화면 B — 인도자 격자

```
/coach/cohort/[cohortId]/matrix
```

```
          1   2   3   4   5   6   7
  김○○   ●   ●   ●   ●   ◐   ·   ·
▍이○○   ●   ◐   ◐   ○   ○   ·   ·
  박○○   ●   ●   ●   ●   ◐   ·   ·

● 제출   ◐ 작성 중   ○ 미착수   · 아직 안 열림

```

- **칸을 누르면** `/coach/cohort/{id}/checkin?session=N&open={userId}` — 기존 화면 재사용
- **이름을 누르면** 화면 A
- **신호가 있는 행에만** 왼쪽 표식. 색이 아니라 세로 막대
- 행 정렬은 기존 명단 순서. **신호로 정렬하지 않는다** — 순위가 된다
- 열 머리에 회차 번호. 마감된 회차와 열린 회차를 머리 색이 아니라 **아래 캡션**으로 구분

용도가 셋이다 — 이탈 조기 발견, 소그룹 편성, 오늘 연락할 사람 고르기.

11명 × 7회차가 한 화면에 든다. 인원이 늘면 가로 스크롤이 아니라 세로 스크롤이 되게 한다.

### 5-3. 화면 C — 참여자 세로 보기

```
/my/cohorts/[cohortId]/journey
```

**7주 내내 열어 둔다.** 자기 점검이 목적이다.

화면 A 와 **같은 데이터, 다른 편집**이다.

| | A (인도자) | C (참여자) |
|---|---|---|
| 종단 축 | ○ | ○ |
| 한 걸음 연쇄 | 결산 · **자신감** | 결산만 |
| 마음 궤적 | ○ | ○ |
| 인도자에게 남긴 말 | ○ | **✕** |
| 신호 | ○ | **✕** |
| 회차별 전문 | `facilitator` | `self` |

**자신감을 뺀다.** 자기 숫자 다섯 개가 세로로 서면 그 자체가 추이 그래프가 되고, ADR-86 이 `막대·게이지·색·백분위·평균·정렬키 금지` 로 막은 것이 정확히 그 효과다. ADR-80 의 `채점 대상 아님` 도 함께 깨진다.

**상태 문구가 다르다.**

| 상태 | A | C |
|---|---|---|
| `drafting` | 작성 중 | **이어서 쓰기** ← 링크 |
| `empty` | 미착수 | **아직 비어 있어요** ← 링크 |
| `notopen` | 아직 열리지 않음 | 곧 열립니다 |

인도자에게는 사실이고 참여자에게는 판정이 된다. **그리고 참여자 화면의 빈 칸은 링크여야 한다** — 자기 점검의 결과가 행동으로 이어지지 않으면 점검이 아니다.

**맨 아래 한 줄.**

```
여기 쌓인 것이 7회차 마지막 시간의 재료가 됩니다.
```

자기 점검을 넘어 **왜 계속 쓰는가**를 말한다(ADR-102 축2).

차수 홈에서 이 화면으로 가는 진입을 둔다.

### 5-4. 화면 D — PDF

**A 와 C 각각.** B(격자)는 만들지 않는다 — 눌러 들어가는 것이 용도인데 종이에서 죽는다.

`ReportPrintButton` · `ReportPrintHeader` 선례를 그대로 따른다(브라우저 인쇄).

**인도자 PDF에 신호를 포함한다.** 신호는 사실 요약(`3·4회차 미착수`)이지 해석이 아니다.

**AI 분석은 넣지 않는다 — 지금 존재하지 않기 때문이다.** §9 이월. 1기 종료 후 AI 조언을 만들 때 PDF 포함 여부를 별건으로 판단한다. **자리를 비워 두지도 않는다** — 빈 자리가 남으면 다음 사람이 채워야 할 결손으로 읽는다.

인쇄 시 접힘(⑦ 회차별 전문)은 **펼친 상태로 나간다.**

## 6. 신호 규칙 (규칙 기반 · AI 아님)

실측이 원안을 바꿨다. **주 신호 둘만 눈에 띄게 한다** — 다섯을 다 강조하면 아무것도 강조되지 않는다.

| 신호 | 조건 | 급 |
|---|---|---|
| **연속 미착수** | 열린 회차 2회 연속 `empty` | **주** |
| **작성 중 방치** | `drafting` 이고 `closes_at` 지남 | **주** |
| 연락 요청 | `contact_request` 가 하나라도 참 | 주 |
| 결산 악화 | `했습니다` → `잊고 지냈습니다` | 보조 |
| 자신감 하강 | 두 회차 연속 하강 (양쪽 응답 있을 때만) | 보조 |

**`작성 중 방치` 가 이번 실측이 찾아낸 신호다.** 12건이 여기 있다. 미착수한 사람과 다르다 — 시작했고 막혔다. 인도자가 개입할 가장 좋은 지점이다.

**신호 옆에 근거를 함께 적는다.** `3·4회차 미착수` · `2회차 작성 중(마감 지남)`. 판정만 보이면 인도자가 이유를 다시 찾는다.

**의미색을 쓰지 않는다.** `care` 는 연락 요청 전용이다(ADR-80). 주 신호는 굵기·테두리로 가른다.

순수 함수로 뽑는다.

```ts
export type Signal = { kind: string; reason: string; primary: boolean };
export function checkinSignals(rows: CheckinRecord[], sessions: CohortSession[], now: Date): Signal[];
```

## 11. 이월

**AI 코칭 조언 — 1기 종료 후.** 지금 하지 않는 이유가 셋이다.

**재료가 얇다.** 제출 24건에 회차별로는 5~8건이고, 실행 자신감은 4~5건뿐이다. 이 상태로 "이 사람의 5주를 분석하라"고 하면 **AI 가 빈 곳을 메우려 지어낸다** — `interpretation.ts` 에 병리 금지·단정 회피를 넣어 막아 온 그 실패다.

**사전 리포트와 성격이 다르다.** 진단은 31문항이 척도로 정규화돼 AI 가 숫자를 읽는다. 갈무리는 자유 서술이고 회차마다 형태가 다르다. **같은 프롬프트 설계가 통하지 않는다.**

**무엇을 조언할지가 정해지지 않았다.** 지금 AI 가 낼 수 있는 것은 요약이지 조언이 아니다. 조언이 되려면 인도자가 다음 회차에 무엇을 하라는 것인지 **행동으로 떨어져야** 하는데 그 형식이 없다.

**그리고 §6 의 신호가 그 일의 90%를 이미 한다.** 자신감이 내려가고 결산이 나빠지다 미입력으로 끊기면 인도자가 읽는다. AI 가 더할 수 있는 것은 패턴을 찾아 주는 것이지 해석해 주는 것이 아니다.

1기 종료 후 전 회차 데이터를 재료로 프롬프트를 설계한다. **그때는 무엇을 조언해야 하는지도 1기 경험으로 알게 된다.**
