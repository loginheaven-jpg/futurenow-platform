## 0. 이 문서의 지위

5회차 STEP 대화창 발주서를 정본으로 삼고, **미결 일곱 건에 대한 지휘부 판정**을 반영했다. 발주서와 충돌하면 이 문서가 이긴다.

**4회차가 남긴 구조를 그대로 쓴다. 새로 만드는 것이 없다.**

## 1. 미결 일곱 건 판정

### #1 카드와 단톡방 — 카드는 이틀 뒤를 맡는다

1기 실측이 정확하다. 인도자가 *"지금 써서 올리자"* 하면 그 자리에서 단톡방에 올라가고, 이틀 뒤 카드는 안 열린다. **두 채널이 같은 것을 물으면 카드가 진다.**

역할을 가른다.

| 채널 | 시점 | 무엇 |
|---|---|---|
| 단톡방 | 현장 즉시 | 오늘 만든 것을 짧게. 서로 본다 |
| 카드 | 이틀 뒤 혼자 | **현장에서 안 만든 것** · 옮겨 적기 · 다음 주 설계 |

**카드 설계에 미치는 영향은 하나뿐이다.** 심화 ②(첫 도미노에 거는 트리거)가 이 원칙의 실물이다 — 현장에서 의도적으로 만들지 않은 것이고, 카드만이 받는다. 문항 1·2 는 옮겨 적기이므로 단톡방과 경쟁하지 않는다(단톡방은 사진, 카드는 문장).

**문안에 단톡방을 언급하지 않는다.** 채널이 카드 안에서 보이면 참여자가 어느 쪽에 쓸지 고민한다.

### #2 환경 사진 — 받지 않는다

`LetterPhotos` 는 `letter_line` 키로 게이트된다. 5회차에 편지가 없으므로 사진 UI 가 자동으로 안 나온다. **이 동작에 의존하고 코드를 바꾸지 않는다.**

받지 않는 이유가 둘이다. 단톡방이 이미 사진을 받고 있어 **같은 것을 두 곳에 올리게 된다.** 그리고 편지 사진은 손글씨 보존이 목적이었지만 환경 사진은 **인증**이라 성격이 다르다 — 카드가 인증 도구가 되면 나머지 칸의 성격까지 바뀐다.

### #3 골든타임 저장 형태 — 텍스트로 받되, 5회차 카드에서는 받지 않는다

6·7회차에서 재호출되는 것은 맞다. 그러나 **5회차 카드가 골든타임을 묻지 않는다** — 발주서 §1 산출물 표가 세 층(물건·생활 습관·첫 도미노)만 받기로 했고 골든타임은 거기 없다.

시각 입력 위젯을 지금 만들지 않는다. **6회차 발주서가 골든타임을 받기로 하면 그때 판단한다.** 그때도 텍스트 한 줄로 충분할 가능성이 크다 — `새벽 5~7시` 같은 답이 시각 위젯보다 정확하다.

### #4 `홀가분함` 중복 — 유지한다

1회차 `후련함` 과 어감이 가깝다는 지적이 맞다. 그러나 **회차 간 낱말 겹침 금지는 문자열 기준**이고 두 낱말은 다르다. 어감까지 겹치지 않게 하면 6·7회차에서 쓸 낱말이 남지 않는다.

그리고 이 회차에서 `홀가분함` 은 대체 불가다. 발주서가 밝힌 대로 **블록 1이 작동했는지 재는 유일한 지표**다. 대안(`후련함`·`가벼움`)이 오히려 1회차와 더 가깝거나 뜻이 흐리다.

**§9 겹침 검증은 문자열 기준으로 통과한다.**

### #5 SEED 짝과 실행 동행의 공존 — 이번 범위 밖

누적 화면(read 모드)에서 둘이 나란히 보이는지는 `readModel` 이 회차 분기 없이 문안을 훑으므로 자동으로 갈린다. 키가 다르고 라벨이 다르다. **확인만 하고 조치하지 않는다** — §9 에 항목으로 넣는다.

### #6 두 칸 입력 — 판정 불요

`pairText` 사양이 이미 있다. 위 §0 참조.

### #7 6회차 이월 — 접수

연습 트리거 실행 횟수 · 네 주 경로표 3·4주차. **6회차 발주서에 전달한다.** 이 지시서에서 처리하지 않는다.

## 2. 카드 구조

### 1면 슬롯 순서

```
order: ['pairText', 'question', 'mood']
```

**`areaPick` 이 없다.** 5회차에 영역 선택이 없다. `order` 는 존재하는 슬롯만 담는다.

**옮겨 적기 둘을 어떻게 담는가.** 문항 1(환경 한 줄)과 문항 2(만약→나는 두 칸)는 형태가 다르다.

- 문항 2 → `pairText`(`from` · `connector` · `to`)
- 문항 1 → **`identity` 슬롯을 쓴다.** 이름이 '정체성'이지만 실제 모양은 **라벨 + 한 줄 입력 + 되비추기**이고 5회차 문항 1이 정확히 그 모양이다. 슬롯 이름은 회차가 아니라 모양을 가리킨다(ADR-90)

`identity` 를 1면 첫 자리에 둔다. `order` 에 명시한다.

```
order: ['identity', 'pairText', 'question', 'mood']
```

### 묶음 이정표

부제 `의지가 아니라 설계` 는 쪼갤 수 없다. **STEP 이름으로 가른다.**

| 슬롯 | `group` |
|---|---|
| `identity` | `환경을 바꾸고` |
| `pairText` | `신호를 만들다` |
| `question` | `신호를 만들다` |
| `mood` | (없음) |

`slotBoundaries` 규칙 그대로다 — 첫 블록 캡션만, 전이에서 선+캡션, 그룹 밖에서 선만.

### 필수 6칸

| # | 묶음 | 키 |
|---|---|---|
| 1 | 오늘 바꾼 환경 | `env_change` |
| 2 | 만약 → 나는 | `trigger_if` · `trigger_then` |
| 3 | 오늘의 마음 | `mood` (altKey `mood_custom`) |
| 4 | 지난 한 걸음 결산 | `last_step_result` |
| 5 | 다음 한 걸음 | `step_what` · `step_when` |
| 6 | 나에게 주는 한마디 | `self_note` |

**선택** — `relief`(보이는 선택) · `ask_person`(심화) · `domino_if` · `domino_then`(심화) · `last_step_note` · `step_blocker` · `confidence` · 인도자 상자.

### 신규 키 여섯

`env_change` · `trigger_if` · `trigger_then` · `relief` · `ask_person` · `domino_if` · `domino_then`

**`step_blocker`(4회차)를 재사용하지 않는다.** 5회차 문항 1은 '오늘 바꾼 환경'이고 4회차 `step_blocker` 는 '못 하게 될 때'다. 되비추기로 읽되 같은 칸에 덮어쓰지 않는다.

**`domino_if`·`domino_then` 을 `trigger_if`·`trigger_then` 과 가른다.** 앞은 첫 도미노에 거는 트리거(심화), 뒤는 생활 습관 트리거(필수)다. 발주서 §1 이 층을 갈라 놓았으므로 키도 갈린다. 한 칸에 덮어쓰면 그 이층 구조가 사라진다.

## 3. 문안 — 리터럴. 조사 하나 바꾸지 않는다

어조는 ADR-102 진취 전환을 따른다. 허락 어휘(`하셔도 됩니다` · `않으셔도 됩니다` · `괜찮습니다` · `아니어도 됩니다` · `충분합니다` · `충분해요`)를 쓰지 않는다.

**발주서 문안 중 셋이 허락 어휘를 담고 있어 교체했다.** §3-4 · §3-6 · §3-7 참조.

### 3-1. 표지

```
brand:    'FUTURE NOW · 5회차'
title:    '오늘의 갈무리'
subtitle: '의지가 아니라 설계'
counter:  (n) => `필수 6칸 중 ${n}칸 채움 · 약 5분`
band:     '오늘 짠 설계를, 잊히기 전에 자리에 놓아 둡니다.'
firstVisitOnce: 없음
```

발주서 §0 의 '참여자 대면 한 줄'(`실행환경을 설계하여…`)은 **띠 문구를 살리고 넣지 않는다.** 발주서가 지시한 대로다.

### 3-2. ① identity — 오늘 바꾼 환경 (필수)

```
group: '환경을 바꾸고'
key:   'env_change'
label: '오늘 바꾸기로 하신 환경 하나를 그대로 옮겨 적어 주세요. (책 210~213쪽)'
help:  '가까이 두기로 한 것이든 멀리 두기로 한 것이든, 하나면 됩니다.'
placeholder: '자기 전에 휴대폰을 거실 서랍에 둔다'
mirror:
  label: '지난 시간에 적으신 「못 하게 될 것 같은 때」'
  keys:  ['step_blocker']
  back:  1
  (empty 없음)
```

이 회차 산출물 중 **유일하게 오늘 밤 안에 물리적으로 실행 가능한 것**이다. 골든타임은 발견이고 경로표는 계획이지만 이것은 손으로 옮기면 끝난다.

되비추기 근거 — 4회차 워크북이 이 칸을 명시적으로 5회차 재료로 넘겼다. 4회차에서 `step_blocker` 는 선택이므로 비워 둔 사람이 있고, `empty` 를 두지 않아 그때는 상자가 그려지지 않는다.

`help` 의 `하나면 됩니다` 는 **사실 진술**이다(원칙 §4). 발주서 원안 `하나만이면 됩니다` 의 오타를 고쳤다.

### 3-3. ② pairText — 만약 → 나는 (필수)

```
group:     '신호를 만들다'
label:     "오늘 만드신 '만약 → 나는' 한 줄을 옮겨 적어 주세요. (책 230~231쪽)"
help:      "시각이 아니라 '무엇을 하고 난 다음'으로 적으면 더 잘 켜집니다."
from:      { key: 'trigger_if',   label: '만약',  placeholder: '저녁 설거지를 끝내면' }
connector: '→ 그러면'
to:        { key: 'trigger_then', label: '나는',  placeholder: '스쿼트 스무 개를 한다' }
```

**두 칸이 다 채워져야 한 칸으로 센다.** 한 칸으로 받으면 상당수가 `밤에 폰 안 보기` 처럼 **신호 없는 다짐**을 쓴다. 트리거는 신호가 있어야 트리거이므로 칸을 갈라 신호를 못 건너뛰게 한다. 3회차 습관 짝·4회차 도미노 짝과 같은 **구조 강제** 장치다.

`connector` 는 `→ 그러면` 이다. 3회차 `↓ 그 자리에`(교체) · 4회차 `↓ 그것이 넘어지면`(인과)과 달리 **조건**이므로 방향 기호를 가로로 둔다.

`help` 는 발주서 원안(`~적으셔도 좋습니다`)을 교체했다. 허락이 아니라 **값**으로 말한다.

### 3-4. ③ question — 오늘의 질문 (보이는 선택)

```
group: '신호를 만들다'
key:   'relief'
label: "'그건 내가 부족해서가 아니었구나' 싶었던 순간이 오늘 있었다면, 하나만 적어 주세요. (책 202~207쪽)"
help:  '떠오른 그대로 적으십시오. 문장이 되지 않아도 그 자리에 남습니다.'
badge: '선택'
```

이 회차의 정서적 전환점(블록 1의 사면)은 **워크북에 기입란이 없다.** 강의와 나눔으로만 지나가므로 종이에 안 남는다. **카드가 유일한 회수 지점이다.**

방향을 위로 둔다 — 못 한 것을 묻지 않고 짐이 내려간 순간을 묻는다.

`help` 는 발주서 원안(`다듬지 않으셔도 됩니다. 떠오른 그대로면 충분해요.`)을 교체했다. 허락 어휘 둘이 겹쳐 있었다.

접힘으로 감싸지 않는다. 이중 STEP 회차의 서술 질문은 **보이는 선택**이다(발주서 지시서 §2).

### 3-5. ④ mood (필수)

```
key:       'mood'
label:     '이 시간을 마치고 나온 지금, 마음은 어떤가요?'
help:      '두 개까지 고르실 수 있습니다.'
options:   ['홀가분함', '든든함', '의욕', '부담스러움', '조바심', '딱 맞는 말이 없음']
exclusive: '딱 맞는 말이 없음'
max:       2
group:     없음
moodCustom:
  key: 'mood_custom'
  placeholder: '직접 쓰기 (선택)'
  promptPlaceholder: '그럼, 지금 마음에 가까운 말을 한마디로 적어 주세요'
```

**여섯째를 `아직 모르겠음` 이 아니라 `딱 맞는 말이 없음` 으로 쓴다**(ADR-91 C · 3회차부터 확정). 발주서 원안이 옛 낱말을 적었다.

이 회차에는 직면 단계가 없다. **면죄(블록 1)와 적재(블록 3~8)** 가 있고, 앞의 셋이 면죄와 설계의 감정, 뒤의 둘이 적재의 감정이다. 부정 쪽 둘로 균형 규칙 통과.

`홀가분함` 이 안 나오면 블록 1이 작동하지 않은 것이다. 인도자에게 가장 값진 신호다.

### 3-6. 심화 (선택 · 두 칸)

```
title:   '여기서부터가 진짜입니다'
summary: '방 밖의 한 사람 · 첫 도미노에 거는 신호'
```

**심화 ①**

```
key:   'ask_person'
label: '이번 주에 나를 끌어올려 줄 한 분께, 무엇을 부탁하시겠어요? (책 216~221쪽)'
help:  '아직 말씀 안 하셨어도 됩니다. 여기서 문장만 먼저 만들어 두면 꺼내기 쉬워집니다.'
```

135분 최종안에서 활동 4의 위 두 칸이 집으로 갔다. 카드가 그 자리를 받는다. **실행 동행은 인도자가 배정하므로 카드가 다시 묻지 않고, 대신 방 밖의 한 사람을 묻는다.** 세미나가 끝난 뒤에도 남는 것은 이쪽이다.

`help` 는 발주서 원안(`~괜찮습니다. ~두셔도 돼요.`)을 교체했다. 앞은 사실 진술로, 뒤는 값으로 바꿨다.

**심화 ②** — 두 칸 입력이다. 심화 필드가 `pairText` 형태를 지원하지 않으면 **라벨 둘을 가진 인접 텍스트 필드 두 개**로 둔다. 새 위젯을 만들지 않는다.

```
[0] key: 'domino_if'
    label: '오늘 만든 신호를 이번엔 첫 도미노에 걸어 본다면 — 만약 (책 230~231쪽)'
    placeholder: '월요일 아침 사무실에 앉으면'
[1] key: 'domino_then'
    label: '나는'
    placeholder: '그 자료를 30분 먼저 연다'
    help: '오늘 모임에서는 가벼운 것으로 연습했습니다. 이건 그 연습을 진짜에 옮기는 자리입니다.'
```

1기에서 참여자가 스스로 이 결손을 지적했다 — *"if then 을 일에 적용해도 좋겠다, 원씽이랑 연계됐던 것처럼."* 세션이 주지 않은 연결을 카드가 준다.

현장에서 만들지 않는 것은 의도다. 첫 도미노에 거는 트리거는 무겁고, **이틀 뒤 혼자 앉아서 쓰는 편이 오히려 정확하다.**

### 3-7. 2면 · 지난 한 걸음 결산 (필수) — 선택지 다섯

```
key:     'last_step_result'
label:   '지난 한 걸음은 어떻게 되었나요?'
options: ['했습니다', '조금 했습니다', '잊고 지냈습니다', '하려다 막혔습니다', '크기나 내용을 바꿨습니다']
note:    { key: 'last_step_note', label: '한 줄만 덧붙여 주세요',
           help: '여기 정직하게 적는 것이 다음 한 주를 바꿉니다.' }
mirror:  { label: '지난 시간의 한 걸음', keys: ['step_what', 'step_when'], back: 1,
           empty: '이번 회차부터 한 걸음이 쌓입니다.' }
```

**다섯째를 신설한다.** 1기에서 한 참여자가 몸 상태 때문에 프로젝트를 통째로 바꿨고 인도자가 그것을 성공으로 인정했다. 다른 참여자는 목표 크기 자체가 처음부터 과했다. **넷 중에는 이 경우가 들어갈 자리가 없다.**

**조정은 실패가 아니라 설계다.** 이 회차의 주제와도 맞는다.

**다섯의 시각적 무게를 같게 둔다.** 새 선택지에 강조·표시·색을 붙이지 않는다.

**저장값 주의.** 1~4회차는 네 선택지로 이미 응답이 쌓였다. 5회차만 다섯이며, **1~4회차 문안을 건드리지 않는다**(ADR-91 R1 — 옵션 목록 변경은 저장값을 유령으로 만든다).

### 3-8. 2면 · 실행 동행 읽기 전용 상자 — 넣지 않는다

발주서 §5-3 이 로스터에서 내려오는 읽기 전용 상자를 요청했다. **이번 범위에서 뺀다.**

근거는 ADR-94 기준이다 — *"도구가 있는가를 먼저 묻는다."* 실행 동행은 **로스터에 저장되는 구조물이 아니다.** 지금 인도자가 현장에서 구두로 배정하고, 카드가 읽을 데이터가 어디에도 없다. 상자를 만들려면 배정을 저장하는 화면·테이블·계약이 먼저 서야 하고, 그건 문안 작업이 아니다.

**대신 심화 ①이 그 자리를 대신한다.** 부탁할 문장을 만드는 것이 이름을 읽는 것보다 행동에 가깝다.

**6회차 발주서에 이월한다** — 실행 동행을 데이터로 관리할지, 계속 현장 구두 배정으로 둘지 판단이 필요하다.

### 3-9. 2면 · 다음 한 걸음 (필수)

```
title:   '다음 시간까지 할 작은 실천 하나를 정해 봅시다.'
help:    '오늘 활동 5에 적으신 2주차 칸이 곧 이번 주입니다. 그대로 옮기십시오.'
what:    { key: 'step_what', label: '무엇을 하시겠어요?' }
when:    { key: 'step_when', label: '언제, 어디서 하시겠어요?',
           placeholder: '토요일 아침, 집 앞 카페에서',
           help: "이미 하고 있는 행동 뒤에 붙이면 훨씬 잘 켜집니다. '양치한 다음'처럼요." }
blocker: { key: 'step_blocker', label: '못 하게 될 것 같은 때가 있다면 언제일까요?',
           placeholder: '야근이 늦게 끝나는 날',
           help: '미리 적어 두면 그 순간에 덜 무너집니다.' }
share:   { notice: '이번 한 걸음은 다음 시간을 열 때 이름과 함께 나눕니다.',
           toggleLabel: '이번 한 걸음은 나만 볼게요' }
mirror:  { label: '지난 시간에 정하신 첫 도미노', keys: ['domino_what'], back: 1 }
```

`title` 아래 `help` 가 **세 층을 눈에 보이게 가른다** — 1면은 물건과 생활 습관, 2면은 첫 도미노다. 발주서 원안(`그대로 옮기셔도 됩니다`)을 명령형으로 교체했다.

`what.help` 를 두지 않는다. 4회차가 `계획이 아니라 동작으로` 를 이미 가르쳤고, 여기서는 `2주차 칸을 옮기라`는 더 구체적인 지시가 위에 있다.

`blocker.help` 를 3회차 문안(`미리 적어 두면 그 순간에 덜 무너집니다.`)으로 되돌린다. 4회차는 `다음 시간의 재료가 됩니다` 였는데 **그 재료를 받는 회차가 지금이다.** 5회차가 또 넘기면 약속이 이월만 된다.

### 3-10. 3면 마무리

`confidence` · `facilitatorBox` 는 4회차와 완전 동일. `defaultOpen` 을 두지 않는다.

```
selfNote:
  key:         'self_note'
  label:       '이번 주를 살아낼 나에게, 한마디만 건네주세요.'
  help:        '오늘의 나에게 지금 필요한 말을 적으십시오. 이 한 줄이 회차마다 쌓입니다.'
  placeholder: '설계는 끝났다. 이제 켜기만 하면 된다'
```

앞의 회차들이 과거의 나·오늘의 나에게 말을 건넸다면 **5회차는 앞을 본다.** WILL 파트의 정체성이 이 한 줄에 들어 있다.

`help` 는 ADR-102 확정 문안이므로 바꾸지 않는다.

### 3-11. save · done

4회차와 완전 동일. 그대로 복제한다.

### 3-12. summaryFields

```
[
  { label: '바꾼 환경',   key: 'env_change' },
  { label: '만약 → 나는', from: 'trigger_if', to: 'trigger_then' },
  { label: '내려놓은 자책', key: 'relief' },
  { label: '부탁할 한마디', key: 'ask_person' },

```

기준은 그대로다 — **나눌 수 있는 문장만.** `domino_if`·`domino_then` 은 심화 두 칸이고 첫 도미노에 걸리는 개인 계획이라 나눔 재료로 약하다. 개인 상세에는 남는다.

`relief` 는 선택 칸이라 비는 자리가 있으나, **비어 있을 가능성은 배제 사유가 아니다**(ADR-99). 이 회차에서 가장 나눌 만한 문장이 여기 나온다.

## 8. 금지 어휘

참여자 문안에서 0건이어야 한다.

```
설문 · 체크 · 지각 · 미제출 · 워크북 · 함정 · 점수 · 평가 · 게으름 · 회피 · 대기열
의지력 · 줄여야 할 사람 · 원씽 · 스프린트 · 전두엽 · 도파민 · 단톡방
하셔도 됩니다 · 않으셔도 됩니다 · 괜찮습니다 · 아니어도 됩니다 · 충분합니다 · 충분해요
```

**신규 넷.** `의지력`(사람을 판정) · `원씽`(4회차가 가설과 확정을 갈라 놓았는데 카드에서 그렇게만 쓰면 어느 층인지 모른다) · `스프린트`·`전두엽`·`도파민`(강의에서만 쓴다. 카드에 오면 의학 언어가 된다) · `단톡방`(채널이 카드 안에서 보이면 어디에 쓸지 고민한다).

`골든타임` · `실행 동행` · `트리거` · `첫 도미노` · `만만하다` 는 **써도 되는 강의 어휘**다.

`체크`는 ADR-107 용어 통일 이후 진단을 가리키므로, 갈무리 문안에 쓰지 않는다.

## 부록. 이월과 판단 기록

**6회차 발주서로 이월** — 연습 트리거 실행 횟수 · 네 주 경로표 3·4주차 · 골든타임 저장 형태 · **실행 동행을 데이터로 관리할지**.

**`identity` 슬롯을 문항 1에 쓴 이유.** 슬롯 이름은 회차가 아니라 모양을 가리킨다(ADR-90). `identity` 의 모양은 라벨 + 한 줄 입력 + 되비추기이고 5회차 문항 1이 정확히 그것이다. 새 슬롯을 만들면 4~7회차마다 슬롯이 늘어 레지스트리를 만든 이유가 사라진다.

**`step_blocker` 를 5회차에서도 쓰는 이유.** 4회차가 `다음 시간의 재료가 됩니다` 로 넘겼고 그 재료를 받는 회차가 5회차다. 5회차 카드는 그것을 되비추기로 읽고, 자기 `step_blocker` 는 다시 6회차로 넘긴다. **키가 같아도 회차 행이 다르므로 덮어쓰지 않는다.**

**결산 선택지를 5회차만 다섯으로 둔 이유.** 1~4회차는 네 선택지로 응답이 이미 쌓였고, 목록을 바꾸면 저장값이 유령이 된다(ADR-91 R1). **2기 시작 전에 전 회차를 다섯으로 통일한다** — 그때는 저장값이 없어 안전하다. `architecture.md` 이월 항목에 남긴다.
