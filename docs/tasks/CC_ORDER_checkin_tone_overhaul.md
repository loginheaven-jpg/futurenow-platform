## 0. 정정 (2026-08-14 · 클코1 대조 후 지휘부 판정)

**ADR 번호는 102다**(97은 `docs/` allowlist 뒤집기에 선점). **기준 커밋은 `8b5fa22`다.**

발행 후 ADR-98~101이 같은 파일을 고쳤다. 원인은 규율 위반이 아니라 **규율의 공백**이다 — "발행 직전 clone"은 발행 시점만 보장하고 그 이후를 못 막는다.

> **같은 파일을 건드리는 작업이 진행 중이면 지시서를 발행하지 않는다. 발행 전에 "지금 열린 작업이 있는가"를 묻는다.**

### 착수 조건 넷 — 판정

**① `selfNote` — ADR-91 D 판례를 부분 파기한다.** 근거 셋 — ⓐ 이 문장은 "무너진 사람이 여는 문"이 아니다(그 문은 연락 요청·익명 안내다. `self_note`는 자기에게 쓰는 말이지 도움을 청하는 통로가 아니다) ⓑ 남겨 둔 완충 넷 중 **유일하게 결측이 일어난 자리**다(나머지 셋은 선택이라 비어도 정상인데, 이 칸만 필수인데 4/8이 비었다) ⓒ 새 문안도 칭찬을 요구하지 않는다 — **허락이 값으로 바뀔 뿐이다.**

→ 테스트에서 이 리터럴만 빼고 나머지 둘은 그대로. 원칙 §3에 제외를 명시한다.

**② 7주 비교 — 문안을 고친다. 화면은 만들지 않는다.** ADR-94 B의 기준("도구가 있는가")을 지휘부 스스로 어겼다. 종단 비교는 종료 리포트(v1.2)의 몫이고, 카드 한 줄 때문에 새 화면을 세우지 않는다.

| 위치 | 확정 문안 |
|---|---|
| 1회차 `identity` help | 손본 문장이 아니라 오늘 쓴 그대로 옮기십시오. **이 문장이 다음 회차의 출발점이 됩니다.** |
| 2회차 `identity` help | 손본 문장이 아니라 오늘 쓴 그대로 옮기십시오. *(값 문장 자리를 비운다)* |
| `selfNote` help | 오늘의 나에게 지금 필요한 말을 적으십시오. **이 한 줄이 회차마다 쌓입니다.** |

**회차별로 갈린 이유 — 되비추기 사슬이 2회차에서 끊겼다.**

```
1회차 존재가치 ──→ 2회차가 되비춤        참
2회차 인생의 한 문장 ──X 읽는 곳 0곳      거짓
```

ADR-100이 3회차 심화를 정리하며 끊었다. **문안이 거짓이 된 것은 증상이고 원인은 사슬이다.** 값 문장을 억지로 채우지 않는다 — 지금 넣을 수 있는 참인 문장("회차마다 쌓입니다")은 `selfNote`와 같은 말이라 원칙 §2-6에 걸린다. **비워 두는 편이 낫다.**

| # | 사슬 복구 — **이번 범위 밖** |
|---|---|
| 1 | 2회차 `identity` help는 앞 문장만 |
| 2 | **4회차 발주서에 `identity_statement` 되비추기를 필수 항목으로 명시** — 4회차는 원씽을 고르는 회차이고 그 준거가 2회차의 한 문장이다 |
| 3 | 4회차 배포 후 2회차 값 문장을 넣는다 — `이 문장이 4회차에서 원씽을 고르는 준거가 됩니다.` |

> **새 규범**(원칙 문서에 반영): 값을 말할 때는 **제품이 지금 이행할 수 있는 것만** 말한다. 미래 기능을 근거로 든 문안은 약속이 아니라 부채다.

**③ 심화 기본 펼침 = `deep_opened` 계측 폐기와 한 몸.** `Disclosure`가 마운트 시 콜백을 부르지 않아 기본 펼침이면 지표가 **자동으로 거짓**이 된다. 가장 위험한 것은 `defaultOpen`만 뒤집고 `onToggle`을 남기는 것 — 접었다 다시 편 사람만 집계돼 **0이 아닌 작은 수**가 찍히고 옛 지표와 구별되지 않는다.

| # | 조치 |
|---|---|
| 1 | `onToggle` 제거 |
| 2 | `deep_opened` 컬럼 보존(1기 데이터) |
| 3 | ADR에 **"`deep_opened`는 1기 지표로 동결"** 명기 |
| 4 | 대체 지표 = **심화 칸 실제 작성률** — 펼침은 의도이고 작성은 행동이다 |

**④ `아직 완성되지 않았습니다` 폐기.** `미제출 ≡ 아직 완성되지 않음`이라 판정 금지에 저촉한다. 축 3이 §4를 어겼다.

### §5 확정 문안 — Phase 3로 미루지 않는다

`완성`을 버리고 **`완료`**로 통일한다 — `완성`은 품질 판정처럼 읽히고, 우리가 세는 것은 칸이 다 찼는지다. `더 채우면`이 방향을 주므로 잔여인지 누적인지 묻지 않아도 되고 `남음`처럼 결핍을 가리키지도 않는다.

| 자리 | 확정 문안 |
|---|---|
| 카드 하단 · 결측 있음 | **`{n}칸 더 채우면 완료`** |
| 카드 하단 · 결측 0 | **`{N}회차 기록 완료`** |
| 차수 홈 · 작성 중 | **`{n}칸 더 채우면 완료`** |
| 차수 홈 · 제출 완료 | **`기록 완료`** |
| 일곱 칸 표시 | **`{done} / {total} 완료`** |

게이트 충돌도 이걸로 풀린다 — 카드 하단이 `완료`를 띄우는 시점은 결측 0일 때이고, 그때는 게이트가 `이대로 제출`을 띄우지 않는다.

### §5-3 일곱 칸 — 위치·위계 확정

- **`AppHeader` 바로 아래 고정.** 상태 무관 규칙이다. `이번 주 갈무리` 블록은 사전진단 미완이면 밀리고 `openSessionNo`가 없으면 안 그려지므로 앵커가 될 수 없다.
- **위계는 캡션급.** ADR-81 3단에 넷째가 끼는 것이라 강조하면 accent CTA가 밀린다.
- 계약·DB 0으로 가능 — `getMyCheckin` 팬아웃, `opensAt <= now`만 질의하면 3주차 기준 추가 왕복 2회.

### 남은 확인

- **ⓐ `충분` 계열** — `BANNED`에 넣되 교체 대상을 명시해야 한다. `충분해요` 3곳을 함께 교체하지 않으면 즉시 실패한다. 문안은 클코1이 §2-6·§4 규칙에 맞춰 제안하고 승인받는다.
- **ⓑ `BANNED` 단언은 Phase 2 이후에 넣는다** — Phase 1만 끝난 시점에 넣으면 아직 안 고친 Phase 2 문안이 즉시 걸린다.
- **스크린샷은 렌더된 문자열 대조로 갈음한다**(승인). 실기기 확인은 지휘부가 최박사께 청한다.

## 1. 배경

1기 1~3회차 실측이 문안 설계의 어긋남을 드러냈다.

| 항목 | 실측 |
|---|---|
| 심화 블록(선택) 펼침 | 8 / 11 |
| 못 하게 될 때(선택) | 7 / 11 |
| **나에게 주는 한마디(필수)** | **4 / 8 비었다** |
| 실행 자신감 값 | `2 · 5 · 7 · 8` (부풀림 없음) |
| 예시 문구 베낌 | 0명 |

**선택은 6~7할이 차고 필수는 절반이 빈다.** 그리고 완충이 막으려던 문제(사회적 바람직성 편향·예시 모방)는 하나도 관측되지 않았다.

참여자는 시간과 돈을 내고 온 사람이다. 그런데 문안 스물다섯 곳이 "안 해도 된다"고 말하고 있었다. 없는 위험에 대비하느라 있는 기회를 잃었다.

**2기부터 갈무리를 과정의 일부로 처음부터 안내한다.** 그러면 문안이 안 해도 된다고 말할 이유가 더더욱 없다.

## 2. 절대 건드리지 말 것

1. **`answers` 키를 바꾸지 않는다.** 문안만 바꾼다.
2. **선택지 목록을 바꾸지 않는다.** 마음 낱말 · 지난 걸음 4지선다 · 영역 칩 전부 그대로다. 목록에서 뺀 값은 화면에 안 그려지고 배타 필터도 통과해 유령 값이 된다(ADR-91 R1). **2기 시작 전에 저장값 없는 상태에서 한다.**
3. **필수 구성·`filledCount` 를 바꾸지 않는다.** 바뀌면 이미 제출된 기록이 소급으로 미완성이 된다. 1회차 5칸 · 2·3회차 6칸 유지.
4. **DB·RLS·RPC·계약을 건드리지 않는다.**
5. **원칙 §3 의 다섯 자리를 건드리지 않는다** — 인도자 연락 요청 · 익명 안내 · 오해 방지 문구 · 사진 열람 고지 · 결측 안내 패널.
6. **압박 어휘(`반드시` · `절대` · `놓치지 마십시오`)를 쓰지 않는다.** 값을 말하면 되지 다그칠 이유가 없다.
7. **판정어(`지각` · `미제출` · `함정`)는 여전히 금지다.** 진취적 어조와 판정어는 다른 것이다.
8. **존대체를 유지한다.** 명령형은 `~하십시오` 를 뜻하지 반말을 뜻하지 않는다.

| 현행 | 교체 |
|---|---|
| `아직 {n}칸이 비어 있어요` | **`{N}회차 기록 · 완성까지 {n}칸`** |
| (결측 0일 때 표시 없음) | **`{N}회차 기록 완성`** |

잔여를 세던 것을 누적으로 바꾼다. 같은 숫자인데 자세가 다르다.

### 5-2. 차수 홈 상태 문구

| 상태 | 현행 | 교체 |
|---|---|---|
| 작성 중 | 쓰시던 자리가 남아 있어요 · {n}칸 남음 | **아직 완성되지 않았습니다 · {n}칸** |
| 제출 완료 | 다 적으셨습니다 | **{N}회차 기록 완성** |
| 미작성 | (현행 유지) | 유지 |

### 5-3. 일곱 칸 진행 표시 (신규)

차수 홈에 7주 기록의 누적을 보이게 한다.

```
7주 기록   ●●○○○○○   2 / 7 완성
```

- 완성(제출) = 채운 표시, 그 외 = 빈 표시
- 회차 수는 `cohort_sessions` 행 수에서 읽는다. 7 로 박지 않는다
- 회차 일정이 없으면 이 블록을 그리지 않는다
- **판정·색을 두지 않는다.** 빈 칸에 경고색을 쓰지 않는다. 채움과 비움의 차이만 보이면 된다
- 위치는 `이번 주 갈무리` 블록 **위**. 카드보다 먼저 전체를 보게 한다

## 6. 리터럴 잠금 처리

이번 개편은 `copyBaseline.json` 을 **대규모로 깬다.** 의도된 변경이다.

1. baseline 을 세 회차 전부 재생성한다.
2. **되돌아가지 않도록 명시 단언을 더한다.** 옛 완충 문구 부재를 못 박는다.

```ts
// ADR-97 — 완충 어휘 회귀 방지. 되돌아오면 톤 개편 전체가 무너진다.
const BANNED = ['하셔도 됩니다', '않으셔도 됩니다', '괜찮습니다', '아니어도 됩니다'];
```

**단, 원칙 §3 의 다섯 자리는 예외 목록으로 둔다.** 인도자 연락 요청·익명 안내·사진 고지·오해 방지·결측 패널의 문자열은 이 검사에서 제외한다. 예외를 코드에 명시해 두지 않으면 다음 사람이 그것까지 지운다.

3. 사유를 ADR-97 본문에 적는다.

## 7. 수용 기준

1. §3~§4 의 문자열이 정확히 교체됐다. 회차별 대조표로 보고한다.
2. **`answers` 키 diff 0.** 선택지 목록 diff 0. `filledCount`·`requiredTotal` diff 0(1회차 5 · 2·3회차 6).
3. 심화 블록이 세 회차 모두 기본 펼침이고 `title` 이 `여기서부터가 진짜입니다` 다. `선택` 표기는 남아 있다.
4. 원칙 §3 의 다섯 자리 문자열이 **그대로다.** 특히 `짧은 안부 연락입니다. 코칭 세션이 아닙니다.` 와 익명 안내.
5. 압박 어휘 0건. 판정어 0건. 반말 0건.
6. 카드 하단·차수 홈 문구가 누적형으로 바뀌었다.
7. 일곱 칸 진행 표시가 뜨고, 회차 수를 `cohort_sessions` 에서 읽는다. 일정 없으면 안 그린다. 경고색 0건.
8. `copyBaseline.json` 세 회차 재생성. 금지 어휘 단언이 있고 예외 목록이 코드에 명시돼 있다.
9. **기존 응답 무손상** — 1기 제출 10건을 read 모드로 열어 값이 그대로 보인다. 마음 낱말 선택 상태가 유지된다.
10. `tsc` 0 · eslint clean · vitest 전량 통과 · build 성공.
11. 계약·코어·DB·마이그레이션 델타 0.

## 9. 이 지시서 밖

**4~7회차는 처음부터 이 원칙으로 쓴다.** 발주서 작성 지시서에 `futurenow_copy_principles.md` 를 상위 규범으로 명시하는 개정이 필요하며 지휘부가 처리한다.

**워크북·스크립트북**은 각 STEP 대화창이 같은 원칙 문서를 받아 진행한다. 특히 스크립트북에서 **진행자 대사의 "안 하셔도 됩니다" 계열을 삭제**하지 않으면, 문안을 아무리 고쳐도 현장에서 톤이 되돌아간다.

**이월** — `confidence.min/max` 죽은 선언(4회차 작업 때), 1·2회차 마음 낱말 통일(2기 시작 전).
