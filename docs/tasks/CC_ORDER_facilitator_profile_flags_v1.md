# CC ORDER - 인도자 전용 박스에 '프로파일 특징' 플래그 추가

> 발신: 지휘부(최박사 + Claude) · 수신: 클로드코드(클코1)
> 작성: 2026-08-24
> 감사 기준 커밋: `23a27f7` (main HEAD). 이 커밋에서 분기할 것.
> 대상: `src/instruments/futurenow/report/FacilitatorPanel.tsx` (2면 인도자 전용 패널)

---

## 1. 배경 (왜 이 수정을 하는가)

인도자 가이드에는 '여섯 원형'과 '원형 빠른 식별표'가 있다. 인도자가 리포트를 보며 원형 가설을 세우려면, 원형 판단에 쓰이는 축 조합을 리포트에서 짚어 줄 실마리가 있으면 좋다.

그러나 **원형 이름을 코드가 자동 판정하게 두지 않는다.** 이유:

- 원형은 극단을 그린 초상이라 대부분의 사람은 여섯 중 어디에도 딱 맞지 않는다. 자동 규칙은 오분류하거나 아무것도 못 고른다.
- 원형 가설을 세우는 일은 인도자의 판단이다(3원칙 ③ "확정은 인도자의 몫"). 박스에 "명료한 정체형"이 떠 있으면 인도자가 그 판정에 닻내림되어, 가이드가 말한 "원형은 가설이지 서랍이 아니다"가 무너진다.

그래서 이 지시는 **원형을 판정하지 않는다.** 대신 인도자 전용 박스에 **원형 판단의 재료가 되는 중립적 축 조합('프로파일 특징')만** 띄운다. 인도자는 이 특징과 가이드의 식별표를 대조해 **스스로** 원형 가설을 세운다. 코드는 사실(어느 축이 두드러진다)만 말하고, 판정(어느 원형이다)은 인도자가 한다.

---

## 2. 절대 건드리지 말 것 (경계)

1. **원형 이름을 코드에 넣지 않는다.** '명료한 정체형' 등 원형명·원형 판정 로직을 만들지 않는다. 플래그는 축의 사실만 말한다.
2. **`scoring.ts` 불변.** 플래그는 표시 층의 파생값이다. 채점에 넣지 않는다. 플래그 계산 함수는 리포트 층(예: `report/profileFlags.ts` 신설 또는 `labels.ts`)에 둔다. `careBanner`가 `labels.ts`에 있는 것과 같은 성격이다.
3. **AI 입력 불변.** 플래그를 `interpretation.ts`에 넣지 않는다.
4. **참여자 미노출.** `FacilitatorPanel`(코치 전용)에만 렌더한다. 참여자 미러에 배선하지 않는다.
5. **중립 톤.** 기존 패널과 같은 네이비·회색만. care 톤·경보색 금지.

---

## 3. 확정 사실 (근거)

`FacilitatorPanel`은 `scores: FuturenowScores`를 받는다. 플래그에 필요한 값이 이미 다 있다.

```ts
vitality: { total: number; band: ...; low: boolean }   // 5~25
compass:  { NAV1..NAV4: number }                        // 각 1~5 (3=중립)
grow:     { G,R,O,W,F: number }                         // 각 1~5
gap:      { B1..B5: number }                            // 각 0~10 (B3=관계·B5=기여)
trap:     { primary; D1..D3 }                           // 패널에 이미 표시됨
```

주관식(E1·E2·E3)은 자유서술이라 플래그에 쓰지 않는다(감정 자동 판정 금지). 정서·기대는 인도자가 원응답에서 직접 읽는다.

---

## 4. 구현 지시

### 4.1 플래그 계산 (리포트 층 헬퍼)

`scores`에서 아래 조건을 만족하는 플래그만 산출한다. **조건에 맞는 것만** 배열로 반환한다(안 맞으면 빠짐). 각 플래그는 중립적 사실 문구다.

| 플래그 문구 | 조건 | 관련 원형(코드에 넣지 말 것·참고용) |
|---|---|---|
| 활력 시들음 구간 | `vitality.total ≤ 10` | 조용한 시들음형 |
| 활력 번성 구간 | `vitality.total ≥ 18` | 질주하는 회피형 |
| 준비도 다섯 축 고르게 높음 | `min(G,R,O,W,F) ≥ 4` | 준비된 도약형 |
| 준비도 편차 큼 | `max(GROW) − min(GROW) ≥ 2` | 명료한 정체형 등 |
| 현실인식이 준비도 중 두드러지게 높음 | `R = max(GROW)` 이고 `R − (2위 축) ≥ 1` | 명료한 정체형 |
| 정체성이 준비도 중 단독 최저 | `F`가 GROW 유일 최저 | (F만 낮음 = 가장 조심) |
| 원씽 낮음 | `O ≤ 2.5` | 따뜻한 표류형 |
| 간격 한 축만 깊이 함몰 | 최저 간격 축이 나머지 네 축 평균보다 `3` 이상 낮음 | 준비된 도약형 |
| 간격 관계·기여 높음 | `B3 ≥ 7` 이고 `B5 ≥ 7` | 따뜻한 표류형 |
| 나침반 좌측 쏠림 | `NAV1~4 중 2개 이상이 ≤ 2` | 회피·비교·결정론·매몰비용 |
| 나침반 우측 지향 | `NAV1~4 중 2개 이상이 ≥ 4` | 접근·미래·제로베이스 |

- **오른쪽 열(관련 원형)은 이 지시서의 설명용이다. 코드·화면에 넣지 않는다.** 화면에는 왼쪽 '플래그 문구'만 뜬다.
- 임계값(≤10·≥18·≥4·≥2·≥1·≤2.5·3·≥7·≤2·≥4)은 초기 제안값이다. 상수로 한 곳에 모아 두면 최박사가 조정하기 쉽다.
- 표시 순서: 활력 → 준비도 → 간격 → 나침반.
- 소프트 캡(선택): 동시에 여럿 뜨면 잡음이 되므로 상위 5개까지만 표시할지 최박사 확인. 기본은 뜬 것 모두.

### 4.2 패널에 렌더

`FacilitatorPanel`의 '믿음의 자리' 다음, '주의 문구' 앞에 새 구획을 넣는다.

- 제목: **프로파일 특징 (원형 참고)**
- 본문: 산출된 플래그를 얇은 태그/칩 목록으로. 중립 톤(회색 칩, `--color-surface-1`·`--color-text-secondary` 정도).
- 플래그가 하나도 없으면 구획 자체를 숨기거나 "두드러진 특징 없음"으로 표기(택1, 최박사 확인).
- 캡션(필수):
  > 이 특징들을 인도자 가이드의 '원형 빠른 식별표'와 대조해 원형 가설을 세우세요. 원형은 코드가 판정하지 않습니다 — 확정은 인도자의 몫입니다.

## 5. 인수 기준 (테스트)

1. **플래그 산출.** 대표 프로파일(예: 박민서 - 현실인식 4.0 홀로 높음·정체성 2.0 최저·원씽 2.5)에서 "현실인식 두드러짐"·"정체성 단독 최저"·"원씽 낮음"이 뜨고, 조건 미달 플래그는 안 뜸을 단언.
2. **원형명 부재.** 패널 산출물·플래그 문구에 '명료한 정체형' 등 원형 이름이 **없음**을 단언(회귀 방지).
3. **참여자 미노출.** 참여자 미러·`MirrorView`에 플래그가 없음을 단언.
4. **AI 입력 불변.** `interpretation.ts` 입력에 플래그가 포함되지 않음을 단언.
5. **채점 불변.** `scoring.test` 무수정 통과.
6. **빈 경우.** 아무 플래그도 안 뜨는 프로파일에서 구획이 §4.2 규칙대로 처리됨을 단언.

## 7. 설계 의도 (참고)

이 기능의 핵심은 **역할 분리**다. 코드는 '어느 축이 두드러진다'는 사실을 모아 주고, 인도자는 그 사실을 가이드 식별표와 대조해 '어느 원형에 가깝다'는 가설을 세운다. 코드가 사람을 유형에 가두지 않으면서, 인도자가 원형을 실제로 손에 쥐게 하는 방식이다. 이 분리를 무너뜨리는 어떤 변경(원형명 자동 표시, 플래그를 원형으로 매핑)도 이 지시의 취지에 반한다.

---

*ORDER 끝. 원형은 판정하지 않는다. 축의 사실(플래그)만 표시하고, 원형 가설은 인도자가 식별표로 세운다. 채점·AI·참여자 경로는 불변.*
