# CC ORDER - 내비게이션 Link 전환 + 액션 pending 표시 (성능 트랙 P2)

> 발신: 지휘부(최박사 + Claude) · 수신: 클로드코드(클코1)
> 작성: 2026-08-25
> 감사 기준 커밋: `bc2e820` (main HEAD). 이 커밋에서 분기할 것.
> 선행: **P1(Vercel 함수 리전 → 서울 전환)은 최박사가 대시보드에서 직접 완료했다.** 이 발주는 그 위에서 시작한다.

---

## 1. 배경 (왜 이 수정을 하는가)

지휘부 분석(2026-08-25)이 확인한 사실 셋.

1. **앱 전체가 `next/link`가 아니라 일반 `<a href>`로 이동한다.** 내부 경로 앵커가 30여 곳이고 `next/link`를 쓰는 파일은 로그인·가입·리셋 계열 4개뿐이다. AppHeader·HeaderActions의 홈/뒤로/메뉴까지 전부 `<a>`다. 결과: 모든 메뉴 클릭이 브라우저 전체 문서 내비게이션이 되어, 서버 TTFB 동안 화면이 이전 페이지 그대로 멈춘다. 참여자가 반응 없음으로 오인해 다시 누른다.
2. **`src/app/loading.tsx`("불러오는 중…")는 지금까지 한 번도 발동한 적이 없다.** loading.tsx는 App Router의 클라이언트 라우팅 전환에서만 뜨는데, 이 앱에는 클라이언트 라우팅이 없기 때문이다. 로딩 UI가 있는데 작동할 통로가 없었다.
3. **서버 액션 버튼에 pending 표시가 없다.** `useTransition` 사용 0건. `CohortDetailClient`의 공통 헬퍼 `run()`은 액션 완료 후 `router.refresh()`까지 도는 동안 버튼이 살아 있어 이중 클릭이 가능하다(JoinClient만 자체 `busy` 가드 보유).

이 발주는 셋을 함께 닫는다. 속도의 뿌리(리전)는 P1이 이미 뽑았으므로, 여기서는 **체감**(즉각 반응 + 로딩 표시 + 이중 클릭 차단)을 닫는다.

## 2. 절대 건드리지 말 것 (경계)

1. **화면 문구 0.** 버튼·라벨·안내문의 문자열을 바꾸지 않는다. pending 중 표시 문구가 필요하면 스피너·비활성화로 해결하고 새 문장을 만들지 않는다(부득이하면 기존 loading.tsx의 "불러오는 중…"만 재사용).
2. **계약 0 · 코어 0 · DB 0 · 마이그 0.** `/contracts`·`/core`·`supabase/` 무변경.
3. **proxy.ts 무변경.** matcher 불변식(ADR-66) 유지.
4. **라우트·리다이렉트 로직 무변경.** href 대상 경로와 쿼리(`?edit=1` 등)는 한 글자도 바꾸지 않는다.
5. **`global-error.tsx`는 `<a>` 유지.** 루트 레이아웃째 대체되는 화면이라 라우터 컨텍스트가 없다. Link로 바꾸면 오히려 깨질 수 있다.
6. **외부 링크·`mailto:`·`target="_blank"`·파일 다운로드 앵커는 대상 아님.** 내부 경로(`/`로 시작하는 href, 리터럴이든 변수든)만 전환한다.
7. **JoinClient의 기존 `busy` 가드 무변경.** 이미 이중 제출을 막고 있다.

## 3. 구현 지시

### 3.1 선행 실측 — P1 효과 확정

전환 작업 전에 현재(리전 전환 후) 수치를 먼저 박제한다.

- 대상 3면: `/home` · `/my/cohorts/[cohortId]`(1기 임의 차수) · `/coach`
- 프로덕션 URL, warm 5회, TTFB median 기록.
- 대조 기준: ADR-66 기록 `/home` median 1573ms(warm-min 899). 리전 전환이 효과를 냈다면 큰 폭으로 내려가 있어야 한다. **내려가 있지 않으면 작업을 멈추고 보고한다** — 리전 설정이 실제 반영되지 않았다는 뜻이고, 그 확인이 Link 전환보다 급하다.

### 3.2 내부 내비게이션 `<a>` → `<Link>` 전수 전환

- 전수 조사 명령(리터럴+변수 href 모두 잡을 것):
  ```bash
  grep -rn "<a " src --include="*.tsx"
  ```
  결과에서 §2-5·§2-6 예외를 뺀 **내부 경로 전부**를 `next/link`의 `<Link>`로 바꾼다. `AppHeader.tsx`(homeHref·backHref)·`HeaderActions.tsx`(homeHref·navHref·/account) 포함 — 이 둘이 체감의 대부분이다.
- `className`·`style`·`aria-*`는 그대로 옮긴다. Link는 anchor로 렌더되므로 시각 델타 0이어야 한다.
- prefetch 속성은 명시하지 않는다(기본값). force-dynamic 라우트는 Next가 loading 경계만 선적재하므로 서버 부하 우려 없음.
- 전환 후 남는 `<a `가 예외 목록과 정확히 일치함을 grep으로 증명해 보고서에 싣는다.

### 3.3 loading.tsx 발동 실증

- **실브라우저**(Playwright)로 프로덕션 또는 로컬 `next start`에서 메뉴 클릭 → "불러오는 중…" 표시를 캡처한다. `fetch 200 ≠ browser normal` 원칙 — curl 로는 이 항목을 검증할 수 없다.
- 표시가 너무 짧아 캡처가 어려우면 네트워크 스로틀로 재현한다. 발동 사실 자체가 검증 대상이다.

### 3.4 서버 액션 pending

- `CohortDetailClient.run()`에 pending 상태를 더한다(`useTransition` 권장). pending 동안 해당 액션 버튼 비활성 + 시각 표시(스피너 또는 기존 disabled 스타일). 이름 변경(낙관적, ADR-62)은 무변경.
- `router.refresh()`를 부르는 나머지 클라이언트 전수 조사:
  ```bash
  grep -rln "router.refresh" src --include="*.tsx"
  ```
  각각에 대해 (a) 이미 자체 가드가 있으면 무변경으로 목록만 보고, (b) 없으면 같은 패턴으로 pending을 붙인다. 특히 `CheckinCardClient`의 저장·제출 버튼은 참여자 표면이라 우선한다.
- 판단이 갈리는 곳(예: pending 표시가 문구 신설을 요구하는 곳)은 임의로 정하지 말고 보고서에 질의로 올린다.

### 3.5 ADR 기록 (architecture.md)

1. **신규 ADR** — 이 발주의 내용: `<a>`→`<Link>` 전수 전환 + 액션 pending. 근거(클라이언트 라우팅 부재로 loading.tsx 미발동)와 실측 전후를 싣는다.
2. **정정 기록** — S-2 파킹(2026-07-03) 결정문의 전제 "in-region 왕복은 TTFB 노이즈 수준"은 당시 실측(ADR-66: getUser 왕복 1회 제거로 warm-min −242ms)과 모순됐다. 왕복 하나가 242ms였다는 것은 함수가 서울 밖(기본 iad1)에 있었다는 뜻이다. 2026-08-25 최박사가 함수 리전을 서울로 전환했다(P1). S-2 파킹 **결론은 유지**하되(리전 정합 후 in-region 왕복은 실제로 노이즈 수준이 된다), 당시 근거가 틀렸음을 명기한다 — 틀린 추론은 결론이 맞아도 문서화한다는 이 저장소의 원칙에 따른다.
