## 0. 읽고 시작하라 - 이 발주의 성격

**서가는 비어 있다.** 라이브 실측(2026-08-28): `library_items` **0행** ·
`storage.objects(bucket_id='library')` **0개**.

그래서 이 발주는 **이전 작업이 아니라 재설계**다. 데이터 이전도, 끊어질 링크도 없다.
1차 구조를 존중하느라 어정쩡하게 얹지 말고, **설계서대로 다시 세운다.**

**다만 표를 지우지는 않는다.** `library_items` 는 `ALTER` 로 간다 -
`DROP TABLE` 은 정책·함수·권한을 통째로 다시 쓰게 만들고, 그 재작성 중에
1차가 옳게 해 둔 것이 조용히 사라진다(ADR-122 ⑰ 이 `handle_new_user` 에서 겪은 그대로).

### 0.1 1차 결함 하나를 정정한다

`library_can_read` 가 `tier='member'` 를 **로그인한 사람 전원**에게 열고 있다.
화면은 *"세미나에 참여하신 분께 열립니다"* 라고 적어 두었다. **문장과 판정이 다르다.**

행이 0 이라 피해자가 없을 뿐이다. **이 정정이 이 발주의 첫 항목이다.**

## 3. 하지 말 것

1. `main` 에 직접 커밋하지 않는다. **새 브랜치**를 판다
2. **적용된 마이그레이션 파일을 수정하지 않는다.** 변경은 항상 새 파일(불변식 15)
3. **`PROXY_MATCHER` 를 좁히지 않는다**(불변식 17). `/library` 는 **공개 라우트**이므로
   `PROTECTED_PREFIXES` 에도 **넣지 않는다**
4. **`/app`·`/instruments` 에서 표를 직접 건드리지 않는다.** `CoreContext` 계약을 지난다(불변식 4)
5. 피드·갈무리·소식의 표와 화면을 **한 줄도 건드리지 않는다.** 서가는 별도 표다
   (재사용하는 것은 **함수 둘**뿐 - `feed_emojis()` · `feed_assert_writable()`)
6. **조회수·인기순·정렬키를 만들지 않는다.** 정렬은 최신순과 회차순뿐
7. **대댓글 슬롯을 만들지 않는다.** 스키마에 `parent_id` 를 두지 않는다
8. **구글 문서·슬라이드를 iframe 으로 끼워 넣지 않는다.** 새 창으로 보낸다
9. **유튜브 iframe 을 처음부터 넣지 않는다.** 얼굴판(facade) - 누른 뒤에 넣는다
10. **자격별로 다른 공유 주소를 만들지 않는다**
11. **동의 문안을 다듬지 않는다.** 설계서 §8.5 가 확정본이다
12. **잠금 안내 문안을 새로 쓰지 않는다.** `membershipVocab.ts` 원문을 읽어 쓴다
13. `design_system.md` 에 없는 부품을 임의로 만들지 않는다 - **부재 목록으로 보고**한다
14. SAIL(`shadow` 스키마)을 건드리지 않는다

## 4. 특별히 조심할 자리 - 다섯

**이 다섯은 겉으로는 통과하고 속으로 틀리는 자리다.**

### 4.1 `library_can_read(text)` 를 지우는 순서

시그니처가 바뀌므로 `CREATE OR REPLACE` 가 되지 않는다. **의존 정책이 먼저 내려가야 한다.**

```
DROP POLICY  library_objects_select ON storage.objects
DROP FUNCTION library_can_read(text)
CREATE FUNCTION library_can_read(uuid)          -- 본체
CREATE FUNCTION library_can_read_path(text)     -- 래퍼
CREATE POLICY library_objects_select ... USING (library_can_read_path(name))
```

**지우기 전에 그 이름이 실물로 있는지 조회한다**(계열 ⑦ - *초록은 대상이 실재한다는 증거가 아니다*).
`pg_get_function_identity_arguments` 로 시그니처까지 확인한다.

### 4.2 `storage_path` UNIQUE 를 부분 인덱스로 바꾼다

**바꾸지 않으면 링크 자료 둘째 행에서 터진다** - `NULL` 이 UNIQUE 를 통과한다고 생각하기 쉬우나,
이 표는 원래 `NOT NULL` 이었으므로 제약을 **다시 걸어야** 한다.

```
ALTER TABLE library_items DROP CONSTRAINT <기존 unique 이름>
CREATE UNIQUE INDEX library_items_path_uq ON library_items (storage_path)
  WHERE storage_path IS NOT NULL
```

**제약 이름을 짐작하지 말고 `pg_constraint` 에서 읽는다.**

### 4.3 표 SELECT 회수 - 이것이 진짜 관문이다

```
REVOKE SELECT ON public.library_items FROM anon, authenticated
```

**이 한 줄이 빠지면 `url` 이 전원에게 노출된다.** RLS 를 아무리 잘 짜도 열이 열려 있으면
`select url from library_items` 한 줄로 새 나간다. 확정 5 가 무너지는 자리다.

**회수 뒤 실제로 막혔는지 `anon` 자격으로 조회해 확인한다.** 코드가 도는 것과 막힌 것은 다르다.

### 4.4 `safeReturn.ts` 두 줄은 **라우트와 같은 커밋**에

먼저 올리면 통과는 되는데 목적지가 404 다. `safeReturn.ts` 주석이 이미 그 사고를 적어 두었다.

### 4.5 `library_get` 의 잠김 분기

**`can_read` 가 거짓일 때 반환에 `url`·`storage_path`·`description`·`author`·`tags` 가
들어가지 않는지 회귀 테스트로 잠근다.** 화면에서 감추는 것은 안전장치가 아니다 -
RPC 가 애초에 내주지 않아야 한다.

### 4.6 올릴 자격은 **구획을 인자로 받는다**

`library_can_upload(p_section)` 이다. **인자 없는 판정으로 만들면 이번 확정을 담지 못한다** -
수료 기수 참여자는 `session` 에는 올리고 `deeper`·`share` 에는 못 올리므로
**같은 사람이 구획에 따라 다른 답을 받아야 한다.**

`p_section` 을 빼고 `boolean` 하나로 만들면 화면이 구획 분기를 스스로 하게 되고,
그 순간 **판정이 화면 수만큼 복사된다.** 설계서 §3.4 의 순서를 그대로 옮긴다.

**②(`expired` 차단)를 빼지 마라.** `feed_assert_writable` 이 어차피 막으니 중복이라고 볼 수 있으나,
그 둘은 **다른 질문**이다 - 하나는 계정 상태, 하나는 구획 자격이다.
②가 없으면 이용 보류된 사람에게 **올리기 화면이 열리고 마지막에 거부된다.**

### 4.7 본인 예외 한 줄을 빠뜨리지 마라

`library_can_read` 에 `OR created_by = auth.uid()`.

**빠지면 수료 기수 참여자가 자기가 올린 `forum` 자료를 못 본다.** 확정 7-2 와 §3.5(등급 상한)가
맞물려 만들어지는 자리이고, **테스트를 짜지 않으면 잡히지 않는다** -
`full` 자격자로만 시험하면 본인 예외 없이도 전부 초록이기 때문이다.

**전용 단언을 둔다**: *수료 기수 참여자가 `tier='forum'` 으로 올린 자료를 그 사람이 연다.*

## 5. 착수 순서

```
0) 새 브랜치 · git merge --ff-only origin/main 선행
1) 설계 보고 - 표·RPC·정책 골격 + 미확정 질의. **코드 전 보고**
2) 마이그레이션 (롤백 검증 → 적용)
3) 계약(/contracts) · 코어(CoreContext)
4) 화면 - /library → /library/[id] → /library/new → /admin/library
5) safeReturn 두 줄 + 내비 라벨 교체 (라우트와 같은 커밋)
6) 커밋·push (독립 단계)
7) 완주 보고 작성 → 커밋·push
8) 감사 대기
```

**1 의 설계 보고만 확인을 받고, 이후는 승인 없이 완주한다.**
**마이그레이션 적용 전 롤백 검증은 유지한다** - 라이브에 닿는 게이트는 줄이지 않는다.

**보고서는 작성 즉시 push 한다.** 로컬에만 두면 지휘부가 읽을 수 없다.

### 6.1 진실표 둘 - 전수

**표가 둘이다.** 읽을 자격과 올릴 자격은 다른 질문이므로 따로 잰다.
자격은 실계정이 아니라 픽스처로 만든다.

**표 A - 읽을 자격** (3단 × 자격 9 = **27칸**)

| 자격 | `public` | `forum` | `coach` |
|---|---|---|---|
| 비로그인 | 열림 | 잠김 | 잠김 |
| 방문회원(`pending` · 기수 소속 없음) | 열림 | 잠김 | 잠김 |
| **수료 기수 참여자**(`read_only` + 기수 소속) | 열림 | **잠김** | 잠김 |
| 확인 대기(`held`) | 열림 | 잠김 | 잠김 |
| 이용 보류(`expired`) | 열림 | 잠김 | 잠김 |
| 포럼회원(`individual`) | 열림 | **열림** | 잠김 |
| 기간 중 참여자(`cohort`) | 열림 | **열림** | 잠김 |
| 인도자(`coach`) | 열림 | 열림 | **열림** |
| 운영자(`admin`) | 열림 | 열림 | **열림** |

**셋째 줄이 1차 결함의 정확한 반대편이다** - 예전 코드는 이 칸을 열었다.

**표 A-2 - 본인 예외** (표 A 를 덮는 한 줄)

| 조건 | 판정 |
|---|---|
| `created_by = auth.uid()` · `tier='forum'` · 자격 `read_only` | **열림** |
| `created_by = auth.uid()` · `tier='coach'` · 자격 `read_only` | **열림** |

**표 A 만 짜면 이 둘이 잡히지 않는다.** `full` 자격자로만 시험하면 본인 예외가 없어도 전부 초록이다.

**표 B - 올릴 자격** (3구획 × 자격 8 = **24칸**)

| 자격 | `session` | `deeper` | `share` |
|---|---|---|---|
| 비로그인 | ✕ | ✕ | ✕ |
| 방문회원(기수 소속 없음) | ✕ | ✕ | ✕ |
| **수료 기수 참여자** | **○** | **✕** | **✕** |
| 확인 대기(`held`) | ✕ | ✕ | ✕ |
| 이용 보류(`expired`) | ✕ | ✕ | ✕ |
| 포럼회원 | ○ | ○ | ○ |
| 기간 중 참여자 | ○ | ○ | ○ |
| 인도자 · 운영자 | ○ | ○ | ○ |

**셋째 줄이 이번 확정이다.** `session` 만 ○ 이고 나머지 둘이 ✕ 인 **유일한 행**이므로
이 행이 무너지면 확정이 사라진다. 세 칸을 각각 단언한다.

**표 C - 고를 수 있는 등급**

| 자격 | `public` | `forum` | `coach` |
|---|---|---|---|
| 수료 기수 참여자 · 포럼회원 · 기간 중 참여자 | ○ | ○ | **✕** |
| 인도자 · 운영자 | ○ | ○ | ○ |

`coach` 는 **RPC 가 거부한다.** 화면에서 꺼 두는 것으로 판정하지 않는다.

### 6.2 노출 차단 - 실측

```
□ anon 자격 `select * from library_items`        → 권한 오류
□ authenticated 자격 같은 조회                    → 권한 오류
□ library_list 반환 열에 url·storage_path        → 0건
□ 잠긴 자료의 library_get 반환                    → title·tier·section 외 전부 NULL
□ 목록 화면 HTML 에 youtube id·docs.google 주소   → 0건 (잠긴 자료 기준)
□ 만료된 서명 URL                                 → 거부
```

**마지막 줄이 중요하다** - HTML 을 실제로 받아 문자열로 센다. 화면에 안 보이는 것과
HTML 에 없는 것은 다르다.

| 목록 반영 | 올린 뒤 목록 맨 위에 붙는다 |

## 7. 미확정 - 없음

v1 의 한 건(수료 기수 참여자의 업로드 자격)이 **2026-08-28 최박사 확정으로 닫혔다.**

> **수료 기수 참여자는 「회차 자료」에 무기한 올릴 수 있다.**

**질문하지 말고 만든다.** 판정과 진실표가 §4.6·§6.1 에 있고, 근거는 설계서 §3.4 다.
**다만 `library_can_upload` 는 그대로 함수 하나로 떼어 둔다** - 확정이 닫혔어도
이 판정은 화면 셋(`/library`·`/library/new`·`/admin/library`)이 함께 묻는 자리라
흩뿌리면 사본이 셋이 된다.

## 8. 보고에 반드시 적을 것

`CLAUDE.md` §11 의 다섯 항목 위에, 이 발주가 더하는 셋.

1. **1차 결함 정정의 실측** - `tier='forum'` 이 로그인 전원에게 열리지 **않는다**는 것을
   픽스처 조회 출력으로 붙인다. 진실표 §6.1 이 그 자리다
2. **`DROP FUNCTION` 대상의 실재 확인** - 지우기 전 조회 출력과 지운 뒤 조회 출력을 **둘 다**
3. **노출 차단 실측** - §6.2 여섯 줄의 실제 명령과 출력
4. **진실표 셋의 전수 결과**(§6.1 · A 27칸 + A-2 2칸 + B 24칸 + C 6칸 = **59칸**).
   특히 **표 B 셋째 줄**(수료 기수 참여자 · `session` ○ / `deeper` ✕ / `share` ✕)과
   **표 A-2 두 줄**(본인 예외)은 **칸별로** 적는다 - 이 다섯 칸이 이번 확정의 실체다

**적는 값은 둘 중 하나다**(§11 승격 조항). 따라가야 하는 값(커밋 해시·행 수·테스트 수)은
**얻는 방법을 함께** 적고, 얼어야 하는 값(동의 문안·ADR 번호)은 **잠금을 함께** 둔다.
