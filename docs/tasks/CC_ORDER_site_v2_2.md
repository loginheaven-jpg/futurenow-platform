## 1. 무엇을 만드는가

### 1.1 동행 피드 — 카톡 대체

날짜별 시간순 피드다. 게시판이 아니다. 실제 사용 예(2026-08-25 하루):

```
06:12  [인도자] 사진
06:19  [인도자] 주님. 저를 향한 뜻을 이해하고 …
07:37  [참여자] 일어나서 팔굽혀펴기 20회 했습니다
07:54  [인도자] 3km 달리고 다리 마사지 중입니다 ㅎㅎ
09:46  [참여자] 팔굽혀펴기 각 25개씩으로 늘려서 75개 완료했습니다
09:51  [인도자] 75개 와우
```

**짧은 글 · 사진 · 즉각 반응.** 하루에 여러 번, 며칠이 아니라 몇 초 단위로 쓰인다.

### 1.2 소식 게시판

1차에서 `/news`가 **최소 구현**(등록·목록·상세)으로 이미 섰고 `news_posts`·`news_upsert`가 있다.
2차는 그 위에 **댓글**을 얹는 것이 전부다. 새로 짓지 않는다.

| 항목 | 결정 |
|---|---|
| **사진 첨부** | **1차부터 포함.** 갈무리 사진 선례를 따른다(§4) |

**1기 인도자 참여 근거** — 6회차가 "삶의 끝에서 오늘을 본다"로 끝나는 프로그램에서 수료가
곧 단절이면 그 마지막 회차가 무색해진다. 실행 동행은 6주로 끝나는 것이 아니다.

## 3. 설계 원칙 — 어기면 이 기능이 죽는다

### 3.1 마찰이 카톡 수준이어야 한다

**세 탭 안에 게시가 끝난다.** 열자마자 입력창 · 사진 한 번 · 게시 한 번.
로그인 세션이 풀려 있으면 그날로 카톡으로 돌아간다 — 세션 유지가 전제다(1차에서 확보).

- 제목 없음 · 분류 없음 · 태그 없음. **본문 하나뿐이다**
- 게시 후 화면 이동 없음. 그 자리에서 목록 맨 위에 붙는다
- 사진만 올려도 게시된다(본문 없이). 카톡 예시의 06:12가 사진 한 장이었다

### 3.2 판정하지 않는다 (불변식 9·11)

**절대 넣지 않는 것** — 연속 기록 배지 · 참여율 · 순위 · 미게시 표시 · 좋아요 수 정렬 ·
"오늘 아직 안 올리셨어요" 알림.

누가 조용한지는 **인도자 콘솔에서만** 조용히 보인다. 그 정보는 지목이 아니라 안부의 재료다.

### 3.3 갈무리와 피드 사이에 벽을 둔다

**금지 방향** — 갈무리 → 피드. 갈무리에 쓴 것을 피드로 옮기는 버튼을 두지 않는다.
갈무리는 혼자 쓰는 방이라는 약속 위에 서 있고, 그 약속이 흔들리면 갈무리가 방어적으로 쓰인다.

**허용 방향** — 피드 → 자기 열람. 자기가 공개한 글을 자기가 되돌아보는 것은 벽을 넘지 않는다.

### 3.4 반응은 있되 판정은 없다

이모지 응원을 넣는다. 카톡의 "75개 와우"가 이 문화의 핵심이다.
**댓글은 1단**(대댓글 없음) — 깊어지면 대화가 되고, 대화는 카톡이 더 낫다.

## 4. 사진 — 갈무리 선례를 따른다

새로 설계하지 않는다. `20260728120000_checkin_photos` · `20260729100000_checkin_photo_limits` ·
`20260802100200_photo_sweep_via_storage_api_only`의 구조를 그대로 옮긴다.

| 항목 | 기준 |
|---|---|
| 버킷 | **비공개** 별도 버킷 하나. `public = false` |
| 파일 크기 | **3 MiB** (갈무리와 동일) |
| 형식 | jpeg. 스토리지가 거부하게 둔다 |
| 경로 | 기수 UUID를 첫 폴더로 — `is_cohort_member` 정책이 그대로 작동한다 |
| 읽기 | 같은 기수 + 그 기수 인도자 + 운영자 |
| 삭제 | 본인 + 운영자 |
| 정리 | **Storage API 경유만.** 직접 DELETE 금지(선례가 그 이유를 적어 두었다) |
| 열람 | **만료형 서명 URL.** 목록에 미리 싣지 않는다(S-4 §2.2 선례) |

**클라이언트 리사이즈를 반드시 넣는다.** 폰 원본은 5~12MB라 3MiB 상한에 그대로 걸린다.
갈무리 선례가 2000px·jpeg 0.85를 쓴다 — 같은 값으로 간다. 이것이 빠지면 인도자가
아침에 사진을 못 올리고, 그것이 곧 실패다.

**장당 개수 상한**을 둔다. 한 게시에 **1장**으로 시작한다 — 여러 장은 화면·용량·삭제가
모두 복잡해지고, 카톡 예시에서도 한 번에 한 장이었다.

## 5. 스코프와 권한

### 5.1 피드

| 대상 | 읽기 | 쓰기 | 반응·댓글 |
|---|---|---|---|
| 해당 기수 참여자 | ○ | ○ | ○ |
| 해당 기수 인도자 | ○ | ○ | ○ |
| 운영자 | ○ | ○ | ○ |
| 다른 기수 | ✕ | ✕ | ✕ |

- **기수 스코프다.** 1기와 2기의 피드는 서로 보이지 않는다(회차 스포일러·기수 간 비교 차단)
- **수료 기수도 그대로 산다.** `cohorts.status='archived'`가 피드를 닫지 않는다
- 여러 기수에 속한 사람은 기수를 고른다. 기본은 **가장 최근 활성 기수**
- `cohorts.kind='seminar'`인 기수만 피드를 갖는다. 휴지통·체험·test 차수는 없다

### 5.2 소식 댓글

| 대상 | 읽기 | 쓰기 |
|---|---|---|
| 전체 가입자 | ○ | ○ |
| 비로그인 | ○ | ✕ |

소식 본문 쓰기는 1차 그대로 운영자·인도자다.

### 5.3 공통

- **쓰기는 전부 DEFINER RPC 경유.** 테이블 직접 쓰기 권한 0
- 삭제는 **본인 + 운영자**. 인도자는 자기 기수 글을 지울 수 있다(부적절 게시 대응)
- 삭제는 soft delete로 한다 — 대화 맥락에서 글이 사라지면 답글이 고아가 된다

## 6. 화면

### 6.1 `/feed` — 참여자

- **입력창이 맨 위**에 상시 노출. 접혀 있지 않다
- 그 아래 날짜 구분선 + 시간순 목록. 오늘이 위
- 각 글: 작성자 · 시각 · 본문 · 사진 · 반응 · 댓글 수
- **"내 걸음만" 필터** — 자기 기록만 모아 본다. 6주 뒤 자기 궤적을 보는 자리다
- 페이지네이션은 **더 보기** 버튼. 무한 스크롤 금지(자기 기록을 찾아 올라가기 어렵다)
- 기수 전환은 여러 기수 소속일 때만 노출

### 6.2 인도자 콘솔

`/coach/cohort/[id]` 아래에 피드 흐름 요약. **판정 없이 사실만**(ADR-114 계열).

- 최근 7일 게시 흐름
- **조용한 분** — 최근 N일 미게시. 색으로 경고하지 않고 목록으로만
- 참여자에게 이 정보가 새지 않는지 회귀 테스트로 잠근다

### 6.3 하단 탭

1차에서 피드 자리를 선점해 두었는지 확인하고, 없으면 이번에 넣는다.

## 7. 하지 말 것

1. `main`에 직접 커밋하지 않는다. **새 브랜치**를 판다
2. SAIL(`shadow` 스키마)을 건드리지 않는다
3. 적용된 마이그레이션을 수정하지 않는다. 변경은 항상 새 파일
4. `PROXY_MATCHER`를 좁히지 않는다
5. **갈무리 테이블·화면을 건드리지 않는다.** 피드는 별도 테이블이다
6. 참여자 경로에 배지·순위·경고색·미게시 표시를 두지 않는다
7. 무한 스크롤·알림 배지·읽음 표시를 넣지 않는다 — 카톡을 흉내 내려다 마찰만 는다
8. **사진 원본을 그대로 올리지 않는다.** 클라이언트 리사이즈 필수
9. design_system에 없는 부품을 임의로 만들지 않는다. 목록으로 보고하라

**실브라우저 검증**(Vercel 프리뷰 · 빌드 id 확인 후):

| 검사 | 판정 기준 |
|---|---|
| 사진 업로드 | **실제 폰 크기 파일**로 리사이즈 후 3 MiB 이하 |

## 9. 미확정 — 막히면 질의한다

1. **조용한 분 판정 기준** — 며칠 미게시부터인가. 지휘부 권고 **3일**
2. **이모지 종류** — 몇 개를 둘지. 권고 **4개 이하**(고르는 데 시간이 들면 안 쓴다)
3. **1기 피드 초기 상태** — 빈 채로 열지, 안내 글 하나를 둘지
4. 소식 댓글 삭제 정책 — 본인·운영자 외에 작성자가 지울 수 있는지

## 10. 착수 순서

```
0) 새 브랜치 · git merge --ff-only origin/main 선행
1) 설계 보고 — 테이블·RPC·정책 골격. 코드 전 보고
2) 마이그레이션 (롤백 검증 → 적용)
3) 계약·코어
4) 화면 — /feed → 인도자 콘솔 → 소식 댓글
5) 커밋·push (독립 단계)
6) 완주 보고 작성 → 커밋·push
7) 감사 대기
```

1의 설계 보고만 확인을 받고, 이후는 승인 없이 완주한다.
**마이그레이션 적용 전 롤백 검증은 유지한다** — 라이브에 닿는 게이트는 줄이지 않는다.

**보고서는 작성 즉시 push한다.** 로컬에만 두면 지휘부가 읽을 수 없다.
