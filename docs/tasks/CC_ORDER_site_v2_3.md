## 0. 왜 이 회차인가

일정상 다음은 사후진단(4차)이고 그것은 11월 초에 필요하다. **두 달 여유가 있다.**
그 사이에 **쌓인 부채를 갚는다.** 부채를 안고 사후진단을 만들면 같은 실패가 반복된다.

**가장 무거운 부채는 `design_system.md`다.** 2차에서 부재 부품 여덟을 목록으로 냈고,
그것이 없어 인라인으로 그린 기수 칩이 §11의 결함을 낳았다.

> `--color-surface-2` 가 `--gray-0`(페이지 배경)과 같은 색이라 선택 표시가 보이지 않았다.
> 부품이 있었으면 일어나지 않았을 일이다.

**부품이 없으면 같은 일이 4차에서도 일어난다.** 사후진단은 새 화면이 여럿이다.

## 2. T-1 · design_system v4 — 이 회차의 본체

### 2.1 원칙

**문서가 코드를 따라가는 것이 아니라, 코드가 이미 한 선택을 문서가 확정한다.**
2차에서 인라인으로 그린 것들은 대부분 합리적이었다. 그것을 부품으로 승격하되,
**§11이 드러낸 함정(토큰이 배경과 같은 색)을 반복하지 않도록 대비를 실측한다.**

### 2.2 확정할 브레이크포인트

`design_system.md:310`이 "미규정"으로 비어 있다. 지휘부가 이미 값을 정했고
2차에서 코드가 그 값으로 돌고 있다. **문서만 비었다.**

```css
--bp-sm: 640px;   --bp-md: 768px;   --bp-lg: 1024px;   --bp-xl: 1280px;
```

| 영역 | 최대 폭 | 거동 |
|---|---|---|
| 공개 영역 | 1200px 중앙 정렬 | `lg` 미만 다단 → 1단 |
| 인도자·운영자 콘솔 | 제한 없음 | `lg` 이상 좌측 고정 사이드바 **250px** · 미만은 상단 탭 |
| 참여자 화면 | **720px 중앙 정렬** | 전 구간 1단. `max-width` 하나로 끝난다 |

세 번째가 요점이다 — **참여자 화면은 브레이크포인트를 쓰지 않는다.**

### 2.3 승격할 부품 여덟

2차 §7 부재 목록 그대로다. 각각 **현재 인라인 구현을 근거로** 사양을 쓴다.

| # | 부품 | 현재 | 승격 시 확인할 것 |
|---|---|---|---|
| 1 | 피드 입력창 | `ui-textarea` + `Button` | 사진 첨부 슬롯 포함 |
| 2 | 피드 아이템 | `ui-card` + 인라인 | 작성자·시각·본문·사진·반응·댓글 슬롯 |
| 3 | 이모지 반응 바 | 인라인 버튼 4 | **선택 표시가 배경과 구분되는가**(§11 재발 방지) |
| 4 | 댓글 1단 목록·입력 | 인라인 | 대댓글 슬롯을 만들지 않는다 |
| 5 | 날짜 구분선 | hairline 한 줄 | |
| 6 | **하단 탭바** | **없음** | §2.4 참조 |
| 7 | 기수 전환 셀렉터 | **`ui-btn` 로 교체됨** | 이미 부품을 쓴다. 사양만 기록 |
| 8 | 인도자 피드 요약 | `ui-card` + 목록 | 판정 없음 · 색 없음 유지 |

추가로 1차 이월 넷 — **날짜 입력 · 단일행 입력 · 승인 큐 표 · 상태 배지**.
상태 배지는 **참여자 화면 비노출**을 사양에 명시한다.

### 2.4 하단 탭바 — 짓지 않는 것을 문서에 남긴다

2차에서 **짓지 않기로 확정**했다(rev.1 §6.3). 그 결정을 부재 목록에 방치하지 말고
**"두지 않는다"를 사양으로 적는다.** 이유도 함께 — 내비는 `AppHeader` 하나이고,
진입은 홈 바로가기·차수 홈·헤더로 낸다.

빈 칸으로 남겨 두면 다음 사람이 만든다.

### 2.5 대비 실측 — §11 재발 방지

**모든 신규·기존 상태 표시 토큰 쌍의 대비를 실측해 표로 남긴다.**

`--color-surface-2 = --gray-0`처럼 **이름은 다른데 값이 같은** 쌍이 더 있는지 전수 확인한다.
선택·비선택, 활성·비활성, 강조·평상을 색으로 가르는 자리가 전부 대상이다.

> 값이 같은 쌍을 찾으면 **부품 사양에 "이 쌍으로 상태를 가르지 말 것"을 명시**한다.
> ADR-113이 대비 실측으로 토큰을 채택한 선례가 있다.

## 3. T-2 · 리포트 패널 재마운트 — 확인이 먼저다

2차 §9.5의 두 번째 관찰이다. **지휘부가 조건 성립을 확인했다.**

```
InterpretationPanel.tsx:67   useState<InterpretationVM|null>(initial)
MemberJourney.tsx:95         <Link href={`/coach/cohort/${cohortId}/report/${reportId}`}>
page.tsx:97                  <InterpretationPanel …/>   ← key 없음
```

리포트→리포트 이동은 **같은 자리에 같은 컴포넌트를 다시 그린다.** 재마운트되지 않으면
`vm`이 **이전 참여자의 해석을 붙든다.**

**갈무리 결함보다 위험하다.** 갈무리는 자기 글이 안 고쳐지는 것이지만, 이쪽은
**A의 화면에 B의 해석이 뜨는 것**이다. 인도자가 그것을 보고 코칭하면 잘못된 사람을 읽는다.

### 3.1 순서

1. **발현을 먼저 확인하라.** 확인하지 않은 것을 결함이라 적지 않는 규율은 유지한다
   - `useEffect`가 `responseId` 변화에 반응해 다시 부르는지 본다. 부른다면 **깜빡임은 있어도 어긋남은 없을** 수 있다
   - `status`·`editing`도 함께 본다. `editing=true`인 채로 이동하면 남의 리포트에 편집 상태가 열린다
2. 발현하면 `key`로 고치고 회귀 테스트를 건다. **2차 §11.4처럼 "무엇이 깨졌는지"에 맞춘다**
3. 발현하지 않으면 **왜 아닌지 적고 관찰로 남겨라**

### 3.2 함께 훑을 것

`useState(prop)` 10곳 중 **형제 이동 경로가 있는 자리**를 전수 확인한다.
2차 §9.5가 여섯을 "위험 낮음"으로 분류했으나 근거는 "이동 경로 없음"이었다.
**그 근거가 지금도 참인지** 확인한다.

## 4. T-3 · `/api/version`

2차 §0에서 **turbopack 전환으로 빌드 id 마커가 사라졌다.** 위양성 배제 수단이 필요하다.

| 항목 | 사양 |
|---|---|
| 경로 | `/api/version` |
| 응답 | 커밋 SHA · 배포 환경 · 빌드 시각 |
| 인증 | **불필요.** 공개해도 무해한 값만 담는다 |
| 금지 | 환경 변수·키·내부 경로·의존성 목록 |

`NEXT_PUBLIC_VERCEL_GIT_COMMIT_SHA`가 이미 있으면 그것을 쓴다. 없으면 빌드 시 주입한다.

**보호 접두사에 넣지 않는다** — 배포 신원 확인은 미인증 상태에서 해야 의미가 있다.
`PROXY_MATCHER`는 건드리지 않는다(불변식 17).

## 5. T-4 · 콘솔 사이드바

2차에서 **"화면이 여럿 설 때 한 번에 세운다"로 미뤘다.** 이제 섰다 —
`/admin`·`/admin/approvals`·`/coach/…` 아홉.

- **T-1 이후에 착수한다.** 부품 사양 없이 만들면 §11이 반복된다
- `lg` 이상 좌측 고정 250px · 미만 상단 탭 (§2.2)
- 시안 P2·P4의 구조를 따른다
- **참여자 화면에는 넣지 않는다.** 콘솔 전용이다

지휘부가 자산을 준비한다. **도착 전까지 착수하지 않는다.**
브랜드 마크를 임의로 만들지 않는다(2차 §11.6 판단 유지).

## 7. T-6 · 문서 정합 점검

부채 회차이므로 문서 자체를 감사한다.

| 대상 | 확인 |
|---|---|
| `architecture.md` §4 스키마 | 2차에서 한 번 드리프트가 났다. **실 DB와 전수 대조** |
| ADR 이월 항목 | ADR-122·123·124의 "이월"이 실제로 처리됐는지 |
| 불변식 목록 | 1~24 중 2차에서 바뀐 것이 있는지 (예: 전화번호 egress) |
| `docs/reports/README.md` | 보고서 종류 규약이 실제 파일과 맞는지 |

**어긋난 것을 고치되, 고친 사실을 보고서에 적는다.** 조용히 맞추지 않는다.

## 8. 하지 말 것

1. `main`에 직접 커밋하지 않는다. 브랜치 `chore/site-v2-3`
2. SAIL(`shadow` 스키마)을 건드리지 않는다
3. **마이그레이션이 필요 없는 회차다.** 필요해지면 멈추고 보고하라
4. `PROXY_MATCHER`를 좁히지 않는다
5. 갈무리 로직·문안을 건드리지 않는다
6. **부품 사양을 쓰면서 기존 화면을 대대적으로 갈아엎지 않는다.** 사양은 현재를 기록하고
   다음을 안내하는 것이다. 리팩터링이 목적이 아니다
7. favicon 자산이 오기 전까지 T-5를 시작하지 않는다

**보고서는 작성 즉시 push한다.**
