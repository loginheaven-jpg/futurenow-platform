## 0. 이 발주가 겨냥하는 것

최박사 실기기 증언 셋 - "다시 로그인해야 한다" · "뒤로가기하면 로그아웃" · "로고 누르면 로그아웃".
**셋 다 실제 로그아웃이 아니었다**(사전조사 실측). 원인은 하나다 - **로그인 상태를 화면이 말하지 않는다.**

여기에 회원 체계 의논의 표시 산출물을 함께 얹는다. 같은 자리를 만지기 때문이다.

## 1. T-1 · 로그인 잔류 제거

| # | 내용 |
|---|---|
| 1 | **`/login`이 인증자를 돌려보낸다** - `page.tsx`가 세션을 보고, 있으면 `/home`(또는 `returnTo`)로. `/signup`·`/reset`도 같은 처리 |
| 2 | **로그인 성공을 `router.replace`로** - `LoginClient.tsx:34`. `/login`이 히스토리에 남지 않는다 |
| 3 | 수리 후 **히스토리 실측** - 로그인 → 홈 → 두어 화면 이동 후 뒤로가기 연타. 로그인 폼이 다시 나오지 않는 것을 확인 |

**`goBack` 반환값으로 판정하지 않는다**(App Router에서 null). URL로 판정하라 - 사전조사의 측정 도구 사례.

## 2. T-2 · 공개 현관이 로그인 상태를 안다

**이것이 증언 셋 중 "로고 누르면 로그아웃"의 직접 수리이고, 대기 칩의 자리다.**

- `/`(공개 현관)가 세션을 읽는다. **미인증 렌더는 지금과 한 픽셀도 다르지 않아야 한다**(ISR·공개 화면 성격 유지 - 세션 분기가 공개 렌더를 오염시키지 않는 방식을 택하고 근거를 적어라)
- 인증 시 `SiteGnb`의 `login` 슬롯이 **이름 + 등급 칩**으로 바뀐다. 누르면 `/account`
- **등급 칩**: 방문회원(승인 전) / 포럼회원. 승인 대기 중이면 `방문회원 · 승인 대기`
- 칩은 **작게**(최박사 확정). 경고색 금지(불변식 9). 순위·집계 표현 금지(불변식 11)

## 3. T-3 · 용어 노출

내부 값은 **불변**이다(`pending`·`individual`·`held`·`expired`). 바뀌는 것은 **문언뿐**이다.

| 내부 | 노출 문언 |
|---|---|
| `pending` | **방문회원** |
| `individual` | **포럼회원** |
| `held` | (참여자 노출 없음 - 운영자 화면만) |

- **단일 출처**로 둔다 - 문언 매핑을 한 파일에 두고 화면들이 그것을 읽는다(사본 둘 금지)
- 노출 자리: 공개 현관 칩 · `/account` · 운영자 화면. **그 외 참여자 화면에는 등급 명칭을 새로 뿌리지 않는다**

## 4. T-4 · 내 정보(`/account`) 등급 표시

| 슬롯 | 내용 |
|---|---|
| 현재 등급 | 방문회원 / 포럼회원 |
| 한 줄 설명 | 그 상태에서 무엇이 되는지 (존대체) |
| 다음 할 일 | 방문회원이면 - 포럼회원 신청 · 세미나 참여 신청 · 인도자 신청 링크 |
| 대기 중 | 신청 후 승인 전이면 같은 자리에 대기 표시 |

**판정하지 않는다** - 등급·대기 여부는 서버가 산출해 prop으로 내린다(F-1 강조 ①).

## 5. T-5 · 역할 카드 복수 노출

현행 `roleTarget()`은 거점을 **하나만** 고른다. 겸직자(인도자이면서 다른 회기 참여자)에게 참여자 카드가 서지 않는다. **실측: 인도자·운영자의 회기 등록 7행 실재 - 겸직은 이미 사실이다.**

- `roleTarget()` → **복수 반환**으로 확장(`RoleTarget[]`). 순수 함수 유지
- 해당자에게 인도자 카드와 참여자 카드가 **함께** 선다. 해당 없으면 그대로 하나
- **목적지를 바꾸지 않는다** - 늘어나는 것은 카드 수뿐이다. 기존 다섯 경우 테스트는 그대로 통과해야 한다

## 6. T-6 · `/login`에 `/signup` 링크

가입 진입이 URL 직접 입력뿐이다. 로그인 화면에 가입 링크를 둔다. **한 줄이다** - 퍼널 골격 재작업은 의제 2 몫이므로 손대지 않는다.

## 7. T-7 · 자격 편의 (자격 값 저장 없음)

**앱은 비밀번호를 들지 않는다.** 사용자가 겪는 결과만 만든다.

| # | 내용 |
|---|---|
| 1 | `LoginForm`에 `name`·`id` 두 줄 추가 - 브라우저 비밀번호 관리자 적중률(특히 안드로이드). `autoComplete`는 이미 있다 |
| 2 | `sb-*` 쿠키 `secure` 플래그 실측 · 가능하면 수리(사전조사 부수 관찰). 운영이 HSTS 2년이라 창은 좁으나 좁은 것과 없는 것은 다르다 |
| 3 | `/account`에 **"이 기기에서 로그인 유지"** 스위치. **기본 켬**(편의 우선 - 최박사 확정). 끄면 세션 쿠키화 |
